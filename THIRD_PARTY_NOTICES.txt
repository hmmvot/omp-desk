built-ins.

================================================================================
Bundled runtime dependencies of the PTY broker (out/pty/pty-broker.js)
================================================================================

The broker is a detached Node process that owns a pseudo terminal for as long as
its child lives (ADR-0024). Its bounded screen state is a headless terminal
emulator, bundled into that entry:

  @xterm/headless           6.0.0   MIT   (see the xterm.js section below)
  @xterm/addon-serialize    0.14.0  MIT   (see the xterm.js section below)
  @xterm/addon-unicode11    0.9.0   MIT   (see the xterm.js section below)

All three are pre-minified upstream CommonJS builds that carry no `@license`
banner, so esbuild `legalComments: "eof"` appends nothing for them and they are
recorded here instead. (In the Webview bundles the same addon resolves to its
ES-module build, which does carry an `@license MIT` banner.)
`node-pty` is deliberately *not* bundled into this entry; it is shipped
as a package next to it and loaded from a staged copy, below.

================================================================================
Staged native package of the PTY broker (out/pty/node_modules/node-pty)
================================================================================

The build copies `node-pty` 1.1.0 from `node_modules` into the packaged tree at
`out/pty/node_modules/node-pty` — its `package.json`, its `lib/**` runtime
modules and its `prebuilds/win32-{x64,arm64}/**` — and the extension stages that
whole tree into extension global storage
(`<globalStorage>/runtime/pty-tree/<sha256>/`, ADR-0012) before any session runs
from it. These files ship in the VSIX but are not part of any JavaScript bundle:

  lib/*.js                                 the loader, the Windows terminal and
                                           the conout worker of node-pty
  prebuilds/<platform>-<arch>/pty.node     winpty addon (N-API)
  prebuilds/<platform>-<arch>/conpty.node  ConPTY addon (N-API)
  prebuilds/<platform>-<arch>/conpty_console_list.node
  prebuilds/<platform>-<arch>/conpty/conpty.dll        Microsoft ConPTY
  prebuilds/<platform>-<arch>/conpty/OpenConsole.exe   Microsoft OpenConsole
  prebuilds/<platform>-<arch>/winpty.dll               winpty
  prebuilds/<platform>-<arch>/winpty-agent.exe         winpty

The native addons are N-API modules built with `node-addon-api` (MIT, used to
build them and not shipped); the extension loads them only after proving they
work in the runtime it will use (`pty-broker.js --self-check`).
