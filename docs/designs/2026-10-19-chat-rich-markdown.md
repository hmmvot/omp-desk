# Rich Markdown in Chat: SVG figures, table charts and math

## Problem

OMP's terminal UI (TUI) draws three things from an assistant's Markdown that Chat shows as plain text: a ```` ```svg ```` fence as an inline image, a chart under a table of numbers, and LaTeX math as typeset Unicode. All three are on by default in OMP 18.11.1 (`tui.renderSvg` default true, `tui.autoGraph` default `always`; `pi-coding-agent/src/modes/settings.ts`). A reader who uses both surfaces sees less in Chat than in the terminal.

## Goals and Non-goals

- Goals:
  - A closed, top-level ```` ```svg ```` fence in the **assistant's reply text** (not inside a list item or a quote; the TUI's splitter, `pi-tui/src/chat/svg-source.ts:16-30`, accepts a fence indented at most three spaces and leaves one in a list's indented block or a quote as prose) is drawn as an image with a Figure | Source toggle and Copy; an unclosed fence, an SVG that cannot be drawn and any other message kind stay a code block (with one muted line saying why where there is a reason). The SVG is untrusted: it is never run, fetched or injected as markup.
  - A top-level table of the assistant's reply that the TUI would chart gets the same kind of chart under it (bar, grouped bar, line), drawn in the theme's colours, with a reader's opt-out.
  - LaTeX math (`$…$`, `$$…$$`, `\(…\)`, `\[…\]`, own-line display blocks, bare `\begin{align}`-style environments) is shown as Unicode text, inline and stacked; dollar amounts in prose are untouched.
  - Find and Quote keep working on the shown text.
- Non-goals: charts the TUI draws in its special kinds (stacked, share, heatmap, waterfall, ladder, bullet, scatter, histogram, slope, butterfly, range, diverging, dots, small multiples) and the model-backed `smart` planner; a host setting that mirrors `tui.autoGraph` or `tui.renderSvg` (below); typeset math (KaTeX, [ADR-0078](../decisions/0078-show-latex-math-as-unicode-text-from-a-project-owned-converter.md)); streaming SVG or math drawn before the block is complete; a system-prompt rule that invites the model to draw figures or charts (the TUI sends one only for its own transcript; Chat draws what a reply or a resumed session holds); exporting images; the TUI's colour commands in math.

## Current State

- `Markdown.tsx` parses a fence to `CodeBlock` and the `mermaid` fence to `MermaidBlock`, which draws only when `AssistantReplyContext` is true (the assistant's reply text) and the block is closed. A table is a `<table>` in a scroll wrapper. Inline text is tokenised by the regular expressions of `lib/markdown-inline.ts`, which `quote-capture.ts` and the Find text model read too.
- The Chat page's policy (`guestCsp` in `src/host/guest-webview.ts`, excerpt) is `default-src 'none'; img-src <cspSource> data:; style-src 'nonce-…' <cspSource>; style-src-attr 'unsafe-inline'; font-src <cspSource>; script-src 'nonce-…' <cspSource>`, plus `base-uri 'none'`, `form-action 'none'` and a `connect-src` of the document's own bridge. Mermaid already shows an SVG as a `data:` URL `<img>` for the reason that an SVG image cannot run script or reach the page.
- Find and Quote operate on shown text (see ADR-0078 for the invariant).
- Desk's display preferences reach the page through the existing `omp:chat-display-preferences` host message (`toolCallDetail`, `accessibilitySupport`, …). Desk does not read OMP's `tui.autoGraph` or `tui.renderSvg` for the Chat (the OMP Settings editor reads OMP settings, but nothing feeds them to the transcript).

## Proposed Design

### Where each feature applies

- **SVG figures and table charts** are drawn only in the assistant's reply text: the block components read `AssistantReplyContext` (as `MermaidBlock` does), so thinking, tool output, native notices and text the user typed show the code or the table unchanged. A figure or a chart is also top-level only: the parser does not offer one inside a quote or a list item (the TUI's splitter reads only the document's root tokens; a fence it lifts may carry up to three spaces of indent, which Desk's parse already treats as a top-level fence).
- **Math** follows the renderer's `emphasis` mode, because Find and Quote read the inline pieces without any React context and the shown text must agree with the DOM: it is on in every Markdown surface the model wrote (the reply, thinking, which the TUI also renders as math, and model-written prose in tool output and notices, quotes included) and off in text the user typed. Pandoc's anti-currency rules, not the surface, are what keep a price a price.

### SVG figures

- `lib/svg-figure.ts` (pure): a small XML tokenizer (no DOM, so it is testable under Node) builds an **allow-list** tree and serialises it back as clean SVG text. Elements outside the list (`script`, `foreignObject`, `image`, `a`, animation elements, HTML, unknown) are removed with their subtree; `on*` attributes, any `href` that is not a same-document `#id`, any `url()` that is not `url(#id)`, `@import` and `expression(` in styles are removed; `<!DOCTYPE>`/entity declarations are invalid; the five predefined entities, a short list of the HTML names models write (`&nbsp;`, `&mdash;`, …) and numeric references are accepted, any other name makes the figure invalid; limits on size, element count, depth and `<use>` expansion turn an SVG into a code block. The CSS filters are textual and reject the literal forms: they are a second line, not the guarantee (the guarantee is that an SVG shown by `<img>` loads nothing and runs nothing); if a figure were ever shown inline, a CSS parser would be required first. The TUI's theme tokens `var(--fg|muted|border|accent|success|warning|error|surface|c1…c6)` are replaced by colours of the page's theme (`lib/figure-palette.ts`, from the `MermaidTheme` that `lib/mermaid-theme.ts` reads out of the VS Code variables): `fg` the editor text colour, `muted` the text colour a third of the way to the background, `border` and `surface` the theme's node outline and fill, `c1…c6` the six chart hues (blue, green, orange, purple, red, yellow, which OMP's TUI derives from the accent in OKLCH instead), `accent` the first, `success`, `warning` and `error` the green, orange and red among them. The root gets a namespace, `color` and `font-family` defaults. A figure with neither `viewBox` nor numeric size is not drawn (it has no size an image could keep).
- `components/SvgFigureBlock.tsx` shows the prepared SVG only as `<img src="data:image/svg+xml;charset=utf-8,…">`: an SVG image runs no script and loads nothing, so the sanitizer is the second wall, not the only one. It follows `MermaidBlock`: the Figure | Source toggle, Copy, the per-source remembered choice, the code fallback when the browser cannot decode the image. Find's shown text always contains the source (it is the leaf's text); in Figure view the source is not on screen, so a match inside it is counted and marks its row without painting, the limit a drawn Mermaid diagram has. The Source view and the code fallback carry the block's leaf, so a selection of them quotes the source; the drawn figure carries none.

### Table charts

- `lib/table-chart.ts` (pure) reads a table's cells (text with Markdown stripped by the caller) and returns a chart spec or `null`. It ports the TUI's local (`always`) path for the common cases and was compared with OMP 18.11.1's own pipeline on generated tables: numeric cell reading (thousands separators, currency, percent, units, magnitude suffixes, ranges and arrows read at their start; dates, times, versions, ids, hashes and missing marks are not measures), measure/label column roles, total rows skipped, dimension rules, and the TUI's draw gate (at least 4 categories, no uniform series, at least 9 points or a 3× spread within a series). Kinds: single-series bar, grouped bar (2–3 same-unit measures; from four same-unit measures over at least three rows the TUI's planner picks a heatmap, `pi-tui/src/charts/chart-plan.ts:981`, so Desk draws none; the TUI's grouped-bar cap of four, `:486`, applies only to the paths that reach grouped bars by other routes, which Desk does not port), line (dates, month names, `Run 3`/`Q3`/`v1.2.3`/`#12`-style or monotonic numeric labels, 4+ rows, up to 6 series). Where columns have different dimensions the largest set of one dimension is drawn, where the TUI draws small multiples: the one deliberate extra chart. Everything else is "no chart".
- `components/TableChart.tsx` draws the chart as React-generated inline SVG (no markup string anywhere) coloured with theme CSS variables, so a theme change needs no JavaScript. The wrapper is `role="img"` with the chart's description and the SVG is `aria-hidden` so Find never reads chart text. Only top-level tables get a chart, as in the TUI.
- **Streaming.** The TUI charts a table when it is not the streaming tail or when a later token follows it. Chat's `Markdown` has no streaming flag (the caller `PacedMarkdown` has one, but threading it through `MessageContent` would touch files this feature does not own), so a table that is the last block of the text is charted once its text has been unchanged for 600 ms, and a table followed by anything is charted at once. A tail table that settled is remembered by its text for the life of the page, so a row that scrolls out of the list and comes back charts at once. A reply that ends with a table shows its chart 600 ms after the last row.
- **Opt-out.** The TUI's off switch is the OMP setting `tui.autoGraph`, which Desk does not read for the Chat. A Desk setting would add a field to the existing `omp:chat-display-preferences` message and a manifest entry. The chart has instead a page-local `Hide chart` button that hides every chart of the page and leaves a one-line `Show chart` under each charted table; unlike the other display preferences it does not persist and resets on reload. A mirror of `tui.autoGraph` (or a `ompDesk` setting) can be added later without touching the chart; whether to add it is the maintainer's call.

### Math

[ADR-0078](../decisions/0078-show-latex-math-as-unicode-text-from-a-project-owned-converter.md) chooses a project-owned Unicode converter over KaTeX. The inline tokeniser gains one token kind: a math span found by `lib/latex-math.ts`'s `nextMathSpan` (per line: a line over 4,000 characters is not searched). Of two tokens, the one that starts first wins, so a `$` inside a code span is code, `*` and `_` inside a math span are math, and a math span that starts inside an earlier token (a link's label, say) is skipped: inline math is not converted inside a link label, where the TUI converts it. `renderInline` and `inlinePieces` (hence Find and Quote) share one scan (`scanInline`), so they agree by construction; the shown text of a span is `latexToUnicode(body)`. An own-line `$$`/`\[` block or a bare math environment becomes a block whose shown lines are `latexToBlock(body)` and whose leaf has the code leaf's shape (Find reads the lines; Quote of a selection of it is the text selected, since shown lines are not source lines). An unclosed opener stays prose, so a streaming reply shows raw TeX until the closer arrives. The delimiter grammar is line-local for every delimiter (OMP's `\(…\)` and `\[…\]` closers may cross a soft line break; a span that does is raw text here).

### Parser touch points

- `parseBlockRange` gains the `svg` dispatch beside `mermaid` (not inside a quote or a list item: `BlockContext.inList` is new), the math-block branch right after the fence branch, and the chart under a table (a Fragment, so a table is still one block with one key). A paragraph also ends at a complete math-block opener.
- **Block reuse changes for display math.** `parseMarkdown` keeps every block before the last one or two while a reply streams. A display block's extent depends on a closer that may be arbitrarily far below, and its body may hold blank lines, so a block kept before the closer arrived would stay wrong. `MarkdownParse` therefore records `openMath` (an own-line `$$`, `\[` or `\begin{` opener outside a fenced block that has no closer yet) and, while it is set, the next parse starts over. A reply streaming an open display block costs one full parse per delta until the closer arrives, as does a lone `$$` line in the text; every other text keeps the old rule. (Find rejected a per-delta full parse for itself; here the cost is bounded by the text of one message and only while an opener is open.)

## Alternatives

- SVG: rasterise in the host, or inject sanitized markup with `dangerouslySetInnerHTML`. Rejected: an `<img>` of an allow-listed document is the smaller trust surface and matches Mermaid.
- Charts: render the TUI's chart SVG as an `<img>`; take a charting library; read `tui.autoGraph` through the existing display-preferences message; hide charts through a Desk setting. Rejected for dependency or cross-subsystem cost against a presentation default; the table's own `Hide chart` control stays within the page. Pass the streaming flag down from `PacedMarkdown` instead of the settle timer: more exact, touches the message components; left as the follow-up if the 600 ms delay bothers.
- Math: see ADR-0078.

## Risks and Open Questions

- A table chart that the TUI would draw as a special kind is missing in Chat, and a table the TUI declines is also declined here; the thresholds are copied from OMP 18.11.1 and may drift in later OMP versions.
- The streaming tail uses a 600 ms settle timer; a reply that ends with a table shows the chart 600 ms after its last row. The tests prove the settle constant (600) and that a static render of a tail table draws no chart; the timer firing itself is not exercised (the owned headless-Chromium suite `table-chart-ui.test.ts` could wait it out; not done).
- The inline grammar is per line: a `\(…\)` span across a soft-wrapped line is raw text, and math in a link label is not converted.
- Models rarely write ```` ```svg ```` unless invited: OMP puts the invitation in the system prompt of a TUI transcript only. Chat shows figures a reply or a resumed session contains; a prompt rule would be a separate decision.
- Whether Desk should mirror `tui.autoGraph` / `tui.renderSvg` with a setting is the maintainer's call.

## Rollout and Verification

Unit tests for the sanitizer (malicious, invalid and oversized SVG), the chart planner and component (numeric and non-numeric tables, the draw gate, hostile cell text), the math delimiters (prices and escapes), the converter and the block layout; renderer tests (`src/webview/rich-markdown.test.ts`) for the fence, table and inline paths, the streamed math block against a fresh parse, Find's shown text and the inline pieces; headless-Chromium suites for the figure and the chart (`svg-figure-ui.test.ts`, `table-chart-ui.test.ts`); `npm run typecheck`. The guide ([Chat](../guide/chat.md)), the changelog and [architecture](../architecture.md) describe the behaviour. Not run by this package: a real-window check with a reply containing a figure, a charted table and display math, and the build and install of the VSIX that [AGENTS.md](../../AGENTS.md) requires before handover. Several packages share this working tree, so one build and install covering all of them is the coordinator's step; the package report names both as not run.
