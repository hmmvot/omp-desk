# OMP transcript parity in VS Code, with running-agent and todo HUDs

## Problem

The RPC-UI chat currently renders native OMP tools through one generic card and omits native transcript/event information. Its bottom Tasks/Plan panel is not the requested todo HUD. Users need the information and structure of OMP's interactive transcript without terminal styling, and running-agent visibility above the conversation.

This extends the accepted [RPC-UI design](2026-09-29-rpc-ui-chat-and-sessions.md), specifically its MVP exclusions of subagent progress UI. It does not revive Collab, the former Hub transport, configuration/usage panels, or a native terminal inside chat. The [compact footer](2026-10-01-compact-chat-footer.md) remains unchanged.

## Goals and Non-goals

Goals:

- Render every built-in native tool family and every reachable native message/entry kind, preserving labels, argument summaries, structured results, previews, errors, streaming updates, grouping, and disclosure behavior.
- Extend the child-event allowlist and shared host/page reducer for native retry, TTSR and subagent events instead of inventing a separate page-only channel.
- Above the transcript: running AGENTS, then TODO. Each is initially collapsed. AGENTS exists only while agents run; TODO exists only when tasks exist.
- Collapsed TODO: current phase, current task, closed/total in that phase, then overall closed/total. Expanded TODO: native phase/task/status/blocker/details/note structure.
- Remove the bottom TodoPlanPanel and Plan-specific projection, styles and tests, migrating retained todo semantics into the new HUD.
- Use VS Code theme variables, codicons, proportional interface/prose text, and monospace only for source/code/output. No ANSI, terminal frames, keyboard-hint imitation or terminal-width layout.

Non-goals: patching OMP, installing a VSIX, controlling any VS Code window/process, changing conversation ownership/broker transport, changing model/footer/menu behavior, exposing a second language provider, or executing arbitrary native extension renderer code inside a webview. Native components are not DOM components. Where RPC supplies content/details but not an extension-defined renderer executable, render the complete content and details through the safe fallback and document the exact limitation.

## Implemented Design

### Data flow and authority

Keep one `ChatModel` for host and page. Map verified child frames; unknown frames remain rejected. Hydration is disk-first and idempotent, with durable ids, timestamps, pending/durable reconciliation and preserved result details/content. Never re-execute a tool to obtain display data.

Define local `ChatMessage`/`ChatEntry` types for user, developer, assistant, toolResult, custom, hookMessage, bashExecution, pythonExecution, fileMention, branchSummary and compactionSummary, plus persisted custom_message, custom metadata and reset/compaction entries. The old `@oh-my-pi/pi-wire` union is a narrower rendered subset, not the installed producer contract. Preserve provider blocks, retryRecovery and unknown data for reconciliation, but render only the native TUI's visible subset. Unknown/internal entry kinds and message roles, developer inputs, hidden custom entries and internal provider blocks have no transcript card or metadata archive. Hidden custom entries can still update canonical todo state.

Use positional snapshot authority, not buffered replay after a snapshot. Every attach/resync sends `set_subagent_subscription {level:"progress"}` (also resetting a child previously left at events), then `get_subagents`. At the response line, host `#onResponse` synchronously validates/applies the roster **before** resolving the pending command or processing later lines. Frames before this cut, including broker-ring replay, are superseded; frames after it are deltas. Apply `get_state.todoPhases` at the same response dispatch cut. There is no secondary buffer that can resurrect pre-snapshot state.

Host→page contract: snapshotOf/applyChatSnapshot carry roster, bounded activity, maintenance/retry state and canonical todo phases. Explicit event frames carry every transition; page parsers validate rows independently. Every get_state cut forwards phases as well as lite footer state (including settle-time state_update). Lazy subagent transcript uses bounded bridge request/response messages; host resolves only ids present in its roster or held task details, never a page-supplied file path. Bump exact-match GUEST_PROTOCOL_VERSION from the footer work's 4 to **5** for the expanded contract.

Preserve the durable-prefix/pending partition and chronological presentation with one shared position-anchored projection: pending rows and bounded live-only ephemeral items carry anchor id + sequence, reconciliation retargets anchors to consumed durable ids, and rewrites drop vanished ephemeral anchors. Native notice/TTSR/reminder/fallback/status lines and command output use this mechanism rather than a second tail-only card list. Architect confirmed this refinement without another review on 2026-10-02.
The stream takes a position at message start and retains it at message end. Reconciled durable rows retain their display position when it depends on a live predecessor; snapshots carry these positions so a notice that arrived before the first saved assistant cannot jump behind it. Turn start/end seals the mutable replacement sequence; settled earlier todo/wait cards cannot be displaced by later turns.

Roster membership, not status filtering, determines the native AGENTS count: a completed progress state may transiently remain until its lifecycle removal. `started` creates/replaces; progress only updates a known identity; terminal/removal of an unknown id is a no-op. Match ownership by parentToolCallId when supplied, otherwise sessionFile; ignore conflicting ownership. Reset roster on resync start, stopped/failed/view-only and child exit, not root `agent_end`/settled because detached children can outlive it. Snapshot-command failure marks the HUD unavailable, not the whole chat failed.

Accept `subagent_event {id,event}` as required, but reduce it only to bounded latest activity (type/tool/intent/timestamp) on an existing roster identity. Never create/revive/remove identities, change status, retain child text/args/per-token history or alter the count from this frame. Unknown/removed ids and invalid payloads are dropped without resync. Activity-map size is bounded by roster size; subscribe only to progress, never events. Broker transport is unchanged.

Live saved custom messages reconcile against durable custom_message using customType + ISO timestamp. `display:false` and never-saved ephemeral messages do not produce unsaved-history warnings. IRC live/persisted duplicates use role/customType/timestamp. `auto_retry_end.retryErrors` patches the already-held durable entryId or pending persistence key: `['assistant',timestamp,provider,model,responseId ?? '',stopReason].join(':')`. Incremental get_entries cannot fix an already-held row by itself.

Retry-superseded assistant errors are hidden; recovered errors become compact recovery notes; genuine terminal errors remain complete. Retract only synthetic aborted/error calls superseded by retry, retaining real completed work. `interrupt_skipped`, `__synthetic` and `__interrupted` skipped work has neutral state. Failed assistant calls finalize instead of remaining queued. Failed retry end presents “Retry failed after N”; TTSR merges only consecutive tail notifications.

Canonical todo authority is the latest active-branch successful non-view todo result with details.phases or custom/user_todo_edit with data.phases, including `[]` as an explicit clear. `get_state` replaces canonical phases at its dispatch cut; old loaded results and loading older history never revert it. Extend HistoryReader's index facts with todo-candidate metadata, reading the newest candidate by byte range even outside the rendered tail. Include it as HistorySnapshot.todoSeed, not an orphan old card; branch rewrites invalidate seeds. Hidden custom metadata must be retained for this fold.

After the first get_state cut in a live generation, phases change only through a later get_state cut or a successful non-view live todo tool_execution_end received after the cut. Durable disk/get_entries/load-older folds apply only before that first cut or in stopped/view-only; an old get_entries candidate arriving after resync's state cut cannot overwrite it. Refresh get_state at settle, todo_auto_clear, eval tool_execution_end with nested todo details, and slash-command completion (custom/user_todo_edit writes have no live frame). Preserve this authority flag through host/page snapshots and state updates.

### Approved presentation resolutions

The maintainer explicitly accepted these three product decisions on 2026-10-02; this records product approval, not architecture acceptance:

1. **Lazy read-only subagent transcript:** expanding an agent/task can request get_subagent_messages by native id/sessionFile/fromByte. Reuse full native message/tool rendering at bounded nesting depth. Keep a bounded rendered window, disclose truncation and load-more; `reset:true` discards/refetches cached rows. The native response has no byte-limit parameter, so do not claim bounded response bytes. Availability is limited to the live registry/retained last 256 paths; stopped/restarted/cleared children show explicit unavailable, never an invented empty transcript. No composer, chat, kill, revive, steer or dialogs; no unsafe disk-path fallback.
2. **Full-history compaction departure:** preserve disk-first recoverable history, labelled as full history instead of claiming native default collapsed-history parity. Follow native full-history replay (`pi-coding-agent/src/session/session-context.ts:405-445`): superseded summaries become placeholders; omit an immediate snapcompact replacement's duplicate source only when parentId/firstKeptEntryId/tokensBefore match. Preserve method/warning/tokensAfter/blocks/images on the retained summary. A reset boundary is a divider, not history elision. The installed-window correction contract supersedes the earlier statistics-disclosure fallback: native default showTokenUsage/showTurnTime/cacheMissMarker are false, and no internal usage/model/response/cache/raw-entry archive is rendered. Model/thinking changes are one compact muted line.
3. **No deobfuscation:** keep transported secret placeholders; do not add a deobfuscation API, guess secrets or patch OMP. The native local renderer/obfuscator display context does not cross RPC. Verify actual transported masking before asserting a concrete smoke result.

### Tool rendering

Use a DOM-native semantic renderer registry indexed by tool name, sharing the same alias/xd delegation semantics as OMP. A tool card retains stable identity, intent, lifecycle and expansion state; renderer-specific content owns the meaningful header, argument summary, structured user result and preview policy. Expansion reveals native body content, not raw call/result/source metadata. Null/undefined optional arguments never appear. Unknown tools use the native meaningful argument/text-output fallback without an extension-capability banner or raw result-details archive.

Implement actual semantic families, not identical generic cards renamed per tool:

- Source operations: read file/location previews and consecutive-read grouping; edit/apply_patch/ast_edit diffs and hunk/path/change summaries; write file previews and xd resolved device dispatch.
- Process/output: bash command/cwd/status and output tail, eval/Python cell/result/output/error sections, debug request/result, wait/job statuses.
- Search/navigation: grep line matches, find/glob path lists, ast_grep matches, web_search titles/URLs/excerpts, lsp action/location/diagnostic/symbol/edit structures.
- Workflow/agent: todo phases and transitions, task/subagent cards with live activity, ask questions/options/answers, goal, resolve/reject, vibe worker lifecycle, think.
- Memory/GitHub: retain/recall/reflect operations/results and github action/repository/item/result structures.

For each family, prefer verified structured `details` for native presentation and preserve textual output where the renderer uses it. Partial results may be incomplete: parse proven shapes, while retaining unshown data in the replica rather than inventing visible metadata fallbacks. Collapsed previews use native semantic limits/tails; expanded views uncap native content. Error state stays visible without requiring expansion. Native output capture/limit/artifact warnings remain concise actionable text, not JSON field tables. Images remain inline constrained DOM images, without base64/provider metadata archives. Completed/queued tools retain status icons but no redundant status text; running/error/skipped states remain textual.

Do not render generic key/value tables or recursively expose transport `details`/payload records. Each family selects only its verified native fields and formats them as semantic rows/text. The native bounded JSON view is reserved for real tool arguments or explicit user-facing JSON output (eval/task structured results and GitHub output), never a details fallback. Collapsed Task shows only agent name/type/status rows; its context/activity/review/assignment/results are expansion-only. Collapsed Wait shows name/type/status/elapsed rows without result text/JSON or labels; native bounded result summaries appear after expansion. Background work stays a header badge, without a fabricated acknowledgement or zero dispatch timer.

The card owns the installed common ten-row collapsed rendered-body boundary, with native family preview overrides and head/tail direction. This bounds rich bodies, images and diagnostics together rather than allowing every child to consume a separate full preview. Task/Wait/Todo use compact semantic row selection instead of arbitrary body clipping. Text preview windows also bound responsive wrapped rows, so a single long Bash line cannot fill the transcript while collapsed. Expansion removes these display bounds and recollapse reinstates them; native explicit JSON/result limits still apply.

Read grouping follows transcript order and installed `pi-tui/src/chat/read-tool-group.ts:35-98`: path precedes legacy file_path, missing target does not group, filesystem/unknown/external targets group, known internal URL schemes group only when their registered compactTranscript flag is true. Continue across invisible assistant content; visible assistant text/thinking/images and native-visible other messages/non-read tools seal a group. Internal usage entries and usage-only assistant metadata consume no cards and do not duplicate a read group's presentation. Keep individual ids/path/status/results and errors. Successful same-turn mutable todo snapshots displace the preceding snapshot; a new wait displaces an all-running mutable poll. User/turn boundaries seal them; committed historical blocks are not removed. Native benign wait placeholders are omitted, while ordinary returned wait snapshots (including interrupted-by-message information) remain visible. One shared projection drives visible/window/card counts so older pagination extends existing groups without duplicates.

The native internal URL scheme spec is a host-installed runtime registry (`pi-tui/src/url-scheme-host.ts:32`), not an RPC field. Mirror the verified installed built-in scheme specs statically: only xd:// declares compactTranscript:true (`pi-coding-agent/src/internal-urls/xd-protocol.ts:62`); other built-in schemes render fully, while unregistered schemes group. Runtime-registered extension/MCP scheme specs are unavailable over RPC and are an explicit parity limit.

### Above-transcript HUDs

`RunningAgents` precedes `TodoHud`, both before the transcript inside the conversation surface. Use accessible buttons/disclosures with codicons; collapse state is view state, not a session mutation.

AGENTS collapsed label is the count of native running-registry members (a terminal progress row may transiently remain until lifecycle removal). Expanded rows show one compact icon/human-name/type/status/activity/elapsed/native-counter row per agent, followed by one ellipsized description line and lazy read-only child access. Native task progress `id` is its allocated human task name, not an opaque transport field; source/index/parent identities, raw timestamps, full task/assignment and raw progress/result archives never render here. The roster has a bounded internal scrollbar. Finished agents remain available in transcript task cards after native removal, not in the running HUD.

TODO uses authoritative snapshots/results/edits. Closed means completed or abandoned; pending/live-agent matches are active display hints, never status mutations. Current phase is first nonempty pending/in_progress phase, otherwise last nonempty phase. Current task is independently first in_progress anywhere, otherwise first pending anywhere, never blocked; show settled context when neither exists. The requested collapsed HUD is a single phase/task/count row, not the TUI's terminal preview of phase/task rows. Expanded phases preserve every task/status/blocker/details/note. As requested, the HUD exists whenever tasks exist: it does not reproduce interactive-only persisted dismissal/auto-clear hiding or successful-subagent writer side effects. No Plan panel remains.

### Clean cutover

Delete TodoPlanPanel and App mount, exclusive omp-projection/todo/plan styles, Plan exports/types/selectors/state, EMPTY_PLAN, TodoPlanProjector and obsolete Plan tests. Remove old Collab OMITTED/isOmitted/mayBeStale projection machinery; move only retained canonical todo helpers to their new owner without aliases/re-exports. Plan-mode content remains ordinary transcript content. Update current architecture and historical ADR/RPC-design supersession notes where they referenced todo-plan; preserve menu/footer behavior.

## Alternatives

- Import the TUI renderers: rejected; they construct terminal components, theme/ANSI/width machinery and process integrations, not a safe browser interface.
- Render all output as generic JSON: rejected; loses source diffs/previews, matched locations, process tails, phase semantics and task state despite those being present in RPC payloads.
- Add a separate webview agent channel/state store: rejected; would diverge during hydration, reconnect and host-owned updates.
- Keep bottom Tasks/Plan alongside the new HUD: rejected; duplicates state and violates the explicit removal requirement.

## Risks and Open Questions

- Native details are not uniform. Resolve renderer-specific shapes with source evidence before implementation; preserve unrecognized information in fallback.
- Native extension renderer callbacks and interactive-only presentation/controller state may not cross RPC. Record exact missing fields and producer paths, distinguishing unavailable data from a dropped extension allowlist frame; never silently downgrade a reachable feature.
- Snapshot/live races, recovered provider errors, synthetic aborted calls and grouped historical reads can create duplicates or stale running indicators. Behavior tests cover these transitions, not source-text/wiring assertions.
- No installed-window proof is authorized. A headless rendered webview and real installed-OMP RPC smoke prove reachable behavior without installing or touching the user's VS Code; the visual verification limit must be explicit.

Exact RPC-only limits are arbitrary extension tool/custom renderer callbacks and mounted xd labels, runtime-registered extension/MCP URL-scheme specs, local interactive preference settings not returned by get_state, local secret deobfuscation context, interactive-only todo writers/dismissal, and Hub chat/kill/revive controls absent from the read-only RPC contract. Complete available args/content/details remain renderable. Usage, time, served model and cache data are derivable and must not be falsely listed as unavailable.
