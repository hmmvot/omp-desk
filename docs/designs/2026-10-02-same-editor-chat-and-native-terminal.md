# Same-editor Chat and native OMP Terminal

## Problem

Sessions currently opens only the web chat over `omp --mode rpc-ui`. The user wants the same conversation and existing editor tab to offer either Chat or the unmodified native OMP TUI, with a persisted profile-wide default and explicit entry points for both views.

## Goals and Non-goals

- Swap Chat and Terminal inside the existing editor; do not open a second editor for an already-open conversation.
- Persist the default in VS Code `globalState`, independently of workspace folders. It applies when a tab is opened/created, including folder New Session. An ordinary click/Open on an existing tab only reveals its actual mode; explicit mode actions switch it. Restore and Reload retain the actual editor mode.
- Mode navigation now belongs to the active editor title in both views ([ADR-0043](../decisions/0043-place-session-mode-actions-in-editor-title.md)); the original top-right in-page selector is removed. Open in Chat and Open in Terminal remain in session context menus.
- Continue the best-known current native session file after positively settling the previous extension-owned writer. A busy switch requires modal consent before abort/stop; an idle switch has no confirmation. An empty session that has no file starts a new empty native session in the same editor and row.
- Reuse the detached broker's `managed-omp` PTY, existing terminal pipeline, xterm renderer, authenticated host-control endpoint, lifecycle gate and editor ownership. Keep native commands unmodified.
- Project live/running status, native title and current conversation facts into Sessions. Stop/Close/Delete/Rename/Reload operate on the actual transport; unsupported native capabilities must be explicitly reported, not simulated.
- Non-goals: changing OMP core, a new terminal framework, terminal screen parsing, synthetic keystroke control, native-command vetoes, global external-writer exclusion, GUI/VS Code process control, installing or committing this package.

## Current State

`TabState` resources are keyed by immutable editor slot E. The conversation T and controlling/passive binding are durable in SessionIndex; VS Code owns editor existence. Dynamic `omp.session.b2.*` view types cannot change in place. `TerminalPane` currently mounts only in the separate folder-shell `ShellView`; the Chat App never mounts it. `ensureTerminalPipeline` already accepts a generic broker `PtyHandle`, and the bridge already carries terminal frames. Folder shell ownership/grace must remain separate from managed sessions.

The currently installed CLI reports `omp/18.4.4`; interactive TUI is its default mode, `--mode rpc-ui` selects chat, and `--resume <exact file>` resumes the requested conversation. The source checkout is 18.2.11 and is not authoritative for installed runtime contracts.

Source of the installed `@oh-my-pi/pi-coding-agent` package (18.4.4; `src/` directory, paths below relative to it) proves:

- `extensibility/extensions/types.ts:458-490` provides live `ctx.isIdle()`, `hasPendingMessages()` and graceful `shutdown()`; `ctx.agent` is an identity, not an AgentSession handle.
- `runner.ts:1355-1374` passes the live SessionManager object and live state functions into contexts. `agent-session.ts:7631` defines idle as not streaming; it does **not** establish transition settlement.
- `session-manager.ts:2154-2163` has a materialization method, but it is outside the extension's read-only SDK facade and is **not used**. `getSessionFile()` alone does not prove persistence (`:2623-2631`).
- SDK `pi.setSessionName()` is native durable rename (`types.ts:1613-1617`). No handoff marker is appended to native history.
- `interactive-mode.ts:6507,6682-6722` disposes before quitting, but `ctx.shutdown()` sets an irreversible deferred request; it does not abort. Queued submissions/background jobs can delay exit. `extension-ui-controller.ts:230,462` routes the request; `event-controller.ts:2148,2175` retries it after turns. A control acknowledgement/EOF is not writer-exit proof.
- `agent-session.ts:10447,10575-10582,10619-10798` emits `session_switch` before remaining awaited work and possible rollback. Its public `waitForSessionTransition()`/settled callbacks are not currently proved reachable from an extension context. Before hooks and repeated equal snapshots are not a settled witness.

## Proposed Design

### View preference and editor identity

Store `chat | terminal` as the profile default using `context.globalState`, with Chat as the initial default. Read it whenever used; refresh the Sessions title context on toggle and window focus because Memento has no cross-window change event. Store actual view mode with the durable editor binding, not in native JSONL or immutable view type. Identity-only webview saved state remains identity-only.
The Sessions title action reflects the current profile default with the Chat comment-discussion or Terminal icon and mode-specific tooltip. Both open the same picker; the command palette retains exactly one generic Choose Default Session View entry.

The maintainer's final clarification: normal Open/click on an existing tab reveals its actual mode. The current default applies when opening/creating a tab, including reopening a closed editor with a surviving writer; an opposite live mode uses the existing guarded replacement. Explicit Open in Chat/Terminal takes precedence and switches an existing tab. A stopped single click is non-mutating in either mode (history in Chat, a stopped placeholder in Terminal); rapid second click/Open starts. Restore precedence is verified live host transport, then saved slot mode, then default; a known actual/saved mode is independent of the current default. Attachment persists actual transport mode so a provisional selection cannot poison later restoration. Automatic relaunch uses the recorded attempt transport; native resumes an exact existing file, and drafts require the existing restoreDrafts opt-in.

The same WebviewPanel gets a fresh immutable document credential for a replacement child; retire the previous route. Keep bounded draft text on the host per slot until a Chat document is ready, discarding it on dispose or conversation change. Do not deliver the draft to Terminal. Attachment bytes cannot leave their document; report attachment loss explicitly. Nothing is persisted to logs or editor saved state.

### One-writer transition

Fence Chat prompt admission and all mutating Chat commands (model/thinking/UI responses/compact/rename) plus terminal input separately from the conversation gate. Under the gate capture the exact slot, broker/root identity, current file/id and epoch, then release it before modal consent. Reacquire and revalidate before acting; never hold the lifecycle gate during a dialog. Busy means not settled: RPC `get_state.isSettled` plus compaction; native `isIdle`, no queued messages, and public `getAsyncJobSnapshot()` showing neither running jobs nor pending deliveries. Missing native state is unknown/busy. Terminal output and timestamps are not authority.

Busy consent explains abort and possible queued/background delay; decline restores admission without changing process/mode. The native action rechecks synchronously and refuses busy without consent; with consent it calls public `ctx.abort()` then `ctx.shutdown()`. Accepted shutdown is irreversible and can be deferred. Keep a visible stopping fence; after bounded timeout show still-finishing with explicit force Stop, never restore normal admission or start a successor. A late exit only marks stopped; it never starts a deferred successor automatically. For RPC recheck settled immediately before EOF; an async wake that wins that final race remains a documented residual risk.

Before settlement inspect current file and conversation content (RPC messageCount; native entries containing user/assistant messages, queried only at transition boundaries). If content exists without a durable file, refuse **before stopping**; a session row with a missing file is a failure, not an empty draft. No private materialization method or synthetic entry is used. Recheck file presence after disposal. A no-turn draft with no file is explicitly allowed to become a fresh empty session.

Native graceful settlement requests shutdown via authenticated control, then waits for that broker's matched child-exit state and a creation-time absence probe for the exact root; bare-pid liveness, EOF and ACK are not proof. Broker PTY stop closes ConPTY and is only an explicit force fallback, never graceful disposal. Both transports require exact-root absence. Tree emptiness is not claimed on Windows; disclose ADR-0029's uncontained-tree limitation.

Keep the draft/file claim and running intent across a mode transition; suppress the ordinary exited/release path while settlement is owned. Before successor launch atomically commit actual mode and the selected transport attempt with null identity. Failure records stopped and releases the claim. Durable successors use best-known exact file, its header cwd, and row profile/session-directory settings. Fileless no-turn replacement uses an explicit leased draft-reset operation only after exact old-root exit and confirmed file absence; it preserves tabId/ordinal/claim/binding while replacing native session identity. It touches no disk and cannot reset a session row.

### Managed native runtime and host control

Add a native runtime using the existing binary resolver, staged host-control module, recipient bootstrap and broker launch/attach. Use `managed-omp`, not folder-shell grace. Extend the existing authenticated protocol with strict bounded session state, public async-job settlement facts, guarded shutdown and rename; snapshot/listTools stay compatible. Query content only at transition boundaries, not every status tick.

Native control is process-bound (pid, creation time, control slot and recipient), with handshake sessionFile expectation null; session identity is readback, not connection authority. Key credential/process material per launch so row rebinding cannot delete a live process's control. Release only after proven exit. Distinguish unsupported methods from unavailable control. Installed `/restart` respawns a descendant without Bun bootstrap flags; explain unavailable control and offer native `/exit` or explicit force Stop with tree-unknown warning. The maintainer approved: no automatic successor after uncontrolled force; another explicit Open is required, and a positively observed survivor refuses successor.

Periodic authenticated state updates activity/name; native events are hints. Natural root exit marks stopped. Restore requires authenticated broker proof and an explicit native discriminator; migrate every `transport !== rpc` legacy assumption. A stopped Terminal shows retained broker screen while attachable, otherwise a placeholder with Start in Terminal/Open in Chat; never silently spawn.

### Native user-driven conversation changes

Native `/resume`, `/new`, branch/tree commands remain native and are never intercepted or vetoed. The maintainer's contract-2 decision explicitly makes native identity rebinding **best effort**: the editor initially remains bound to the launched session; supported session-switch hints and authenticated current-file readback may rebind it. No transition-settlement proof is required for these user-controlled operations. Preserve E while rebinding T; a detected owned conflict demotes the newcomer, not the incumbent.

Observed A→B transfer acquires B's claim first, moves the RecordedHost identity from A to B without claiming root exit, retires A's host and marks A stopped, bumps the editor binding generation, then releases A's claim. A verified rival makes the newcomer passive/conflicting. A native `/new` without a durable file creates B as a new claimed draft, later promoted normally. Rollback reverses the same procedure. Before extension-owned Open/Resume/Reload launches a known file, read current-file state fresh from this window's live owned native processes, avoiding a positively observed own writer hidden by a stale row. Failed/stale readback remains best effort; this is not a global ledger or native settled witness.

`session_switch` precedes remaining work and possible rollback; idle is not a transition barrier. The observed identity can therefore briefly be speculative, missed or stale. On Terminal→Chat, settle the native process first, require exact root exit, and continue the best-known current file. That best-known file may not be the native user's intended conversation when a switch/rollback races observation. This is an explicitly accepted risk, not a settled-identity guarantee. Extension-initiated successor launch still never overlaps the old writer.

### Surfaces and lifecycle consumers

Mount TerminalPane in the session App under mode-specific presentation. [ADR-0043](../decisions/0043-place-session-mode-actions-in-editor-title.md) replaces the original in-page selector with opposite-mode editor/title navigation and native Copy Screen overflow; existing lifecycle refusal remains authoritative. Managed terminal recovery wording names the session, not a folder shell. Keep nonce stamping and licensed Codicon assets; permit renderer style attributes under [ADR-0041](../decisions/0041-allow-terminal-style-attributes-under-nonce-stylesheets.md), retaining nonce/resource-gated stylesheets/scripts and existing network boundaries.

A native page may mount before its successor's PTY is published. The existing running projection starts a fresh authenticated terminal attach when the host becomes available, including after an early unavailable answer; current passive permission controls rendered input. Sessions and the window status bar report native liveness from that PTY, not from an absent RPC conversation.
Native frontend publication installs its output watcher and explicitly activates the broker's PTY stream before reporting availability. Authenticating/adopting the broker handle is not that subscription. Attach reports the desired fit but does not acknowledge a resize; ownership triggers the actual resize, so the displayed grid and native broker geometry agree.

The pane shows current problems, not a historical notice log. Managed panes have only abnormal in-pane notices; separate folder shells retain their header. Normal adoption/reset emits no persistent warning. Screen-damage notices remain until a valid repair snapshot or a replacement screen. [ADR-0044](../decisions/0044-resynchronize-on-stream-discontinuity-and-retain-broker-ownership.md) makes healthy probes non-resetting and broker ownership independent of DOM blur.

Native and folder-shell panes share VS Code terminal font settings resolved for their terminal resource: `terminal.integrated.fontFamily` with `editor.fontFamily` fallback, plus terminal font size, line height and letter spacing. Attach supplies current settings even before broker readiness; configuration changes update existing xterm instances and refit without replacing their screens or processes. Only the owning pane resizes the PTY. System-installed fonts require no URL/font fetch; the existing restricted font CSP continues to allow bundled local fonts.

The earlier installed comparison found editor-default Consolas lacked the exercised Nerd Font PUA glyphs and Cascadia Code NF lacked model U+EC19, matching VS Code's integrated terminal. The [native UX design](2026-10-03-native-terminal-ux.md) augments the unchanged configured-first family with common/installed Nerd and symbol fallbacks, including existing Codicon for U+EC19. It does not override OMP's symbol preset or add a font dependency; canonical isolated no-font-override acceptance and its limits are recorded there.

Explicit recovery of a recorded managed RPC or native survivor re-proves and attaches it. The legacy Stop-and-Open confirmation applies only to legacy/unmanaged records, never to a managed native session whose existing writer can be attached.

Route Stop, Close, Delete and Reload through verified actual broker kind and the same settlement primitive. Reload preserves mode and exact file. Rename uses native `pi.setSessionName()` readback in Terminal, existing RPC rename in Chat and existing native storage helper while stopped. Terminal activity is native idle/pending state, not process-running alone. Native file/id/name updates feed the same index/title projections as RPC.

Gate Chat-only palette commands/keybindings with the active panel's mode context; in Terminal they report unsupported or leave handling to native TUI (especially Escape). Add symmetric explicit context entries for every session state. Default consumers include palette/folder New Session, folder Resume picker, discovered history and inline Open, only when creating/opening a tab.

## Alternatives

- A second terminal editor: rejected; violates same-tab requirement and separates editor ownership.
- An external VS Code terminal: rejected; wrong requested surface and not the existing owned PTY pipeline.
- Rendering TUI from RPC events: rejected; not the unmodified native TUI.
- Running RPC and TUI simultaneously: rejected; introduces two extension-owned writers for one native file.
- Screen scraping, synthetic keystrokes or guessed session files: rejected; cannot prove busy/settlement/persistence and changes native behavior.
- Bringing back Collab/Hub/raw recorder: rejected; neither view needs those removed transports.

## Risks and Open Questions

The maintainer resolved the SDK limits without OMP/private changes: native identity is best effort; fileless no-turn drafts can reset; ordinary Open reveals an existing tab; uncontrolled `/restart` force-stop never auto-launches a successor and observed survivors refuse one. Remaining risks: speculative/missed identity, deferred irreversible shutdown, RPC final idle/EOF race, Windows tree limits, external writers and attachment loss. No native settled-identity or forced persistence guarantee is claimed.
