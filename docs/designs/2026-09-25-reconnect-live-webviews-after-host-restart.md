# Reconnect surviving OMP Webviews to a new extension host

## Implementation status (2026-09-26)

The design is **implemented and locally verified, not yet live-verified**. Its status stays
`accepted`: the accepted criteria require an isolated installed-VSIX run with a real Webview and a
real native OMP process, and that run is **unexecuted** — the package's desktop computer-control
permission was revoked after an isolated window overlapped the user's own work, so no visible
VS Code window, focus change or keystroke may be used. No behaviour below is claimed as observed in
a real window.

What *is* established: the whole path is implemented (`src/bridge-protocol.ts`,
`src/bridge-identity.ts`, `src/host/bridge-records.ts`, `src/host/bridge-listener.ts`,
`src/host/bridge-route.ts`, `src/host/bridge-endpoint.ts`, `src/host/editor-coordinator.ts`,
`src/webview/lib/bridge-client.ts`, `src/webview/bridge.ts`, and the wiring in `src/extension.ts`,
`src/host/guest-webview.ts`, `src/host/control-client.ts`, `src/webview/messages.ts`,
`src/webview/panel-identity.ts`), and the transport is exercised end to end in process by
`src/host/bridge-e2e.test.ts` — the real listener, the real durable records and the real guest
client module, including a host-only restart that rebinds the recorded port, adopts the surviving
document and re-authenticates the page into a new host generation. The installed-target premises
(exact Origin, CSP, WebCrypto, `TabInputWebview` mapping, exclusive bind and same-port rebind,
serializer laziness) were measured against VS Code 1.139.1 by an isolated probe; its evidence
notes are not kept in the repository.

Still unverified: anything that needs a real Webview or a real native host — the panel-route
offer/ack round trip, the secret delivery and acknowledgement in a live page, the native/Collab
binding assembly against a live process, the legacy one-time migration of a real generic panel, and
model/thinking/Tools over the bridge. Independent read-only security review found two material
defects (an unauthenticated-socket allowance that was never returned and an observed editor close
that did not retire its endpoint, port or secret), both repaired with regression tests. A second
review found the production SHA-256 binding and workspace hashes rejected as 128-bit tokens in
the panel bind/ack parsers; both boundaries now validate 64 lowercase hex characters, with a
positive round trip and malformed-hash tests. A refused unauthenticated socket also no longer
clears the incumbent document's live route.

A final independent read-only security review found three further material
source defects: endpoint close left captured native reservations dispatchable,
heartbeat pongs used plaintext on an authenticated encrypted socket, and
duplicate editor membership could replace the elected editor's bridge. The
endpoint now retires its routes synchronously, the last native-send fence
rechecks live editor/native ownership, pongs use the sequenced encrypted
writer, and membership reconciliation honors the editor election across
asynchronous adoption. The close fence and real listener/client heartbeat
have end-to-end regression coverage; editor election also has focused
coordinator tests. A focused independent corrective review
found all three repairs sound and no new material security issue in those paths.
These are source-level repairs, **not** installed-Webview acceptance. The final
VSIX was installed into the ordinary VS Code profile by CLI on explicit user
request, without opening or controlling a VS Code window. Its live behavior
after either restart action remains unverified.

## Ordinary-profile installation follow-up

After CLI installation, the user reported a restored editor showing “local Collab
relay is not available.” The ordinary VS Code OMP output log actually reported
the loopback relay ready, then repeated listener binds for the same editor ID
and `record-unwritable` refusals for competing ports. The exact failure is
concurrent per-editor endpoint creation in activation/serializer/panel paths,
not evidence that the native host or Collab relay died. Endpoint creation now
shares one in-flight result for each editor. Document preparation and panel
adoption may complete in either order without losing the document ticket; if
bridge preparation genuinely fails, the restored panel uses the already
supported non-bridge Collab chat route instead of retaining an unrelated relay
placeholder. This repair has **not** yet been observed after another installed
VSIX reload; no existing native OMP process was stopped or relaunched for
diagnosis.

Review of that repair also found two ordering boundaries: a guest rendered before
the ticket existed was incorrectly reused by the same-kind/same-relay cache, and
closing during an endpoint bind could leave its editor reservation behind. The
document cache now includes its bridge document ID, and close releases the
reservation synchronously before forgetting even a late-bound endpoint. A
headless regression covers late bind and record cleanup; actual installed-Webview
recovery remains unobserved.

## Problem and boundary

The user develops this extension inside an OMP chat. **Restart Extensions** replaces the extension host but leaves an already-resolved Webview and its direct Collab chat connection running. The new host does not receive the old `WebviewPanel` handle: `postMessage`, `onDidReceiveMessage`, `reveal`, title changes and disposal through that handle are unavailable. This does **not** prevent the surviving page from opening its own authenticated connection to the new host. Before the bridge, chat could still reply while the Sessions tree filtered out unbound panels and model/thinking/Tools requests went through the dead panel message route. **Reload Window** instead destroys the old page and restores the saved editor through its serializer. Both actions must resume the same verified native OMP process without requiring a manual Open/Resume.

A Webview already orphaned under a build that did not ship this bridge cannot acquire new JavaScript, a new CSP origin or a secret through its dead VS Code message route. One **Reload Window** after upgrading installs the new document; future host-only restarts can reconnect it. This is a real migration prerequisite, not a promise to retrofit already-running old code.

## Goals and non-goals

- Keep the original, still-open Webview and its Collab connection/composer mounted across host-only restarts; authenticated model/thinking snapshots/mutations and read-only Tools recover through the new host. Rebuild Sessions from actual editor membership and verified registration/ownership; preserve native PID, room and claims when the recorded process survives and verifies.
- Keep the existing serializer and VS Code layout authority on Reload Window. An explicitly closed tab must not be recreated from a saved bridge record, index row or stale heartbeat.
- No native host-control key or Collab write token in persisted Webview state, bridge messages, logs, endpoint metadata, or URL. No guest-chosen native host, pipe, cwd, claim, session file, command execution, Tool mutation or unverified fileless control access.
- A surviving orphan cannot regain `WebviewPanel` APIs through the bridge. Exact tree-row Focus/reveal, title/icon changes and panel-specific operations need an honest unavailable state while that editor is orphaned; selecting its already-open tab remains possible in VS Code. Do not silently report complete parity for those operations.

## Editor identity and migration

Let `W` be this profile's canonical workspace-storage URI hash, `T` the indexed `tab:<uuid>`, `E` a fresh random 128-bit **actual editor** ID and `D` a fresh random 128-bit **HTML document** incarnation. New panels have a versioned namespaced viewType containing `T` and `E`; saved Webview state is identity-only `{version:2,tabId:T,editorId:E}`. `E` survives serializer re-creation of that editor, but every actual `webview.html` replacement mints a new `D`; merely reconnecting after Restart Extensions does not. Two windows viewing `T` normally have different `E`s. A type with `T` alone cannot identify which duplicate editor closed. Validate external registered type, `panel.viewType`, saved `T/E`, actual `TabInputWebview.viewType` and indexed `T` together; disagreement selects no session or credentials.

Every document the host builds for a dynamic editor carries that editor's own `(T, E)` namespace, and it is the host rather than the panel kind that decides which identity is saved: the guest document names the tab in its meta tag and the editor in its bridge ticket, and the bounded *fallback* document — the explanation a panel shows while its relay or bridge is not ready — runs an inline bootstrap that persists the whole version-2 state. A document that cannot name a valid identity saves nothing instead of a weaker one. A guest document with no bridge ticket (an editor whose listener could not be provisioned) saves the version-1 state, because it has no editor id to write; that is exactly the state the recovery below covers. For editors an earlier build already left in the legacy version-1 shape `{version:1,tabId}`, the dynamic serializer accepts that state once, and only when the editor's own registered viewType, the saved tab and the durable **controlling** binding of `E` to `T` (`EditorSlotBinding.role`) all prove the same pair: the editor is then bound exactly as a version-2 revival (same reservation, one writer, no claim change) and its next document writes the version-2 identity. A missing viewType, a mismatched tab, or an absent/passive/foreign binding is still refused, so no editor of another conversation and no second writer is ever guessed. An explicitly unrecognized editor keeps today's bounded explanation and persists nothing.

Legacy `omp.session` cannot change its readonly viewType in place. A first post-upgrade Reload Window invokes its serializer only when each saved panel is resolved (hidden panels can wait until selection). After validating saved `{tabId}`, synchronously reserve the first valid saved editor as the winner over a transient explicit panel under ADR-0019; a second saved callback loses. The winner's serializer creates a **single typed successor** in its source view column, with `preserveFocus` for a background source, binds that successor before intentionally disposing only the exact legacy predecessor, and reuses the existing native attempt. This is ADR-0023's one-time exception to supplied-panel adoption, **not** replacement of an upgraded surviving page during Restart Extensions. Exact tab order, preview/pin state, concurrent group moves and unsent input are not preserved. The legacy type itself keeps the version-1 identity its own serializer reads (including when its migration is refused), so a legacy panel is never migrated into a state its type cannot be restored from. If source/group identity cannot be validated, leave an honest explanation instead of guessing. A pre-bridge resolved generic orphan cannot be retrofitted; show extension-owned Reload Window guidance. Unresolved hidden panels migrate lazily on their first serializer callback, not necessarily in the first reload.

Subscribe to TabGroups changes before the synchronous startup snapshot. Register the legacy serializer and an exact serializer for every recognized dynamic viewType in actual live membership, **including stale indexed IDs**, before asynchronous native work; register each newly observed type on tab changes and before creating its panel. A stale type's resolver shows a bounded explanation and starts no native work. No wildcard activation assumption, title/order inference or index-driven tab recreation. Prove the installed `mainThreadWebview-` prefix mapping in an isolated instance. Actual TabGroups membership governs editor existence; index/claim governs native authority; socket/secret records never govern editor existence.

Use one editor/document transition coordinator per `T`, distinct from the ADR-0015 native-operation gate. Its synchronous reservation tracks winning `E`, provenance (saved or transient), pending transition ticket, observed close/open sequence, current `D` and selected route generation. A previously authenticated orphan is an occupied saved winner; a later different-editor callback is a duplicate, while the callback for the **same `E`** after full reload installs a new `D`. An explicit Open joins/reveals the winner, including a pending legacy migration, instead of starting another editor/native attempt. Capture source disposal immediately; after **every** provisioning await recheck reservation, exact source editor, index and observed close. Re-read source group/focus just before creation, publish successor only for the winning ticket, and ensure disposing its predecessor cannot retire its endpoint/native runtime. A close observed before publication cancels it; a close observed after publication retires that document. Public VS Code APIs cannot make physical close and create/dispose atomic, so a truly overlapping user close may briefly leave a successor; never promise strict physical close-wins across the unobservable commit race. Staged asynchronous SecretStorage writes may finish after cancellation but confer no authority and are cleaned by their exact ticket. Restart between creation and predecessor disposal may save both; first validated saved callback wins next time without a second native attempt.

## Authenticated host bridge and durable ownership

Store one exact listener per `E`, not a shared per-window broker. Bind `127.0.0.1:0` exclusively before rendering the editor, record the chosen port for that `W/T/E`, and rebind **only that exact port** after host restart. Each editor's CSP includes its assigned exact bridge origin plus its existing exact Collab relay origin. The OS listener bind is the resource-writer lease; test real Windows exclusive behavior. On startup, only `E` values present in **this window's actual recognized TabGroups membership** are candidates, not every indexed row or every stored secret. Another window's different `E` cannot be rebound here; even a copied same `E` must fail closed if ownership/bind is ambiguous. Sibling native authority still requires the current holder lease. An occupied port is never replaced by scanning or a new random endpoint for the old page.

Use individually immutable private records rather than one workspace/tab mutable slot: `bridge/v1/W/T/E/endpoint` is `{v,W,T,E,port}`, a **complete** `docs/D` is `{v,W,T,E,D,port,path,origin,bootstrapId,nativeBinding,bindingHash}`, `manifest` names only the current `D` and its `prepared|committed|retired` state; `SecretStorage` key `omp.bridge.v1/W/T/E/D` holds solely an independent random 32-byte browser reconnect secret `K`. A prepared manifest may name `D` **before** `docs/D` exists. Only after Origin and `B0` verify, atomically write the complete immutable descriptor, store `K`, and commit the manifest; authentication requires committed state with every matching record. `E` and `D` are globally random, so two same-workspace windows cannot rotate or delete each other's credentials. Records are resource metadata, not an editor-open registry or native claim. The exclusive listener owner alone may change that `E`'s manifest or retire its exact `D`. Do not sweep records because this window lacks another window's tab. A close attributed to this exact owned `E` fences requests, tombstones that `D`, deletes only its secret and releases its listener; a crash can leave inert records, never authorization to open a tab. Deactivation releases sockets without retiring live documents, Collab relay or OMP.

Provision the exact endpoint/CSP/`D` before installing HTML, but **never delay ordinary Collab chat on native host-control availability**. The existing trusted panel sends its available Collab link with a fresh host `connectId` immediately under the usual rules; the guest remembers that link/client association in memory. An endpoint descriptor remains prepared and **no bridge secret is delivered** until the matching native peer/control identity can be verified. If verified while this exact panel/document still exists, compare its current unchanged link and `connectId` with the host's original delivery, persist the canonical Origin and `B0`, commit that `D`, then deliver independent bridge secret `K` and bindingHash over the panel and receive an ACK from the guest's **existing** chat client for the same connectId/link. This does not redeliver a link or remount GuestClient. If control never initializes, chat still works and controls remain unavailable. If the page becomes orphaned before a verified `B0` and ACK, the new host cannot provision it via its socket; show bounded Reload Window guidance rather than assigning a new process. A crash before commit or bootstrap delivery likewise leaves no reconnect-authorized document; after delivery a reconnect proof for committed `D` can confirm it despite a missing ACK. A newly installed HTML document (including relay-unavailable → guest, relay change, serializer or migration) fences old `D`, prepares its own secret and repeats this bootstrap. No HTML change or rotation on host-only restart, visibility change, native-ready invalidation or unchanged render. Do not store a reusable secret in Webview state, URL, link, terminal options, logs or relay metadata.

Pin host-authored `B0` **when native control can verify the already-delivered original Collab link**, not as a prerequisite for delivering chat: owner generation; native PID and creation time from the existing peer-verified handle, control slot/instance/epoch; session ID and exact file if already known; and separately validated Collab instance/generation/room from that same link. Hash a fixed-order encoding into `bindingHash`. The guest acknowledges that hash only if the remembered `connectId` and currently installed chat client still refer to the unchanged link, and includes it in its bridge handshake. Neither browser nor stored endpoint chooses native identities. A recovered orphan receives controls only if current verified PID **and creation time**, owner generation/current holder, control slot/instance/epoch, Collab instance/generation/room, indexed session and exact-file authority match `B0`. A different native process, PID reuse, session switch or room rotation leaves its old chat in a fixed `native-binding-changed` state with no controls; a recreated panel/document may establish a new binding through the trusted route. Only the ordinary draft's null-file → exact promoted-file transition may advance file authorization without changing original process/control/Collab identities; do not rewrite `B0`. A materialized dead host may follow existing resume policy, but this bridge never attaches the old page's controls to its replacement.

## Bridge wire protocol v1

The original panel route receives ready `[1,D,bootstrapId,location.origin]`, validates its current document ticket and a canonical non-opaque Webview Origin, and persists that **exact** Origin; do not infer it from `cspSource` or learn it from an unauthenticated socket. Upgrade only `GET /omp-webview/v1/bridge` on literal IPv4 `127.0.0.1`, exact `Host: 127.0.0.1:<recorded-port>`, no query/body/subprotocol credential, exactly the pinned `Origin`, loopback local/remote address and no duplicate Host/Origin headers. Disable compression and discovery routes. If installed Webview Origin, CSP or WebCrypto cannot satisfy this, fail the runtime gate; never accept `*`/`null` Origin or weaker localhost trust.

`A(x)` is UTF-8 of `JSON.stringify` over fixed-length ASCII-field arrays with canonical unpadded base64url for 16/32-byte binary values (reject extra fields/noncanonical encodings). `W` and `bindingHash` are lowercase SHA-256 hex. The client sends `['hello',1,W,T,E,D,bindingHash,C]` with fresh 32-byte nonce `C`. The server uses the **already-minted activation-wide** 16-byte host generation `H` and chooses fresh 32-byte nonce `S` and per-connection 16-byte ID `Q`. Define **text** transcript `X=JSON.stringify(['omp-webview-bridge',1,W,T,E,D,bindingHash,'ws://127.0.0.1:<port>','/omp-webview/v1/bridge',origin,C,S,H,Q])`; all its elements have canonical ASCII encodings. `H` is stable only until the next extension-host activation; `Q` is fresh on every WebSocket connection.

The server returns `['challenge',1,S,H,Q,HMAC-SHA256(K,A(['server',X]))]`; the client verifies **before sending any proof** and then sends `['proof',1,HMAC-SHA256(K,A(['client',X]))]`. Verify MACs with cryptographic comparison. Derive separate 32-byte AES keys with HKDF-SHA256(`IKM=K`, `salt=SHA256(UTF8(X))`, `info='omp-webview-bridge/v1/c2s'` or `/s2c`). Never reuse ADR-0006 native credentials.

An encrypted binary frame is `version:u8(1) || direction:u8(0=c2s,1=s2c) || sequence:u32be || AES-256-GCM(ciphertext,tag:16)`, with IV `8 zero bytes || sequence:u32be` and AAD `A(['omp-webview-bridge',1,H,Q,D,direction,sequence])`. Each direction starts at zero; accept **only** the next sequence, close on replay/gap/bad tag/reflection, reserve counters and serialize crypto so browser WebCrypto completion cannot reorder, and reconnect before `2^20` messages. The first encrypted server frame is `['ready',H,D,status]`; until both proofs pass no session payload or control authority is sent. Route negotiation uses `['route-offer',H,D,R,status]` from host and `['route-ack',H,D,R]` from guest; reject stale/cross-document ACKs, and disable mutation if no matching ACK arrives within five seconds. An exactly corresponding pair of `omp:control-route`/`omp:control-route-ack` panel DTOs uses the same H/D/R/status checks. Application messages are strictly `['request',H,D,R,requestId,actionSeq,operation,payload]`, `['reply',H,D,R,requestId,result]`, `['invalidate',H,D,R]`, `['status',H,D,R,status]` and `['ping'|'pong',id]`. `requestId` is a random 128-bit correlation ID; `actionSeq` is a strictly increasing unsigned decimal-string counter for **all** guest requests within one `D` (including route changes), not a second native ID. Mutation admission keys on `(D,actionSeq)` and fences H/R; browser never replays a timed-out action into a new host generation. `operation` is only current model-list/snapshot, set-model, set-thinking and read-only tools DTOs with their existing validators; statuses are fixed bounded codes. Native requests never accept guest-chosen process/file/pipe.

Limits: HTTP headers at most 8 KiB; handshake JSON 4 KiB before parse and absolute five-second timeout from TCP acceptance; at most 16 unauthenticated sockets per host, two per listener, one active authenticated endpoint per `D`; framed message ≤256 KiB plus 22 bytes, plaintext ≤256 KiB, queued outbound ≤1 MiB, eight outstanding reads and one mutation per `D`, nesting ≤16 with existing DTO string limits. A failed newcomer does not evict the incumbent. Heartbeat every 15 seconds; 45 seconds without authenticated traffic marks **disconnected, never closed**. Limit even pre-auth accumulation; bounded fixed-code diagnostics contain no raw frames, URLs, errors, credentials or external strings. Browser `crypto.subtle` and Node WebCrypto must match deterministic transcript/proof/key/IV/ciphertext vectors in a real installed Webview, not just Node tests.

## Control routing, editor lifetime and ownership

Retain existing DTO validators and peer-verified native pipe, but send/receive through one **authenticated document endpoint** rather than requiring `state.panel` for all controls. Endpoint states: `PROVISIONING` (fresh HTML, chat may work independently, no verified bridge binding/ACK); `PANEL_BOUND` (exact panel/document and acknowledged VS Code route); `DISCONNECTED` (no acknowledged route, chat still mounted); `BRIDGE_AUTHENTICATED_WAITING` (original document/membership verified, native attach or exact file not ready); `BRIDGE_READY` (the same endpoint and exact native checks ready); `RETIRED` (observed close/supersession/native identity mismatch). A WebSocket opening and an `acquireVsCodeApi` object are not proof of a usable route. Native readiness is independent of chat delivery and transport. Authentication before native attach or draft promotion enters waiting, then the current endpoint receives one read-only invalidation/snapshot automatically once ownership and file authorization arrive. An orphan never provisioned with verified `B0` stays disconnected and reports Reload Window guidance while its existing Collab chat may continue.

The host offers **one** route selected for activation-wide host generation `H`, document `D` and fresh endpoint generation `R`: panel messaging when this exact panel/document handle exists, otherwise authenticated bridge for an eligible orphan. Fence the previous `R` synchronously, send `route-offer(H,D,R,status)` through the chosen route and require a matching `route-ack` within five seconds before enabling mutation. A bridge may remain authenticated standby for a panel-bound document but cannot dispatch; a guest cannot fan out to both routes or infer route health from the existence of the VS Code API. On route loss/change, clear control correlation books by `(H,D,R)` without remounting GuestClient/composer; a sent unanswered mutation has **unknown** outcome, is never replayed, and read-only snapshots may refresh. Native-ready, ownership and promotion invalidations travel over the current acknowledged endpoint, not the missing panel. Old host generations/endpoints and delayed replies/ACKs are rejected. Orphan-only Focus/reveal, title/icon and other non-allowlisted panel operations show unavailable rather than silently entering `postMessage`.

Before an irreversible native mutation, both panel and bridge requests enter one per-document admission path. Under the editor coordinator synchronously check current `H/D/R`, exact tab membership and ownership, reserve the request's strictly increasing `actionSeq` with bounded payload identity, and mint **one** native request ID for that reservation. A duplicate `(D,actionSeq)` from another route or with a changed payload cannot reserve again; retain a high-water mark even after a result cache is evicted. Recheck document/membership/native binding immediately before native handoff, including inside the existing native client's queued send so a close or route loss while queued cancels before its first write. After a send with no response the outcome is unknown: query the same recorded native request only if still valid, never issue a new mutation ID. The native mutation ledger is a second safeguard, not a replacement for guest admission. Browser transport does not buffer/replay mutations as CollabSocket does. Closing a tab cannot undo an already handed-off native action.

The Sessions provider is re-registered on activation. Its open rows derive only from actual validated dynamic `TabGroups` membership, indexed folder identity and the elected authenticated panel/document (or an explicitly reconnecting matching editor); close of that exact `E` retires its endpoint and row while preserving native OMP under existing close semantics. A timeout/pagehide is only a hint. A saved serializer callback for the same `E` installs a new `D`; another saved/editor callback for `T` loses against an authenticated surviving orphan under the one-winner policy. Tree-row Focus cannot `panel.reveal()` an orphan and instead instructs selection of the already-open tab without opening a duplicate. A source close while provisioning cancels only its own resources; copied/other-window `E`s or losing duplicates cannot revoke the winning document. No editor callback/listener preparation holds the ADR-0015 native lease; reuse one native attempt.

## Alternatives and rollout

- Replace the old Webview with a new panel: supported but loses its running page/composer and has difficult close/lazy-serializer races; [the rejected replacement proposal](../decisions/0022-replace-orphaned-webview-editors-after-host-restart.md) overstated that this is necessary for controls and tree recovery.
- Add model/tool mutations to native Collab: the installed OMP guest protocol lacks these typed operations, and updating the extension does not hot-patch the already-running native process; this widens native capability grants.
- Extend the detached relay: it currently forwards binary Collab frames only, and digest-versioned older sidecars remain alive after upgrade. A new route would not exist on the old relay used by a surviving page. A separate pre-provisioned exact listener avoids silently replacing that sidecar.
- Rebind the lost `WebviewPanel`: no supported VS Code API returns that handle for an already-resolved tab.

Ship bridge support with the new guest bundle and CSP. A first Reload Window is required for existing pre-bridge pages. Do not install a VSIX and promise an already-orphaned page will recover without that reload. Keep legacy serializer only while old saved panels remain possible; no title/order inference or automatic mass tab recreation.

## Verification and limits

First run an isolated installed VS Code probe for exact Webview Origin/CSP/WebCrypto, exclusive Windows localhost binding and same-port rebind on built-in Restart Extensions, two `TabInputWebview` type mappings and a lazy generic serializer after Reload Window; never control the user's ordinary window. Interoperability tests compare browser/Node transcript, proofs, keys and frames, then reject altered fields, reflected/reordered/replayed frames, forged Origin/Host/path, occupied ports, oversized/slow handshakes and cross-tab credentials. Lifecycle tests pause each provisioning await and close the exact source, race saved/explicit/duplicate editors and HTML replacement, inspect stale type explanations and orphan route switches/ACKs, and assert one native dispatch with no mutation replay. Native binding tests cover same PID survivor, PID reuse with different creation time, native death/resume, session switch, room rotation and draft promotion. When native peer verification is unavailable but Collab works, initial/reloaded chat must still exchange a prompt/reply; controls stay disabled, later same-link provisioning works only while the panel survives, and an unprovisioned orphan gets honest Reload Window guidance. Multi-window tests use the same workspace and tab in two windows with distinct `E`s, independent/simultaneous restarts, one window's close and the other's unchanged secret/listener. Crash tests cover before prepared/committed/bootstrap/ACK and after tombstone.

For installed-VSIX live acceptance, record a memory-only document sentinel, `D/E`, GuestClient identity, unsent composer canary and selected editor/group **before** Restart Extensions. Across repeated host-only restarts verify that same document/client and unsent text remain, no `webview.html` assignment or panel replacement occurs, and the original Collab connection remains if the network itself is healthy. Then prove same verified native PID/room/session and zero additional launches, chat prompt/reply, actual model/thinking mutation/readback, read-only Tools and Sessions membership. The later Reload Window must instead create a fresh `D`, reject the old credential and use the serializer while conditionally retaining the same native process; an explicitly closed third tab stays closed. Orphan Focus must show its honest limitation. Inspect persisted state, endpoint files and diagnostics for capability/secret canaries. No mock reply alone is acceptance.

If exact listener rebinding, secure guest origin/authentication, tab identity mapping or a reliable native-owner fence fails in the installed target, do not weaken them or silently revert to mass tab replacement; record the concrete failed gate and revisit the decision.
