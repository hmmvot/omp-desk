# Sessions sidebar and in-tab OMP terminal

> Ownership clauses narrowed by [ADR-0039](../decisions/0039-refuse-only-on-a-verified-live-writer-the-extension-owns.md): unknown ownership is not Blocked; stale/release states disappear, verified legacy children are Running, and Resume/Delete offer one confirmed stop-and-continue. Exact-file transactions and folder shells survive.

> Narrowly superseded by [ADR-0038](../decisions/0038-host-chat-over-rpc-ui-on-a-broker-pipe-child.md) and its [RPC-UI chat and Sessions design](2026-09-29-rpc-ui-chat-and-sessions.md) for the in-tab native TUI, the Chat | Terminal switch and native session switching. Still operative: the Sessions sidebar, stopped/live rows, folder shell, unified Resume/Delete, Rename/Reload and user-controlled semantics.

## Problem

The existing Sessions view lists only open Webview editors. Closing an editor hides a still-running OMP host; explicit session termination, durable agent activity, native TUI in the same editor tab, folder shells, native session switching, and deletion from folder-scoped Resume are not represented consistently. The user selected one coherent UI and explicitly accepted the bounded risks below. This design describes intended behavior, not currently implemented behavior.

## Goals and non-goals

- Keep a genuine interactive OMP process and its Collab GUI on one authoritative native session. Within one VS Code editor tab, show persistent **Chat | Terminal** controls and render the real native TUI through an extension-owned PTY and terminal renderer. Retain a running process when the editor closes or the extension host reloads; a complete VS Code exit need not preserve its PID.
- List indexed running and stopped conversations under OMP-registered folders, regardless of editor presence. Keep exact session ownership distinct from editor-slot identity and folder navigation.
- Give folder-scoped Resume one unified list of discoverable OMP history files, including files produced outside the extension, with per-file deletion. Make all destructive or process-replacing actions explicit.
- Support switching a managed native TUI from conversation A to B in the same process/editor, including B in a previously unregistered working folder. User-typed `/resume` and similar native terminal commands are **the user's responsibility**; do not impose unreliable prehook vetoes or an all-hosts deletion blockade. Detect and visibly disable/error clearly broken editor bindings without promising to prevent earlier overlapping writes or repair history.
- Do not change or reinstall OMP core, silently attach to a manually started OMP, launch a second writer on uncertain ownership, alter VS Code workspace folders when registering an OMP folder, or silently treat a display alias as a native rename.

## Baseline before this cutover

`src/host/native-terminal.ts` launches installed OMP in a hidden `vscode.Terminal` and verifies its PID against local Collab host metadata. `src/extension.ts` connects one Webview guest, and `SessionIndex` keeps exact-file extension claims. A closed editor leaves its native OMP process running but removes the row because `src/views/session-tree.ts` filters by open panel. The tree groups only explicitly registered folders. `Resume` scans OMP history on demand and labels indexed versus previously unknown candidates differently; deletion refuses imported files. The existing control channel permits model/thinking mutation but not Rename or Reload. Current editor, native host, and indexed session identities are coupled. None of the PTY broker, in-tab TUI, background status, native switching transfer, or new actions described below is already implemented.

## Accepted design

### Surfaces and ownership

An extension-managed, independently surviving PTY broker starts the **actual resolved OMP executable directly**, with the existing profile, cwd, exact `--resume` or new-session directory, local-only Collab overlay, and authenticated host-control preload. The broker records the OS-proven process generation, PTY I/O, bounded terminal screen state, and terminal dimensions; it never stores control capabilities in Webview state or logs. Its lifetime is independent of the Webview and the extension host for verified same-window reattachment. One active terminal frontend owns input and resize; hidden or disconnected renderers do not drop output. A new Webview frontend authenticates and receives a consistent screen snapshot or proven replay before accepting input. A stale editor generation cannot send input, resize, approvals, or host-control commands to a successor process. Across a full VS Code exit, first reconcile the recorded broker and native OMP process generation: adopt a proven surviving writer, or start a new exact-file writer **only after** positive old-writer absence under its canonical claim. An unreachable broker, missing room, stale heartbeat, expired lease or absent extension-host process is not proof of native exit; uncertainty retains a blocked row and reservation, never silently stops the survivor.

The broker and its entire runtime load tree (native addon, helper executables/DLLs) are staged in a verified content-identified private directory outside the installed extension before launch; retain copies used by surviving generations under ADR-0012. Native PTY and broker runtime ABI compatibility is an installed-VSIX gate. The existing versioned authenticated document bridge gains separately authorized terminal input/output/resize/snapshot frames, including a verified fileless draft with its reserved claim; a surviving Webview with no new panel handle can reconnect without changing ADR-0023's materialized-only gate for model/thinking/Tools. Broker-client transport is independently authenticated and bound to document incarnation, exact process creation time and claim generation. The Webview stores only identity, not a reusable PTY or native capability.

The same `WebviewPanel` has a persistent, visible **Chat | Terminal** switch. Chat uses the local Collab guest; Terminal uses a bundled xterm.js-compatible renderer connected to the broker PTY, not a second OMP process or VS Code's integrated terminal. Initial mode is Chat; closing and reopening an editor restores its last mode. Switching modes does not stop or relaunch OMP. When a native question/approval arrives while Terminal is shown, remain in Terminal and let the native TUI settle it; do not automatically move focus or settle it twice. The running session's native TUI exit leaves its editor open with an explicit Stopped presentation and a stopped sidebar row. The user closes the editor at will. Editor close while OMP runs detaches the frontend only; selecting its row reopens a **new** editor and attaches to the verified same PID/room, refusing rather than launching if attachment cannot be established.

A **folder** context action, `Open Terminal`, is different: it creates a separate xterm.js editor and a **new** general-purpose shell whose cwd is that folder; it never reuses another folder shell implicitly. Users may run and exit arbitrary commands, including manual `omp`. A manually launched OMP is not silently registered, attached to the full-control GUI, or represented as a managed Sessions writer: its Collab room could be absent, view-only, or using a remote relay, and it lacks the extension's authenticated control bootstrap. After that process exits, its saved history can appear in the folder's unified Resume if its exact file is discoverable. VS Code exposes **post-close**, not cancellable pre-close, notification for a WebviewPanel. Persist a recoverable shell-slot identity **before** awaiting any prompt, and retain it throughout detached/prompt-pending, interrupted or uncertain-stop states until positive tree-exit proof. Closing an editor with a live shell detaches it first, then asks whether to terminate that exact shell **and its children**, including any manual OMP. Only affirmative Confirm authorizes stop of the verified shell tree; Keep Running recreates a folder-shell editor attached to the **same** broker/PID/screen, never launching a replacement. Dismissal/interruption, failed recreation or unverified/failed stop never authorizes termination or drops the slot. The folder context exposes **Reconnect Terminal** when a recoverable detached shell exists; with multiple slots it opens a picker, and its action only attaches to the selected verified broker/PID/screen, never creates a shell. `Open Terminal` always remains New. The original tab cannot literally be kept open after VS Code closes it. A clean shell exit needs no stop prompt. On extension-host restart a verified surviving shell reattaches to its actual editor or remains reachable through Reconnect; on **proven full VS Code exit** the shell broker owns a finite orphan grace period and terminates only its own tree. Frontend/extension-host disconnection while the window remains alive must not trigger shell-grace expiry or managed OMP termination.

Persist **run intent** separately from current availability and editor presence: an explicit Close, confirmed native TUI exit or retired A is stopped until an explicit Resume, even after Restart Extensions, Reload Window and full VS Code restart. Activation may reattach a previously running verified survivor, or recover a previously running session under the exact-file admission rules after confirmed writer absence; it must never auto-start a deliberately stopped row or fileless draft whose writer died. Serializer revival of a stopped editor presents Stopped, not an implicit Resume. Distinguish a process that was active before a host crash from one the user explicitly closed.

### Sessions tree and actions

The view header has **Add Folder** only; the empty view also links to that action. A registered folder is always visible, even with zero sessions, and shows its basename plus path. Folder-row inline actions are New and Resume; folder context actions include Open Terminal and Remove. Remove never deletes a directory, transcript or host, and is refused while a managed OMP session in that folder runs. Folder registration is presentation metadata, not VS Code workspace membership or a second claim database.

Each indexed conversation has one row under its canonically matching folder, even with no editor. Running rows precede stopped rows in a single list. The row label uses OMP's stored title, otherwise a stable per-conversation `New session N` label. The icon, not descriptive status text, conveys agent state. Native TreeView selection marks the last selected OMP session even when another kind of editor gains focus. A stopped icon overrides agent activity; blocked/unknown ownership has its own warning icon and reason in the tooltip. No inline buttons appear on session rows. The conversation's **editor tab** is named by the same rule rather than by the working folder — OMP's stored title, the last title this window observed, then the ordinal label — and carries the OMP icon (`media/omp-icon.png`), so a tab is never a second copy of the folder name and two untitled conversations stay distinguishable in the tab strip; the appearance is re-applied when a panel is bound (created, restored or migrated), when a settled native switch moves an editor to another conversation, and after a rename.

The row's description does not repeat its status or JSONL basename. Its tooltip names the status in text before the ownership reason and exact file path, so icons are not the only way to understand a row.

For an attached, live guest, precedence is Blocked/Unknown ownership, Stopped process, structured pending Question, Working/streaming, heuristic Question for a completed assistant text whose trailing whitespace is followed by `?` as its final character, Answer Ready for a completed unviewed reply, then Waiting for Input. The trailing-question rule is explicitly a heuristic, not proof of an actionable question; a pending question is never hidden behind Working. Error, abort, disconnect and unknown must not be mislabeled successful completion. Record a stable conversation-scoped last-completed reply identity and last-seen identity, not just a boolean. A completed answer becomes seen only when its content is actually displayed in a focused, visible Chat or Terminal surface; hidden chat output or a detached editor does not mark it seen. After tab close, observe exact matched Collab host `busy`/`inputRequired` metadata independently of Webview, and the exact native transcript for last-completed text when possible. Initial idle snapshots or reconnects must not manufacture unread replies. Missing/stale evidence yields Unknown, not the previous live activity.

Clicking or choosing **Open** on a running row attaches/focuses the same verified process and editor; a stopped row's **Resume** starts a new OMP process from its exact file and makes that row running. Both explicit menu items remain despite row-click duplication. Running-row menu: Open, native Rename, Close Session, Reload. Stopped-row menu: Resume, native Rename, Forget, Delete. On ownership uncertainty disable mutations and explain why. Close Session always confirms, stops the exact process, verifies writer absence, durably records stopped intent, retains history and the stopped row, and never releases a claim after uncertain stop. A stopped row's Forget removes only the extension index record; its file remains discoverable in Resume. Delete requires confirmation, exact-target revalidation, exclusive canonical deletion claim held across native transcript plus associated-artifact deletion and transaction finalization; a fileless draft has no transcript to delete or resume.

For older imported bookmarks without a recorded extension host, a blocked row may still offer Forget and Delete in its context menu; offering either is not permission to mutate. Forget drops only a safely removable bookmark and leaves another generation's claim and the native file alone. Delete rechecks the exact file, local host, claim, and positive absence proof under its own exclusive transaction and refuses unresolved writers. A missing transcript offers Forget, not Delete. A retained extension-owned uncertain broker/writer still offers neither destructive action. A saved old row whose persisted intent says running but has no running host is presented as stopped, rather than displaying an untrue Running status.

Rename changes **OMP's actual stored title** in the TUI, tree, the conversation's editor tab and Resume; no VS Code-only alias. OMP 18.3.0 has a mutable current-session setter with no atomic expected-session target and asynchronous persistence. The user accepted the bounded risk of the wrong session title/metadata changing during a concurrent native switch. Check exact native identity immediately before dispatch, use the authenticated at-most-once channel and verify actual title afterward; describe a mismatch, never silently claim atomicity or attempt an unverified rollback. Stopped-file renames require exclusive extension-claim ownership and the installed native storage manager, not direct JSONL title-slot surgery. No second interactive writer is started for that operation.

Reload on a **running, materialized** session always requests confirmation, including during an active turn. Warn that in-flight text, requests or tool effects may not be completely persisted; never resend them. Retain the exact-file claim throughout a generation-fenced replacement, confirm old PID/room withdrawal, then start a fresh process with `--resume` of the exact verified current file/profile/cwd, rotate all native capabilities, and rebind the same editor and selected Chat/Terminal mode. A failed or uncertain stop never starts a replacement. If a successor's launch outcome is unknown, reconcile instead of replaying launch; if the old process stopped and launch failed, retain the stopped row/editor with a reason. For a draft without an existing valid JSONL, Reload is unavailable rather than masquerading a new draft as Resume. A stopped row already has Resume rather than Reload. On confirmed native process exit, leave its editor open as Stopped.

### Unified Resume and deletion

Folder Resume performs the current explicit, cancellable scan of supported native history roots and indexed exact paths. Display **one row per canonical OMP file** and its actual title/metadata, with no visible split into extension-known and externally found history. Selecting a running record focuses its verified owner; selecting a stopped record resumes its exact file. Every eligible row has a trash button; confirmed deletion updates the picker in place and is also available in a stopped session row's context menu. A row with a known live writer, held/unknown extension claim, missing file or unverifiable target cannot be deleted; **another unrelated live managed host alone does not block deletion**. Confirm the exact JSONL and disclose recursively deleted sibling artifact directory and all adjacent `<basename>.*.bak` backups, plus that an independent OMP or a user's native `/resume` may enter the file during deletion and destroy history. Freeze and revalidate the target under the exclusive canonical deletion claim and local per-file lifecycle gate, held through transcript/artifact cleanup and row finalization even for unindexed candidates. Record partial transcript-versus-artifact/backup removal separately; no stale picker snapshot authorizes unlinking or a success report.

### Native conversation switch and folder registration

A managed TUI `/resume B` changes the conversation in the **same** OS process and editor. Preserve an immutable editor slot and a mutable, generation-bound editor-to-conversation binding: after a verified successful switch A remains an indexed stopped conversation under its original folder, B receives the running binding, title, activity and Reload target, and the Webview obtains the newly verified Collab room. Do not turn an old A request, recorder consent or host-control result into a B operation. Keep A's writer claim until its retirement is established; after observing B, acquire an available exact B claim for extension-side controls, but **do not veto the user's native TUI command** when unavailable. If B is already owned elsewhere, mark this editor conflicting/noncontrolling rather than stealing B's row or control. Support native new/fork/branch paths without guessing a fileless identity from the newest JSONL. If B already has a stopped editor in this window, preserve that editor's unsent draft but make it non-controlling; the initiating editor becomes B's sole controlling surface only on a nonconflicting verified binding, and the old editor remains readable/copyable until the user closes it.

Reconciliation uses a **fresh live native Collab registry IPC snapshot** for a room serving B, matched to the same OS PID and creation time, Collab instance with generation newer than A, authenticated host-control current exact B file/session/cwd and the validated B header. In installed OMP 18.3.0 the replacement room starts only after its internal transition barrier settles; a live registry snapshot is served only while that room is current and the session is not transitioning. This is a positive post-transition witness for the **observed successful path**, unlike an early `session_switch`, a cached link or a generic later model snapshot. Durably commit the editor-slot→B binding and A's retired-writer intent with that correlated evidence **before** releasing A's canonical claim and advertising its stopped row as resumable. A later user-typed native switch back to A is a separate operation under the user-responsibility boundary; the extension does not promise to prevent it from overlapping a prior writer. No new room, mismatched identity, restart without persisted proof or rollback retains A as visibly Blocked rather than falsely resumable and fences unverified GUI controls; do not launch another host just to create room evidence.

Native `/new`, fork, branch and tree transitions do not always supply a prospective exact target file. Record the observed operation/process/source generation, fence old credentials and preserve A's claim; validate and claim the actual target once its native header and exact file are observed, **without** inferring identity from the latest disk file. Their native writes can precede posthoc exact-file ownership: report a detected conflict and make the broken editor noncontrolling, without a new global reservation or prehook veto. Publish/retire only after the fresh settled-room witness above. A truly fileless target keeps its own native draft reservation until exact materialization; missing prospective identity is not permission to claim a null file. If uniquely attributable target/settled room evidence is unavailable, keep the transfer Blocked rather than relabeling A or starting a duplicate writer.

For a valid B whose header records a usable absolute working directory, validate that folder's canonical path after observing the native target, even when it lies outside the VS Code workspace or current OMP Sessions registry. After B's binding is verified, durably add/deduplicate its folder in the **current OMP Sessions registry**, then expand/reveal B, without altering VS Code workspace roots. An invalid/inaccessible path or post-transition registration failure cannot retroactively veto the user's native command: hold affected extension controls in a visible blocked state and retry registration, never assign B to A's folder or fabricate a row. Rollback before publication does not add B's folder. Concurrent explicit folder edits must be serialized with auto-registration; explicit Remove is still refused while a managed writer in that folder is running.

The installed OMP 18.3.0 `session_before_switch` hook is optional and fail-open, and `session_switch` precedes possible rollback. Following the user's latest instruction, native commands are not subjected to new extension-side veto or global admission machinery. Detect a known B conflict against exact verified process/claim evidence as soon as possible; show a fixed-category error and mark **only the newcomer editor** conflicting/noncontrolling, preserving the incumbent B. Earlier writes may already be mixed, and leaving the newcomer process alive remains the user's responsibility. Do not automatically stop either writer. The user may explicitly choose Close Session on the newcomer; confirm, stop its exact process and close only its editor after positive PID/room withdrawal, otherwise leave it visible. Never claim a detected error repaired the file. Ordinary extension-issued New/Resume/Reload and Delete still revalidate their own exact claim; they cannot control user-typed native transitions or independent OMP processes.

## Alternatives

- `TerminalLocation.Editor` opens a second VS Code terminal editor; it cannot replace a Webview's content while retaining tab identity. The old VS Code-owned PTY does not expose its output stream for xterm.js takeover. An extension-owned PTY with a single Webview and independently surviving broker is the chosen substantial cutover, not an in-place migration of an already running VS Code terminal.
- A GUI RPC process followed by `omp --resume` in a separate terminal would replace the live PID and lose an active turn. A manually started folder-shell OMP is not silently equivalent to an authenticated extension-managed host.
- A mandatory fail-closed native admission/settlement API would prevent conflicting TUI writes but changes OMP core. The user instead owns native terminal commands; extra global conflict reservations or a ban on deletion whenever another managed host exists were expressly rejected. Extension-issued New/Resume/Reload still require their own exact-file claims, without promising to control user keystrokes.
- Detecting a B conflict after `session_switch` alone is too late to prevent B writes. Show and deactivate a clearly broken newcomer tab; do not silently kill a process or represent a warning as transcript repair.

## Risks and open questions

The PTY broker, runtime packaging, restart/reconnect, exact native identity and Webview rendering require an end-to-end runtime proof. The existing VS Code-owned OMP processes cannot be retroactively attached to the new PTY; do not stop or restart them silently during rollout. `node-pty` or an equivalent native PTY implementation adds platform binaries and extension-host/broker lifetime and packaging concerns. A terminal emulator must handle OMP's actual Unicode, alternate-screen, mouse, paste and resize behavior, with bounded output retained while hidden. Multi-window holder claims exclude extension writers only; independently launched OMP processes remain outside that guarantee. The user revoked desktop/visible VS Code control permission for this task; headless source/runtime checks do not establish a verified visible editor appearance.

**Windows prebuilt-addon limit (user decision, 2026-09-27).** The current `node-pty` ConPTY launch has no creation-time Windows Job Object. A parent-PID snapshot cannot prove that a grandchild with an exited intermediary is gone, so affirmative Confirm may authorize a termination attempt through owned PTY handles without establishing that the **entire** shell tree stopped. ADR-0024 separately permits a shell-only finite grace after positive proof of the owning VS Code instance's exit; frontend or extension-host loss alone is not authorization, and managed OMP brokers are excluded. ADR-0030 implements an attested main-process-generation monitor with real-process fixture proof, but no installed-VS-Code window-close observation under the user's desktop-control denial; an unattestable main leaves automatic stopping disabled.

The user explicitly declined a system C++ Build Tools installation after being told the positive exact-tree-stop criterion would remain unmet. The fallback **must** report `tree: unknown` (or `remaining` when observed) and `verified: false`, retain the recoverable shell slot, never signal a stale numeric PID, and describe termination as an attempt rather than promise whole-tree success. A natural root exit or retention timer is not proof. Explicitly stopping/replacing a managed writer separately requires absence of its matched process **and** matched Collab room; a roomless launch remains held. An A→B conversation retirement in the **same** PID instead uses ADR-0025's settled-room witness and durable binding. The positive folder-shell tree-stop step 3 below is **still open**, not passed by an unknown result; [accepted ADR-0029](../decisions/0029-report-uncontained-pty-tree-stop-as-unknown.md) records the narrower safety decision. Installed VS Code appearance remains separately unverified.

**Owning-instance exit scope (ADR-0030).** For an attested local Windows VS Code main-process generation, a broker-retained kernel handle signals that the owning application instance ended; the extension host, one Webview and an individual window are not substitutes. The folder shell's finite grace starts only when all admitted, positively verified main generations have ended. An adopted, verified new generation cancels an older grace epoch; an unverified association disables automatic stopping. This is not a claim about every VS Code installation or an instance that never reaches the broker, nor proof that escaped descendants exited. Installed VS Code topology and post-exit grace still require runtime verification; the architecture is accepted separately in [ADR-0030](../decisions/0030-watch-the-verified-owning-vscode-process-for-shell-grace.md).

## Rollout and verification

1. Keep this design and its ADRs `proposed` until separate independent architecture reviews; record material corrections before acceptance.
2. Implement broker/process lifecycle and xterm Webview surface first; prove direct PID = Collab registry PID, exactly one OMP process **per extension-issued launch**, two-way native TUI input, Chat→Terminal→Chat during a live turn, editor detach/reattach and extension-host reload. Keep old live VS Code-hosted processes untouched until they exit; this check does not claim to control user-typed native transitions.
3. Cut over folder shell and session model with stopped/running rows, title/ordinal/status, exact resume/deletion and commands. Exercise explicit managed Close, native TUI exit, closed editor with live host, Rename, Reload idle/busy and fileless draft refusal. Separately exercise **folder-shell native X with manual OMP child**: Confirm stops only the exact shell tree; Keep Running preserves broker/PID/screen with zero shell launches; dismiss, fail recreation, fail/uncertain stop and restart during pending prompt each leave a discoverable folder Reconnect route. Prove multiple detached shell slots pick the exact survivor, and shell-only full-exit grace never runs on frontend/extension-host loss while VS Code remains alive or terminates a managed OMP broker. Do not use the user's desktop/visible VS Code to make this claim without a new permission grant.
4. Exercise A→B within and outside registered folders, a second stopped editor with an unsent draft, an observed B owner conflict, missing/mismatched settled-room evidence, rollback uncertainty and the passive newcomer-error state. Verify a user-typed native command is neither vetoed by the extension nor followed by an automatic process stop; a positive settled witness must precede A's resumability. A detected conflict does not repair prior writes.
5. Run focused deterministic tests and build/package the VSIX. Use headless native OMP and local Webview harness where supported. Do not drive the user's desktop, existing browser or existing OMP process without a new permission grant. Update `docs/architecture.md` only with implemented and actually verified behavior; retain unverified runtime boundaries explicitly.
