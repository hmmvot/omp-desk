# ADR-0060: Merge background processes into Sessions and stop everything through each process's own lifecycle or authenticated route

## Context and Problem Statement

The Processes view listed the PTY brokers that host sessions and folder terminals next to the Sessions view that lists the sessions. The two overlapped, a session's live process was only visible in the other view, and no action ended everything. The user asked for a single Sessions view that marks live processes, shows terminals without sessions separately, has a Terminals layout, and offers Stop Orphaned and Idle and Kill All, where Kill All ends everything in this window and may also end the processes of other windows after an explicit offer. The Processes design had deliberately left "stop everything" undecided because it ends live, driven sessions in this and other windows.

Constraints that stay: no process id is ever signalled (ADR-0029, ADR-0037, ADR-0039); a session's stop runs through its own lifecycle under the per-tab gate (ADR-0015); a process authenticated by a record is stopped only after its identity is re-verified; the view that is always visible must not poll expensively.

## Considered Options

- **One Sessions view over the existing reader, with Kill All stopping this window's rows through their own lifecycle, asking every other live window to stop its own rows through the window request channel, and using the authenticated broker only for rows no window runs or answers for, in confirmed tiers.** One list, one reader, one stop function; a live window's processes end through that window's own stop lifecycle.
- **Keep two views and add Kill All.** Leaves the duplication the user asked to remove.
- **Stop every window's processes through the broker from this window, with no request.** Simple (any window can authenticate to a broker) but, for a session or terminal another live window runs, it bypasses that window's lifecycle (no stopped intent or claim release by the owner, no per-tab gate, and the owner's exit handler races the broker's retirement). Rejected by the product decision of 2026-10-11.
- **End processes by PID or process tree.** Rejected by the standing ADRs: the check and the kill are not atomic and Windows cannot prove a tree.
- **Kill All limited to rows this window shows.** Leaves a "kill all" that leaves processes running and no single action that ends them.
- **Treat a row with no known window as this window's.** A session another window holds is `none` until its claim is observed; this would stop another window's work without the explicit choice the user required.

## Decision Outcome

First option.

- **Sessions is the one place.** The Processes view is removed. A session row marks its process from its own status (and from the process snapshot's facts when it has them); processes that no listed row stands for are served in a separate **Terminals** group in the flat and folders layouts, and every process in the new `terminals` layout. The Processes design's classification, reader, identity caches and presentation words are kept, moved behind the Sessions provider.
- **One stop path.** Single Stop, Stop Orphaned and Idle and Kill All call the same row stop function, which chooses the `driven`, `recorded` or `broker` route from a fresh derivation exactly as the Processes design defines. A session this window drives is stopped through its own lifecycle; nothing here signals a PID.
- **Kill All has three tiers behind one modal.** *This window* is exact local identity: a session whose runtime this window holds under that exact slot, broker id and generation (an editor-only runtime included), or a folder terminal an editor of this window carries for the generation it attached to; a session another window holds is that window's even when this window has an editor on it. *Other windows* are rows another window holds; *not run by this window* is everything else stoppable (no window shows it, or this window only shows it). The last two are acted on only after the explicit choice *Stop in All Windows*, because a window attribution is a record, not proof. Rows this build cannot authenticate to are never attempted and are named in the result. Every dispatch is revalidated against a fresh derivation (the same broker: id, generation, PID and creation time, in a tier the choice covers) and the confirmed set only shrinks.
- **Other windows are asked, not bypassed.** "Stop in All Windows" sends a `stop` request over ADR-0056/0057's window request channel to each other live window. It carries only the row identities the requester was shown (slot, broker id, generation, type, conversation; no process ids). The receiver takes the request up (atomic rename), re-reads its own processes, and stops through its own lifecycle (native shutdown with stopped intent, Chat stop, the per-tab gate, the shell lifecycle) only the rows that still equal an identity named and that it provably runs, never forcing, and answers per row (`stopped`, `unconfirmed`, `refused`, `changed`). The receiver is graceful only end to end: its session flows are captured without a Force Stop or any other modal, and a failed graceful stop is answered `unconfirmed`. The requester aggregates every window's answers into one report and cross-checks it against a final fresh read; a window's `stopped` is advisory and counts only after the requester independently proves the row's broker gone by its process identity. A row no window answers for (every window refused it, a window that never took the request up as a requester that kept watching proved, or a window whose outcome was uncertain and whose extension host is proven gone) is stopped by an explicit fallback route (this window's own lifecycle if the row became locally driven, otherwise the authenticated broker bound to the exact slot, broker id, generation and process identity, never a recorded reattach) and reported as stopped without its window. A live window that took the request up and went silent, a request that could not be withdrawn, and a requester that was suspended while evidence could have been swept are all *uncertain*: the rows are left alone and reported until the window's extension host, identified by process id and kernel creation time when it was asked, is positively proven gone: a lapsed lease, a missing or unreadable registry and an undecided probe prove nothing, because a hung host can resume the request it took up, and the broker never acts concurrently with a request that may still be served. A registry that cannot be read leaves every row another window may run alone. Take-up evidence outlives the ordinary sweep, the whole wait is bounded, and a row nobody was asked about that another window attached meanwhile is left alone. Rows no window can run (orphans, idle processes, detached terminals, the Stats dashboard) are stopped through the broker as before.
- **The writer's exit and the broker's exit are separate evidence.** A row's own flow proves the session's writer gone, not the broker retired; the broker's process is probed by its recorded identity afterwards, and an unproven exit is reported as not confirmed on every route.
- **One serialized reader, bounded polling.** `process-wiring.ts` owns the reader; every read, the poll's and every controller's, runs through one queue and is published to the Sessions provider. No background read while Sessions is hidden (explicit actions always read fresh); explicit reads on visibility, layout change and after stops; ticks every 5 s in the `terminals` layout and every 30 s elsewhere, plus one debounced tick after launcher refreshes; one authenticated child-state read per newly seen broker; a verified identity is trusted for 60 s of wall time.

### Consequences

- Positive: one list for sessions, terminals and their processes; every stop action reaches the same row stop function; a live window's processes end through that window's own lifecycle; Kill All's result says per row what each window or route confirmed.
- Negative: a new request kind (versioned, validated, bounded, with a take-up and progress protocol) and its failure modes (a window that does not answer, one that goes silent, a request that cannot be withdrawn, a suspended requester, an older build that ignores the kind, a hung window whose host cannot be proven gone); Kill All is destructive and its duration grows with the number of processes; a terminal held by another window cannot be revealed from here; a mark derived from status can be a moment out of date; the visible-only poll now runs for the main view (slower in the common layouts to bound its cost). A request file is writable by any local process of the user, so a forged request can make a window stop only processes it runs itself (the same as an ordinary Stop) and the window says in a notification what it stopped.

## Architecture Review

- Reviewer: independent `architect` agent, two rounds (2026-10-11).
- Outcome: round 1 accept after fixes (addressed); round 2 not accepted, so this ADR stays `proposed` with the [design](../designs/2026-10-11-sessions-unify-processes.md): a native session held by another window is stopped through its broker's graceful stop rather than the owner's native shutdown lifecycle (needs the product owner's decision); the owner window's convergence after a remote shutdown is unverified; `drivenHere` is slot equality; driven and recorded routes prove the writer gone, not the broker retired.
- Notes: a desktop notification for a session whose process has ended, activated in the Terminals layout, switches to the user's last session-serving layout (flat by default) and reveals the session's row, so it is not silently dropped. "one stop path" above means one function choosing the existing routes; it does not mean every route has the same lifecycle effects. After round 2 the product owner decided that Kill All must not stop another live window's processes through the broker; the request kind above implements that decision, and the same revision carries exact local broker identity and independent broker-exit evidence. This revision has not been re-reviewed.
