# ADR-0060: Merge background processes into Sessions and stop everything through each process's own lifecycle or authenticated route

## Context and Problem Statement

The Processes view listed the PTY brokers that host sessions and folder terminals next to the Sessions view that lists the sessions. The two overlapped, a session's live process was only visible in the other view, and no action ended everything. The user asked for a single Sessions view that marks live processes, shows terminals without sessions separately, has a Terminals layout, and offers Stop Orphaned and Idle and Kill All, where Kill All ends everything in this window and may also end the processes of other windows after an explicit offer. The Processes design had deliberately left "stop everything" undecided because it ends live, driven sessions in this and other windows.

Constraints that stay: no process id is ever signalled (ADR-0029, ADR-0037, ADR-0039); a session's stop runs through its own lifecycle under the per-tab gate (ADR-0015); a process authenticated by a record is stopped only after its identity is re-verified; the view that is always visible must not poll expensively.

## Considered Options

- **One Sessions view over the existing reader, with Kill All stopping this window's rows through their own lifecycle, asking every other live window to stop its own rows through the window request channel, and using the authenticated broker only for rows no window runs or answers for, in confirmed tiers.** One list, one reader, one stop function; a live window's processes end through that window's own stop lifecycle.
- **Keep two views and add Kill All.** Leaves the duplication the user asked to remove.
- **Stop every window's processes through the broker from this window, with no request.** Simple (any window can authenticate to a broker) but, for a session or terminal another live window runs, it bypasses that window's lifecycle (no stopped intent or claim release by the owner, no per-tab gate, and the owner's exit handler races the broker's retirement). Rejected by the product decision of 2026-10-11.
- **End processes by PID or process tree.** Rejected by the standing ADRs: the check and the kill are not atomic and Windows cannot prove a tree.
- **Kill All limited to rows this window shows.** Leaves a "kill all" that leaves processes running and no single action that ends them.
- **Treat a row with no known window as this window's.** A session another window holds is `none` until its claim is observed; this would stop another window's work without the explicit choice the user required.

## Decision Outcome

First option.

- **Sessions is the one place.** The Processes view is removed. A session row marks its process from its own status (and from the process snapshot's facts when it has them); processes that no listed row stands for are served in a separate **Terminals** group in the flat and folders layouts, and every process in the new `terminals` layout. The Processes design's classification, reader, identity caches and presentation words are kept, moved behind the Sessions provider.
- **One stop path.** Single Stop, Stop Orphaned and Idle and Kill All call the same row stop function, which chooses the `driven`, `recorded` or `broker` route from a fresh derivation exactly as the Processes design defines. A session this window drives is stopped through its own lifecycle; nothing here signals a PID.
- **Kill All has three tiers behind one modal.** *This window* is exact local identity: a session whose runtime this window holds under that exact slot, broker id and generation (an editor-only runtime included), or a folder terminal an editor of this window carries for the generation it attached to; a session another window holds is that window's even when this window has an editor on it. *Other windows* are rows another window holds; *not run by this window* is everything else stoppable (no window shows it, or this window only shows it). The last two are acted on only after the explicit choice *Stop in All Windows*, because a window attribution is a record, not proof. Rows this build cannot authenticate to are never attempted and are named in the result. Every dispatch is revalidated against a fresh derivation (the same broker: id, generation, PID and creation time, in a tier the choice covers) and the confirmed set only shrinks.
- **Other windows are asked, not bypassed.** "Stop in All Windows" sends a `stop` request over ADR-0056/0057's window request channel to each other live window. It carries only the row identities the requester was shown (slot, broker id, generation, type, conversation; no process ids). The receiver takes the request up (atomic rename), re-reads its own processes, and stops through its own lifecycle (native shutdown with stopped intent, Chat stop, the per-tab gate, the shell lifecycle) only the rows that still equal an identity named and that it provably runs, never forcing, and answers per row (`stopped`, `unconfirmed`, `refused`, `changed`). The receiver is graceful only end to end: its session flows are captured without a Force Stop or any other modal, and a failed graceful stop is answered `unconfirmed`. The requester aggregates every window's answers into one report and cross-checks it against a final fresh read; a window's `stopped` is advisory and counts only after the requester independently proves the row's broker gone by its process identity. A row no window answers for (every window refused it, a window that never took the request up as a requester that kept watching proved, or a window whose outcome was uncertain and whose extension host is proven gone) is stopped by an explicit fallback route (this window's own lifecycle if the row became locally driven, otherwise the authenticated broker bound to the exact slot, broker id, generation and process identity, never a recorded reattach) and reported as stopped without its window. A live window that took the request up and went silent, a request that could not be withdrawn, and a requester that was suspended while evidence could have been swept are all *uncertain*: the rows are left alone and reported until the window's extension host, identified by process id and kernel creation time when it was asked, is positively proven gone: a lapsed lease, a missing or unreadable registry and an undecided probe prove nothing, because a hung host can resume the request it took up, and the broker never acts concurrently with a request that may still be served. A registry that cannot be read, or one of whose records could not be read in the very read Kill All awaited (not a shared cache another read can overwrite), leaves every row another window may run alone. Take-up evidence outlives the ordinary sweep, the whole wait is bounded, and a row nobody was asked about that another window attached meanwhile is left alone. Rows no window can run (orphans, idle processes, detached terminals, the Stats dashboard) are stopped through the broker as before.
- **The writer's exit and the broker's exit are separate evidence.** A row's own flow proves the session's writer gone, not the broker retired; the broker's process is probed by its recorded identity afterwards, and an unproven exit is reported as not confirmed on every route.
- **One serialized reader, bounded polling.** `process-wiring.ts` owns the reader; every read, the poll's and every controller's, runs through one queue and is published to the Sessions provider. No background read while Sessions is hidden (explicit actions always read fresh); explicit reads on visibility, layout change and after stops; ticks every 5 s in the `terminals` layout and every 30 s elsewhere, plus one debounced tick after launcher refreshes; one authenticated child-state read per newly seen broker; a verified identity is trusted for 60 s of wall time.

### Consequences

- Positive: one list for sessions, terminals and their processes; every stop action reaches the same row stop function; a live window's processes end through that window's own lifecycle; Kill All's result says per row what each window or route confirmed.
- Negative: a new request kind (versioned, validated, bounded, with a take-up and progress protocol) and its failure modes (a window that does not answer, one that goes silent, a request that cannot be withdrawn, a suspended requester, an older build that ignores the kind, a hung window whose host cannot be proven gone); Kill All is destructive and its duration grows with the number of processes; a terminal held by another window cannot be revealed from here; a mark derived from status can be a moment out of date; the visible-only poll now runs for the main view (slower in the common layouts to bound its cost). A request file is writable by any local process of the user, so a forged request can make a window stop only processes it runs itself (the same as an ordinary Stop) and the window says in a notification what it stopped.

## Amendment (2026-10-12): Kill, an explicit process-tree kill of one row

### Context

The user decided that the Sessions context menu gets **Kill**: it ends the session's process at once, without waiting for any answer from OMP and without checking the session's state (busy, settled, ownership, claims). A session that is busy, hung or held by a window that does not answer cannot be ended by Stop, and the user wants the equivalent of VS Code's Kill Terminal. This **intentionally overrides the "no process id is ever signalled" constraint for this one explicit action only**. Stop, Stop Orphaned and Idle and Kill All keep their semantics and never reach the kill; ADR-0029, ADR-0035, ADR-0037 and ADR-0039 stand for them.

### Decision

- **What is killed.** An identity-checked tree-kill attempt on the row's recorded roots: the broker, which is the parent of the OMP child on both transports (the pipe child of a chat session, the process started in the pseudo console for a native terminal and for a folder shell), and the OMP child the session recorded as a second root. A process row (Terminals layout: folder shell, orphan, idle process, a process of an incompatible build) names its broker, and the recorded OMP child when the session recorded it under that exact broker. What happens to descendants is `taskkill`'s own behaviour: a descendant that detached from the tree earlier is not reached, and Desk never claims the tree empty (ADR-0029).
- **How.** `taskkill.exe /PID <pid> /T /F` from `System32` (never found on `PATH`): the operating system's own tree kill. Chosen over a kill mode in the staged probe helper (considered by the Processes design and deferred) because it adds no script, digest change or terminate right to a staged helper; and over `process.kill(pid)`, which ends only the root. Microsoft documents `/T` and `/F` but not an internal algorithm, so Desk relies on no ordering or snapshot property of it. Each recorded root is proven gone afterwards: by a liveness look and, when the id is still in use, by the creation-time probe; an exit code is never trusted alone. A non-zero exit with the root gone is reported as an incomplete kill, never as success.
- **The one check that stays.** Every root carries the kernel creation time Desk recorded for it (the broker's own record, or the session's recorded host). It is killed only if a fresh reading of that id equals it; an id nobody has, or one now held by a process created later, is reported as already gone and nothing is killed; a reading that cannot decide kills nothing. This is not an OMP state check. It is what makes the target the process Desk means (ADR-0035). The check and the kill are two steps, so it is a best-effort guard and not an atomic one: a stranger could be ended only if the recorded process exited and its id was reissued between them, with no timing bound claimed. A handle-based kill would close that window for a root (not for a historical tree) and is the follow-up if it is ever judged too wide.
- **No confirmation dialog**, as with Kill Terminal. The command names its target only from the tree item it was invoked on and never falls back to the active session.
- **Availability.** Every session row that can have a process (running, working, background, question, unread, waiting, restoring, stopping, starting, checking, and a row another window holds) and every process row, stoppable or not. Not on stopped, draft, blocked or externally-run rows.
- **Records follow evidence, not the kill.** Killing is permission to end a process; retiring Desk's records still needs proof about the writer, bound to the incarnation that was examined.
  - A session row's records (stopped intent, claim, host record, broker slot, control material) are retired only when the OMP child the session recorded (pid and creation time) is among the roots and was shown gone, and only for exactly the incarnation Kill examined: the launch attempt, slot, broker id and generation and process the host record names. This is one index transaction (`SessionIndex.reconcileKilledHost`, not `stopRecordedHost`, so it takes no rival-Stop exception): under the tab's lifecycle gate it requires that this window does not drive the host, that the row still records the captured incarnation and that no live rival window holds the claim; it then takes the claim (a rival that acquires meanwhile refuses it) and commits with a conditional shared write that the catalog refuses when the *committed* row no longer records that incarnation, so a replacement launch another window published meanwhile is never recorded stopped. A refused or skipped call changes nothing and is logged; a failed write is a warning. A broker's absence alone is never writer evidence, so a process row that cannot name the recorded child records nothing.
  - A session this window drives, or one a live rival window holds, is not recorded by the killing window: the driving window's own broker watch ends it (below), so the claim and the editor stay with their owner.
  - A mapping no session records forgets only its broker-slot mapping (`brokerSlots`) for a broker shown gone. A folder shell's recovery record (`shellSlots`) is never retired by Kill on a broker-only proof: it is retired by the owning window's shell watch once the shell root is also proven gone, and otherwise stays.
  - The window that drives a runtime looks once a second, with no process spawn, for its broker's process. Its absence is only a trigger: nothing is published until the broker's and the OMP (or shell) root's recorded creation times both name gone processes, waiting a bounded 30 s for a root that follows its broker (Kill ends the recorded root after the broker). Then a chat session ends the way its child's exit ends it (the session shows the process ended and the existing exit handling records the row stopped, releases the claim and forgets the slot) and a native terminal runs its existing exit handling; a folder shell retires its slot and its pane says the process ended, re-checking inside the slot's gate that an ordinary Stop or a replacement pane has not taken the watch over. When the root cannot be shown gone (still running, no recorded creation time, no probe) the runtime and the recovery record are kept and the user gets a warning. A broker that disappears without Kill (Task Manager, a crash, another window's Stop) takes the same path. A reissued broker id is not noticed by the liveness look; the proof then never holds, and nothing is released.
  - **Amendment (2026-10-17): Kill records the stopped intent before it ends the process.** The exit handling named above records a row stopped only for a normal exit (exit code 0); a crash, a signal or the operating system ending the session leaves the run intent so the next startup relaunches the row ([ADR-0031](0031-reattach-a-surviving-managed-host-through-its-broker.md) amendment), and the window that drives the session cannot tell a Kill from a crash. So Kill first records the stopped intent of exactly the incarnation it captured (`KillCommandPorts.recordStopIntent` → `SessionIndex.recordKillIntent`; a row that records another process is left alone), puts the earlier intent back when the kill then failed, and kills nothing when the intent cannot be recorded. The claim, host record and slot are still retired only on the proof described above. A broker that disappears without Kill (Task Manager, a crash) is such an end too: its row keeps its intent.
- **Reporting.** A failure (access denied, a protected process, a process that could not be confirmed gone), an incomplete tree kill, and records that could not be updated are each a warning notification and a line in the OMP Desk log; every kill is logged with who asked, the root ids, the result and, when incomplete or failed, a bounded excerpt of `taskkill`'s own output. A fully successful kill is silent; an already-gone target is an information message.

### Consequences

- Positive: one action ends the processes Desk recorded, including rows that Stop cannot reach, with a best-effort check against a reissued id; Desk's records are retired only on writer-absence evidence bound to the examined incarnation.
- Negative: the first and only place that signals a process id; a tree kill cannot reach a descendant that detached from the tree before it ran, and Desk does not prove the tree empty; work OMP had not written is lost; the owning window learns of the kill from its own watch, normally within a second or two but without a guarantee (a probe that cannot run delays or withholds it, and the user is told when it is withheld).

### Alternatives considered (Kill)

- **Force Stop through the authenticated broker.** Already exists, but asks OMP's broker, needs a live broker and a graceful attempt first; it cannot end a hung broker.
- **Kill the OMP child only.** Leaves the broker, which would then report the child exited; the user asked for the tree.
- **A kill mode in the staged probe helper** (open the process by handle, check the creation time on the handle, terminate the tree). Closes the check-to-kill window. Rejected for now: changes the staged tree digest of every runtime, gives a helper terminate rights, and is a larger security review than the user's request.
- **Skip the identity check.** Rejected by the product owner's own conservative default: killing an id Desk no longer owns could end an unrelated process.


### Amendment note (2026-10-21)

The statement above that the window driving a session "cannot tell a Kill from a crash" is superseded by [ADR-0034](0034-store-sessions-in-one-profile-catalog.md) (amendment of 2026-10-21): the driving window now reads the committed run intent (`SessionIndex.committedRunIntent`) when its process ends, so a Kill or Stop another window recorded is reported as stopped. The Kill still records the stopped intent first: it is what survives when no window sees the process end.

## Architecture Review

- Reviewer: independent `architect` agent, six rounds (2026-10-11), read-only static review.
- Outcome: **accepted** after round 6 (see the [design](../designs/2026-10-11-sessions-unify-processes.md#architecture-review) for the rounds). The main correction was the product owner's decision, after round 2, that Kill All asks another live window to stop its own rows through a `stop` request instead of stopping them through the broker; later rounds hardened the request protocol, fallback evidence and registry reads.
- Notes: "one stop path" above means one function choosing the existing routes; it does not mean every route has the same lifecycle effects. A desktop notification for a session whose process has ended, activated in the Terminals layout, switches to the user's last session-serving layout and reveals the session's row.

### Kill amendment review (2026-10-12)

- Reviewer: independent `architect` agents, read-only static review of the amendment against the implementation; rounds 1–4 by one reviewer, round 5 by a second.
- Outcome: **accepted after five rounds** (round 5 below). Rounds 1–4: no identity, publication or record-retirement blocker remained in rounds 3 and 4; round 4 left one major, the chat exit reporting. Round 1 findings (2 blockers, 4 majors, 1 minor) were addressed in the Decision above. Round 2 confirmed B2, M4 and the documentation corrections resolved and left: explicit shell Kill retiring the shell record on a broker-only proof (fixed: Kill forgets only the broker-slot mapping), record-update failures that looked like success (fixed: they warn), and the rival-claim check that preceded the gate (blocker B1). Round 3 found B1 only half closed (`reconcileKilledHost` mutated the shared in-memory row before the conditional write, so a queued unrelated save could publish it): fixed, the stopped row exists only in the private snapshot of the conditional write and this window's own state follows only after that write landed, in the same serialized turn, with a test that queues unrelated saves around a refused write. Rounds 3 and 4 asked for the loss-failure reporting to cover both transports: a native terminal or chat whose exit could not be completed after a proven loss keeps its runtime where it can and always warns, including a rejected asynchronous cleanup. The previously established absence proof is not passed into the gated exit transaction (the exit handler re-probes); the reviewer accepted conservative retention with a visible warning instead. A chat's exit completion is observed by the runtime leaving this window within 10 s, then by the handler's own catch.
- Round 5 (second reviewer): the round-4 major M3 was only partly closed — the applied catch was inside the transaction, after the runtime was cleared. An enclosing report-only catch around the whole lifecycle transaction in `handleRpcHostExited` was then applied; the reviewer **accepted** it with no new identity, publication or record-retirement blocker. The amendment is accepted.
- Not decided by the review: no change to the product defaults (no confirmation, no state check, recorded-identity check only). A handle-based kill remains the option if a zero-race root kill is ever required; discarding a shell's recovery record on a broker's disappearance alone was rejected, as it would change the recovery contract.
