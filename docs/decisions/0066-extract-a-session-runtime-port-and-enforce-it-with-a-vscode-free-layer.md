# ADR-0066: Extract a `SessionRuntime` port inside the extension host and enforce it with a `vscode`-free layer

## Context and Problem Statement

Process and conversation management (claims, launch, attach, restore, stop, the host-owned chat) is spread through `src/extension.ts` (11,527 lines) interleaved with editors, dialogs and focus, and its central record, `TabState`, mixes per-editor and per-conversation fields. The module-structure work (ADR-0065) gave the source layers a checked direction but deliberately left the launch, restore and stop paths in `extension.ts`. An independent assessment of a per-profile session daemon (2026-10-13) recommended against building one now, since it reverses accepted decisions (ADR-0030, ADR-0056) and buys little speed, but recommended cutting an in-process `SessionRuntime` port first: the seam a daemon could implement later and the structure `extension.ts` needs anyway.

A port is only a boundary if something checks it. Two facts make a per-file rule insufficient: `host/` already contains modules that import `vscode`, and the process code on the launch path reaches one of them (`rpc-launch.ts` and `native-session.ts` import `native-terminal.ts`, which imports `vscode` for one setting and the provider-login terminals). A rule has to be about what a module reaches, not only what it names.

Constraints: no behaviour change; no daemon, wire protocol or broker change; the rule must run in `npm run typecheck` like ADR-0065's; the invariants of ADR-0015, 0029, 0035, 0037, 0039, 0050, 0055, 0059 and 0060 must not change.

## Considered Options

- **A `SessionRuntime` port in a new `src/runtime/` layer, with a `vscode`-free closure rule in `check-imports`:** the boundary is a directory and a rule the build fails on; the closure rule catches a `vscode` import anywhere behind the port; costs one layer row, a prerequisite split of `native-terminal.ts`, and migration of the callers in cuts.
- **Make `host/` itself free of `vscode` and ban it per layer:** simpler rule, but nine non-test `host/` files (settings editors, pickers, debug tools, the Kill wiring, `native-terminal`) move to `wiring/`, which changes ADR-0065's layer contents and touches unrelated modules and tests; the closure rule remains correct if that later happens and then reduces to the ban. A follow-up, not this step.
- **The same port in `src/host/` with a list of banned files:** no new layer, but a list is a second place to keep up to date and says nothing about modules the listed files import.
- **Keep cutting `extension.ts` by function lists (the wiring-seam procedure) with no port:** the procedure works and costs nothing new, but each seam takes `TabState` and the mixed launch path as its dependencies and nothing stops a `vscode` call re-entering process code.
- **Build the daemon now:** answers the question the port leaves open, but reverses accepted decisions, introduces a two-sided version skew over the chat projection and a crash radius over every session, for a speed gain the assessment found mostly available in process.
- **Project references or a separate package for the runtime:** the compiler would enforce the boundary, but the repository builds from one root with esbuild and ADR-0065 declined this for the same reason.

## Decision Outcome

Proposed: the first option.

- **The port.** `src/runtime/session-runtime.ts` declares `SessionRuntime`: `open`, `restore`, `reattach`, the pure read `readTransitionFacts` (later also the gated `stop`, `stopRecorded` and `endEnded`), a conversation surface, `snapshot(s)` and one event stream. Results are per-operation discriminated unions (restore outcomes, the truthful stop verdict with a closed `code`; an unknown code of a mutating operation reads as `unconfirmed`); events and snapshots are conversation-scoped and carry an incarnation (owner generation, broker generation, attachment sequence); `ChatModel` stays inside. Calls carry neither a window id nor an editor slot as identity: the runtime instance is the claim holder (id, pid, creation time) and knows conversations, not editors. Admission is expressed by the existing fields (`allowStoppedResume`, `automatic`, `restoreDrafts`), not a two-valued intent. One implementation, `LocalSessionRuntime`, runs in the extension host. The full contract and invariants are in [the design](../designs/2026-10-13-session-runtime-port.md).
- **The honest in-process contract.** Until the last cut, the per-conversation lifecycle gate crosses the in-process boundary: `LocalSessionRuntime` has lease-bound forms for callers that already hold a lease (the stop verdict operations `requestStop`, `awaitSettled` and `confirmEnded` of cut 4 are `LocalSessionRuntime` members only: they stop or probe a process and record nothing, which is safe only because the caller holds the lease and records under it, so they are not on the port; they take no gate and cut 7 folds them into the gated `stop` and `replaceWriter`), and the runtime reaches the window through contractual `RuntimeWindow` hooks and accessors (fire-and-forget notices; the window's copy of the runtime is adopted before the broker watch starts; no gated calls, no waiting for the user, a throwing hook fails the operation). Every such member is named in the design with the cut that removes it, except `terminalHandle` and the hook `prepareView`, which stay until the native terminal's stream has its own design; none appears on `SessionRuntime` itself. `TabState.runtime` is the single copy of the runtime until the `TabState` split, read through a transitional `current(runtime)` accessor; the runtime keeps no table of its own.
- **The layer.** `src/runtime/` may import `host`, `broker`, `omp`, `protocol`, `chat` and `shared`; `wiring` and `extension.ts` may import it; no other layer may. Rules: no file under `src/runtime/` may refer to `vscode` in any form (static, type-only, dynamic, `require`, `import("vscode")`) or reach, through any chain of non-test imports, a file that does (the chain is printed); the port module uses only statement-level `import type`, from an allow-list of data-shape modules, so a live object cannot enter its contract by a type import. A module the runtime needs that touches `vscode` is split, not excepted. Test files stay exempt as in ADR-0065.
- **The first split.** `host/native-terminal.ts` keeps everything but its three `vscode` functions, which move to `host/omp-vscode.ts`; `resolveOmpBinary`'s default explicit path comes from a reader registered at activation and called on every resolution.
- **Migration** in behaviour-preserving cuts, each with its tests (design §6): the split and the layer; the port with open, restore and reattach; launch and attach; the stop verdict family (`requestStop`, `awaitSettled`, `confirmEnded` on `LocalSessionRuntime` and the port's `readTransitionFacts`: verdict only, the recording that follows a stop stays in each caller; `endEnded` belongs to cut 5). The end-of-process handlers with `endEnded`, identity, host control and the native handover, the conversation surface, and the `TabState` split with `stop`, `stopRecorded`, the compound replace flows and Kill follow as separate cuts; the design lists by name what still bypasses the port after the first four.
- **Amendment, 2026-10-20 ([ADR-0080](0080-hand-over-a-live-session-through-a-taken-up-request-that-detaches-the-holder-without-stopping-it.md)).** The port gains `detach`: a gated transition beside `stop` and `replaceWriter`, implemented in `LocalTransitions` over the existing `index`, `records`, `chat` and `control` collaborators and the launcher's broker-watch disposal. It returns a value (`detached`, `refused` with `not-holder`, `busy` or `terminal`, or `failed` with `claim-unreleased`), is DTO-only and `vscode`-free, ends this window's serving of a live session without stopping it, and renders the read-only note view through the conversation surface once the gate is released; what is window-side (the registry checks, the notification, the repaint) stays in `extension.ts` and `window-routing.ts`.
- **The daemon stays open, unbuilt.** A remote implementation would implement the same interface; what would change is who holds claims (the daemon), what a window is (a client), the temporary contract above (hooks become request/reply or events), and versioning (a handshake with an additive minor, a refused major, a compatibility window). Those need their own ADR, which would reverse ADR-0030 and ADR-0056 in part. This record neither takes nor presumes them.

Reasons: it is the smallest change that makes the extension's second shape checkable; it follows ADR-0065's mechanism instead of adding a tool; the closure rule is about the actual requirement (no `vscode` behind the port) rather than a proxy for it; and results-as-values, events with incarnations and the gate's position are the properties a later remote implementation would otherwise have to retrofit.

### Consequences

- Positive: process code is testable without a `vscode` stub; a `vscode` reference behind the port fails `typecheck` with the offending chain; `extension.ts` shrinks by the launch, restore and stop paths and each moved region gets its own tests; the daemon option stays open at no runtime cost.
- Negative: while the lease-bound forms, hooks and `TabState.runtime` exist the in-process implementation still depends on window state and is not yet something a daemon could replace (named, bounded, removed in later cuts); the window keeps the full `SessionIndex` until the last cut narrows its type, so the guarantee that nothing bypasses the claim is held by per-cut greps, not by the compiler; a module that needs both `vscode` and process logic must be split; the native terminal's PTY stream remains an in-process member until it has its own design; the event and snapshot layer adds code a purely in-process implementation would not strictly need (accepted because retrofitting it is the expensive part of a later daemon).

- Notes: round 1 returned accept-with-changes with ten material findings (M1-M10: the gate crossing the boundary, the live-object leaks in the contract, the layer rule's closure, admission as two-valued intent, and others), round 2 accept-with-changes with six (N1-N6: ungated stop forms and their deadlock analysis, adopt-before-watch ordering, cut 4 scope, fences, the daemon-contract wording), round 3 accept-with-changes with two (A: the lease-dependent stop operations belong on `LocalSessionRuntime`, not the port; B: one copy of the runtime, `current(runtime)`) plus minors. All were resolved in the documents; round 3 stated that no further review is needed once A and B are resolved.
