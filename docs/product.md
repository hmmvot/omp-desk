# Product Context

The intended product is OMP Desk, a Windows-only VS Code extension for launching and managing Oh My Pi (`omp`) sessions. The current implementation and its unverified boundaries are described in [current architecture](architecture.md); the points below remain product requirements rather than claims that parity is complete.

**Direction ([ADR-0038](decisions/0038-host-chat-over-rpc-ui-on-a-broker-pipe-child.md), narrowly superseded by [ADR-0040](decisions/0040-switch-one-editor-between-rpc-chat-and-native-pty.md)):** Chat uses OMP's `--mode rpc-ui`; the same editor also offers the unmodified native TUI under the managed PTY broker. The profile default applies only when opening/creating a tab. Collab, relay, raw recorder and Agents Hub remain removed. Sessions, Chat/Terminal and restore across host/VS Code restarts are implemented in source; installed-window acceptance of the new mode feature is separate. OAuth-dependent MCP setup remains out of scope.

- A UI that does not require the terminal for ordinary use: start a session, exchange messages, see responses and progress, and manage sessions.
- A session editor with opposite-mode **Switch to Terminal / Switch to Chat** navigation in its native editor title, native **Copy Screen** in title overflow, and symmetric **Open in Chat / Open in Terminal** session actions ([ADR-0043](decisions/0043-place-session-mode-actions-in-editor-title.md)). Chat and Terminal have no duplicated in-page mode/status rows. Chat retains history, streaming, prompts, approvals and host-readback model/thinking over RPC; Terminal is genuine installed native OMP, not a recreated transcript. The same WebviewPanel/slot survives transport replacement. A busy switch asks consent before abort/stop; idle switches are silent. The old exact root must exit before a successor starts on the best-known file. Default mode is only for new/opened tabs; ordinary reveal and restore preserve actual mode.
- Folder-shell Confirm should stop its exact native process tree, including a manually started OMP. The user declined the C++ toolchain needed to prove Windows prebuilt ConPTY descendants stopped: the current [ADR-0029 fallback](decisions/0029-report-uncontained-pty-tree-stop-as-unknown.md) attempts termination, reports `unknown` or observed `remaining`, and retains its recoverable slot. This explicitly **does not meet** the positive whole-tree-stop criterion. Separately, the user chose [verified exit of the owning VS Code main-process instance](decisions/0030-watch-the-verified-owning-vscode-process-for-shell-grace.md) as the trigger for a finite folder-shell-only cleanup attempt; closing one window, reloading the extension host or a generic broker signal is not authorization. An unattestable owning instance leaves automatic stopping disabled, not guessed.
- Folder-shell pages are panel-only, not chat-bridge members. After an extension-host-only restart, an unanswered visible-pane probe revokes input and names the folder's **Reconnect Terminal** action; it does not blame another editor. Reconnect attaches the same recorded broker/slot and reuses a reachable editor, or opens a fresh editor on that slot when the surviving page cannot be reached. The old dead page may be closed. Closing a host-less shell page cannot be intercepted and produces no confirmation prompt; the shell's durable slot remains recoverable after restart.
- **Open Terminal** intentionally creates a new folder shell, even if another survives in that folder, as specified by the terminal design. Use **Reconnect Terminal** to regain the existing shell, not Open Terminal. An uncertain Terminate keeps the broker and slot because the process tree could not be proven empty (ADR-0029).
- Sessions persist independently of open editors and folder navigation. Fresh verified broker/holder facts determine Running or Blocked; unknown rows are stopped/draft. Explicit Close/native exit record stopped intent. Automatic running-intent relaunch needs accepted absence evidence; explicit Resume follows ADR-0039 without an absence prerequisite. VS Code owns editor existence, SessionIndex owns exact conversation identity, and folder metadata never changes VS Code roots.
- A stopped single click is non-mutating: saved history in Chat or a stopped Terminal placeholder, including fileless drafts. A rapid second click or explicit Open starts. Ordinary Open/click on an already-open editor only reveals its actual mode; explicit mode actions switch it. Profile default applies to new/opened tabs, including folder New/Resume and discovered history. Restore/Reload retain verified actual transport, then saved slot mode, rather than applying a changed default to an existing editor.
- **Add editor context to a session:** select text or a file and use **OMP: Add Selection to Session** (Alt+Shift+K, editor menu) or **OMP: Add File to Session** (Explorer incl. multi-select, editor tab and editor menus) to put a *reference* — `@src/a.ts [lines 12-30]`, never the code — into a session's input, Chat or Terminal. The user always chooses the session in a picker (most recently focused first; stopped ones with an open editor start when chosen; a new session in the file's folder is always offered; choosing it adds that folder to the OMP folders when it is not listed yet, which the picker row and the status message say), blocked or other-window sessions are never offered, nothing is ever submitted, and the target is revealed, focused and named in the status bar. OMP has no line-range mention syntax, hence the note beside the `@path` ([design](designs/2026-10-07-add-editor-context-to-session.md)).
- **Ownership policy (user decision 2026-09-30, [ADR-0039](decisions/0039-refuse-only-on-a-verified-live-writer-the-extension-owns.md)):** block only a positively verified live writer this extension owns for this exact session. Unknown/unreachable/dead brokers, ambiguous PIDs, unresolved launches and stale/unverifiable/unreadable claims are unowned: Open/Resume/Delete/Forget/Rename are immediately available, on the user's responsibility, with ordinary exact-path Delete confirmation only. No stale-reservation state or release ceremony.
- Another verified-live extension-window holder shows **Open in another window**, with Stop available; Open and a click **switch to that window at once**, with no notification or confirmation, and select the session's tab there; they never launch. A message appears only when switching is impossible (the owning window has no saved workspace or single-folder identity, another window shows the same folder, it did not answer, or it no longer has the session open) and says why. Every window shows the holder's live status for that row (Working, Needs your answer, Idle, Unread reply), not just "in another window". The row updates live when that window opens or stops the session; a window that is simply closed does not release its claim, so the row is rechecked when this window regains focus or the row is clicked ([ADR-0045](decisions/0045-derive-window-folders-per-window-and-pin-with-identity-ids.md)). Local launch/stop show **Starting/Stopping**. An accepted native shutdown is irreversible and may be deferred by queued/background work; uncertainty about that accepted request keeps input fenced and never schedules a successor. `/restart` may lose control/bootstrap: explain native `/exit` or separately confirmed force Stop with tree-unknown warning, no automatic successor after uncontrolled force, and no successor over a positively observed survivor.
- A session an `omp` process this window does not run (most likely a plain terminal `omp`) is writing shows **Open in another OMP process** (detected through OMP's own session lease, checked read-only; [ADR-0046](decisions/0046-probe-omp-session-lease-for-external-writers.md)). It refuses nothing: Open, a click and every explicit launch that could start a writer ask **Open Anyway** / **Cancel** first, because OMP will then write to a new sibling file; this confirmation is the only addition to the ADR-0039 policy and applies only when that lease is actually observed. Restored editors and automatic relaunches do not consult it.
- **Folders in Sessions:** the folders VS Code has open in any window of the profile appear automatically in every window (every local root of a multi-root workspace), together with the folders you **pinned**, so every window shows the same sessions in the same order with the same status; selection, a row's available actions and the collapsed state of an unpinned folder stay per window. A window that closes drops its folders after a short, bounded delay (seconds, at most about 75 s if it hangs). **Pin Folder** keeps a folder after VS Code closes it and shows it in every window; **Unpin Folder** (the former Remove) drops it from the shared list (a running session never refuses it), and an open folder stays visible. **Add Folder** pins. The setting `omp.showWorkspaceFolders` (default on, applies to all windows) hides the automatic ones. A folder with a running session in any window never disappears. Pinning and unpinning change no VS Code folder, session or file.
- **Agent root folder:** when a folder VS Code has open has no agent files (`AGENTS.md`, `CLAUDE.md`, `.agents`, `.omp`, `.claude`, `.pi`) but lies inside a Git repository whose root (or a folder between) has them, Sessions shows that ancestor instead, so new sessions start where OMP finds them (a Unity project opened as `repo/Unity` shows `repo`). Its hover text says so. Sessions recorded in the opened subfolder stay listed under the ancestor. Folders outside a Git repository are never replaced. The setting `omp.useAgentRootFolder` (default on, applies to all windows) turns it off.
- **Sessions start where their folder is:** New Session, Resume Session and opening a stopped session of a folder that VS Code has open only in another window start in that window, which comes to the front with the session's tab (the most recently used one when several have it; a folder open here, or nowhere, starts here). A Unity project's sessions need a window with the Unity project folder as workspace root, so they start in one, or in a new window opened on the project; the session's working directory stays the repository's agent root. If the other window does not answer, a message says so and nothing is started. `omp.launchInFolderWindow` turns it off.
- Folder Resume lists readable exact history files once, with per-file Delete. Running rows offer ordinary reveal, explicit modes, Rename, Reload, Close and exact-path Delete. Lifecycle acts on the actual transport: RPC commands in Chat, guarded public SDK shutdown/name in Terminal, honest unsupported/unavailable control, and distinct force consent rather than pretending ConPTY close is graceful native disposal. Reload preserves mode/file; stopped rows may Open, Rename, Forget or Delete; fileless drafts have no transcript to delete.
- Explicit `native` transport is managed, not legacy. Historical records lacking a managed discriminator remain Running (legacy) when their exact broker child is verified. They are never silently migrated; unverified legacy records are ordinary usable stopped/draft rows. Any already-open managed tab is revealed without replacing its writer by ordinary Open.
- Explicit legacy Stop verifies the recorded child gone, shuts down its now-empty broker and immediately displays Stopped; the broker's recovery record is retained. Surviving folder shells of a previous build reconnect to their restored editors. Sessions activity follows dialog answers and turn transitions without Refresh; the footer queue chip follows OMP's own queue snapshots and delivery events.
- The chat has one compact footer below the composer: host-reported model and thinking pickers, context usage and abnormal statuses only. Empty thinking renders nothing; non-empty and redacted reasoning remain expandable. The header, notices history, settings/tool/configuration panels, usage totals and account quotas are removed by the [compact-footer design](designs/2026-10-01-compact-chat-footer.md). Native provider login is `OMP: Log In to Provider…` in the Command Palette and Sessions title overflow menu. The Agents Hub remains removed (ADR-0038).
- Native transcript parity uses VS Code theme variables, proportional prose and Codicons, not terminal frames or ANSI. AGENTS is above TODO above the transcript, both initially collapsed; only running registry members and existing tasks make their respective HUD visible. Expanded agents preserve native progress and lazy read-only child history; expanded todos preserve phases/status/blockers/details/notes. Completed and abandoned count as closed. Native messages/tools, grouped reads, summaries, provider errors/retries, TTSR, shell/Python and slash output remain readable. The bottom Tasks/Plan panel is removed; full recoverable history is the explicit compaction departure. Exact RPC-only limits are recorded in the [TUI-parity design](designs/2026-10-01-tui-parity-transcript.md).
- Windows **desktop** toasts, not VS Code information messages, announce a main session becoming idle (including a turn-stopping error, not user aborts/subagent completions) or blocking on structured user input. `omp.desktopNotifications` defaults to true. Consume each event once, including disabled/watched events; suppress only a focused window's exact active visible session editor. Show session title, folder name and a short reason/question first line, never hidden dialog payloads or errors. Chat observes RPC dialogs; native's reliable wait set is only built-in ask/tool approval in an active main TUI run, with exact limitations in the [desktop-notification design](designs/2026-10-03-windows-desktop-session-notifications.md). Windows notification policy and history/lock-screen privacy remain the user's OS settings.
- Where OMP exposes machine-readable capabilities or settings metadata, build UI from that information so new options do not routinely require extension UI changes. Where such metadata is absent, do not pretend a guessed control is supported.
- Exact-file leases exclude positively verified live extension-window holders, not unverified writers. Unusable claim storage/mutex permits a window-local lease without touching that namespace. OMP itself permits concurrent writers and rpc-ui exit appends `session_exit`; overlaps with unverified/external writers are the user's responsibility. Automatic activation still requires running intent and accepted absence evidence; explicit Resume does not. No process is stopped by a recorded PID alone.
- Discovered OMP history resumes from its exact file in the selected new-editor default or explicit mode under the same extension claim, regardless of provenance. A stopped file may be deleted with the same warning and exclusive transaction as other saved sessions. See [ADR-0018](decisions/0018-resume-imported-history-under-extension-claims.md), narrowly superseded by [ADR-0027](decisions/0027-delete-discovered-history-under-exclusive-extension-claim.md).
- Claude resources are **not ported** by this extension (user decision, 2026-09-24). Installed OMP already discovers and owns context files (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`), skills, plugins/extensions, MCP servers and agents through its own capability providers, and the extension neither reimplements that discovery nor ships a resource inventory or capability-endpoint UI. Any change to that boundary needs a new user decision. Language tools are **native OMP `lsp` only** in the current release, and the user reopened the VS Code language-provider bridge on 2026-09-24 as **planned future work** — see the [bridge design](designs/2026-09-24-vscode-language-provider-bridge.md), which stays historical and `rejected` for the implementation it once described. Nothing of it is implemented and no bridge source remains, and enabling it is gated on a revised security design that closes the three findings already recorded against that code — a shared mutable workspace root letting one native session read another session's editor data, out-of-root workspace-symbol content reaching normalized results, and removing a workspace folder not revoking an existing attachment — together with explicit consent and disclosure of the editor data a query would return, independent security review, and real-window acceptance. Claude resources remain excluded from both the current release and that planned work.
- **Read-only session inventory** (user decision, 2026-10-08) narrowly amends the no-inventory boundary above: the Tools view shows only skill commands and tools reported by the active or last-focused OMP editor. OMP still owns discovery; no directory scan, resource adapter, endpoint management or tool-selection mutation is added. Skill paths are unavailable from the installed RPC catalogue, so no Open SKILL.md action is inferred.
- **Native Models and Agents settings** (user decision, 2026-10-08) narrowly reopens settings editing for the native `/models` and `/agents` dashboards. Separate editor tabs use installed OMP discovery/configuration contracts, explicit profile/project scopes and safe direct writes; opening is read-only, while explicit Refresh/Generate disclose OMP-native credential effects. The old Collab-era Agents Hub roster remains removed. See the [accepted design](designs/2026-10-08-native-models-and-agents-settings.md).

The Collab GUI direction of [ADR-0002](decisions/0002-local-collab-gui-native-omp.md) is superseded by ADR-0038; the product assumes installed OMP and offers native provider login, not GUI onboarding. The 2026-10-08 Models/Agents decision is the narrow exception to the earlier no-settings-editor boundary. The accepted [development design](designs/2026-09-24-omp-vscode-development.md) and [ADR-0006](decisions/0006-host-generated-key-peer-verified-pipe.md) record surviving security and actual VS Code acceptance gates. Do not confuse source implementation or headless browser/CLI proof with a verified installed Webview.
