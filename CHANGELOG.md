# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Chat: fenced code blocks are coloured with the active VS Code colour theme and follow a theme change: TypeScript/JavaScript, JSON, Python, C#, C/C++, Go, Rust, Java, Kotlin, Swift, PHP, Ruby, Scala, Dart, Lua, R, Perl, Haskell, Elixir, Objective-C, Groovy/Gradle, SQL, PowerShell, Bash, Windows batch (`bat`/`cmd`), Dockerfile, Makefile, HCL/Terraform, Nginx, TOML/INI/`.properties`/`.editorconfig`, `.gitignore`/`.dockerignore`, GraphQL, Protocol Buffers, HTML/XML, CSS, Markdown, YAML and diff, under the usual ids and aliases (`ps1`, `yml`, `kt`, `rb`, `tf`, …). Copy still copies the plain text, and unknown languages (including `text`) and very large blocks stay plain. Inline code takes the theme's string colour on a faint tint of it, and a file, symbol or web link in or around inline code keeps that look (only a subtle underline marks it); High Contrast themes keep their own colours. The colours approximate the editor's: about 94 % of characters match in Dark Modern and 82 % to 85 % in the 2026 default themes for the first languages, about 82 % on average for the others ([ADR-0067](docs/decisions/0067-highlight-chat-code-with-highlightjs-and-host-resolved-theme-rules.md)).
- Chat: tool cards colour the code they show with the same theme colours, by the language of the file: the content of **Write** (also while it streams), **Read** and **Find** snippets, the lines of **Edit** and patch diffs (each line's code is coloured as the old or the new file, and the diff's signs, line numbers and added/removed backgrounds stay), the code of **Eval** cells, the match lines of **Grep**, and a **Bash** command in the card's header (as shell; a `python` command as Python). The language comes from the file name or extension (`Dockerfile`, `Makefile`, `.gitignore` and the fence languages' extensions); other files stay plain. Line numbers, wrapping, Copy and the expand controls are unchanged. Text over 10,000 characters or 400 lines is coloured only for the lines in view, up to those limits; in a diff, a construct that spans two hunks is cut between them.
- **OMP Desk: Reload All Windows** reloads every open VS Code window of the profile that runs OMP Desk, then the window you ran it from, so a newly installed build takes effect everywhere in one action. It is in the Command Palette and in the Sessions title's `…` menu, and asks nothing: running sessions survive a reload as they do after Reload Window. A window that does not answer within two seconds (a build from before this command, or a window that is not responding) is logged in the OMP Desk output and left as it is; reload it by hand.
- Chat: when a tab fails because its OMP process no longer serves the conversation ("The running OMP process is not serving this session file", or "The session identity changed inside the OMP process"), the banner offers **Restart**: after your confirmation it stops exactly that process and reopens the tab's own saved conversation, keeping your draft. Before, the banner had no action and the only way out was Kill and reopening the session from Sessions. The OMP Desk output now logs which session file and id OMP reported and which ones the tab expected.
- A status bar item shows your provider's usage limits for the active Chat, for example `5h 42% · 2h13m  │  7d 18% · 3d4h` (used percent and time left until each window resets, written like `4d4h42m`, each unit only when above zero). It turns yellow from 80 % and red from 95 %; its tooltip lists the exact reset times, and a click (or **OMP Desk: Refresh Provider Usage**) re-reads the limits. Right-click it to hide it.
- **Ctrl+Shift+N** in a Chat opens VS Code's Go to File with the text you selected in the Chat (or in the composer) already typed in, the way Ctrl+N does for symbols; with nothing selected it opens the empty Go to File. It is the command **OMP Desk: Go to File from Chat Selection**, and the key overrides your keymap's own Ctrl+Shift+N only inside a Chat.
- Chat: fenced ```` ```mermaid ```` blocks are drawn as diagrams (flowcharts, sequence, class, state, ER, gantt, pie and the other mermaid types) in the colours of your VS Code theme, once the block is complete and not while it is still streaming. A diagram that cannot be drawn (a syntax error, an unknown type, a source over 8,000 characters or 80 statements, or a block diagram) stays a code block with one muted line saying why. **Diagram | Source** switches the view, Copy copies the source, and a diagram wider than the block scales to it and opens at full size on click. Mermaid (about 3.5 MB, without the ELK layout and KaTeX math) is a separate script that the page loads only when a reply has a diagram; the diagram is shown as an SVG image, so nothing in a diagram can run script or reach the page.
- **OMP Desk: Log In to Provider…** now signs in inside VS Code instead of an `omp login` terminal: pick the provider from a list, the sign-in page opens in your browser, a pasted authorization code goes through a masked box, and Cancel ends the sign-in. Every open window of the profile re-reads its models when a sign-in, a log out or the fallback terminal login ends. Providers that take an API key are not entered in VS Code: choosing one (or **Other providers**) points to `omp` in a terminal and offers **Open Terminal Login**, which opens the old `omp login` terminal. The sign-in runs in a short-lived OMP process that, like any OMP, starts the MCP servers your profile and folder configure; Cancel ends that process and everything it started.
- **OMP Desk: Log Out of Provider…** removes a provider's stored account after a confirmation.
- **OMP Desk: Open OMP Settings** edits OMP's own settings, the ones its terminal `/settings` shows, in an editor tab laid out like VS Code's Settings editor: a table of contents of OMP's ten tabs and groups beside one list, search with filters (`@modified`, `@env`, `@warning`, `@tab:model`), and a **Global / Project / Effective** switch. Every change goes to the **global** layer (`config.yml` of the OMP profile) or the **project** layer (`.omp/config.yml` of a folder), with the value each layer holds, the value OMP uses and the layer it comes from, the environment variable that overrides a setting when one does, and **Reset** to remove a layer's value. Controls are switches, choices, numbers, text and lists; the 26 numbers OMP's own panel hides take a typed number that is checked before it is written. A setting OMP hides under a condition is hidden here too, search included. It opens from the Command Palette, from `/settings` in a Chat (which used to open Models) and from the Sessions title menu. Credentials are never read into the page (set them with `omp config set` in a terminal), and lists, mappings and settings whose choices OMP fills at run time open their YAML at the key instead. Changes are written under OMP's file lock and refuse when the file changed underneath; a settings schema this build does not recognise is refused with a clear message (no version number gates it; the page says when the installed OMP is not the 18.10.3 it was verified with). A project file that OMP merges over `.omp/config.yml` (`.claude/settings.json`) is named on the setting it overrides, and the first project write is refused, with the reason, when it would make OMP stop loading an ancestor folder's `AGENTS.md`, `RULES.md` or `SYSTEM.md` for that folder. OMP's running sessions reload config files when they change; settings it reads once at session start apply to new sessions.

### Changed (breaking)

- **Everything OMP Desk contributes moved from the `omp.` namespace, which is Oh My Pi's own, to `ompDesk.`, and the Command Palette category is now "OMP Desk" (it read "OMP").** Commands (`omp.newSession` → `ompDesk.newSession`, all 95), settings (`omp.chatColumn` → `ompDesk.chatColumn`, all 13), the side bar container and its views (`omp.sessions` → `ompDesk.sessions`, …), context keys (`omp.sessionMode` → `ompDesk.sessionMode`, …) and the `when` clauses and `workbench.view.extension.omp` reference that name them: replace the prefix `omp.` with `ompDesk.`. Unchanged: the names of OMP itself, the OMP Desk output channel and the stored sessions, folders and secrets (nothing recorded is renamed). What to do:
  - **Settings move by themselves** the first time this version starts: each `omp.*` value in your user settings, and in a workspace's settings wherever the setting can live there, is written to its `ompDesk.*` name (unless that name already has a value, which wins), then the old line is removed; the OMP Desk output has one line per move. A read-only workspace settings file is left as it is, with a line saying so. Values that were never applied stay where they are and are not touched: `[language]` overrides, a folder's settings in a multi-root workspace, and `toolCallDetail`, `showWorkspaceFolders`, `useAgentRootFolder`, `launchInFolderWindow`, `executablePath` and the three `agentDebugger` settings in a *workspace* (they apply in user settings only). A workspace's `.vscode/settings.json` may be committed; check `git status` after the first start. A machine that still runs 0.3.x and syncs these settings with Settings Sync loses the old keys once this one updates; update both. The old names stay in the manifest as hidden, deprecated settings (VS Code marks a leftover line in `settings.json`) until the first minor release published on or after 2027-04-13, so a profile or Settings Sync exclusion that named them keeps working, and the same migration then also moves a value that reappears. **Windows that were already open when the extension updated keep running 0.3.x until reloaded:** in such a window a moved setting reads its default until you Reload Window, and a value written meanwhile under the old name loses to the new one at the next start (the OMP Desk output records the dropped value). `settingsSync.ignoredSettings` and `workbench.settings.applyToAllProfiles` get the new name next to the old one.
  - **Your own keybindings keep working for now**: every command id that 0.3.2 published (all 92) still runs the new command with the same arguments, and the first use of each shows a warning with a button that opens `keybindings.json`. Rename `omp.<command>` to `ompDesk.<command>` there, and in `terminal.integrated.commandsToSkipShell`. `omp.sessionMode`, `omp.streaming` and `omp.composerPopupOpen` in a `when` clause are also still set. The old command ids and these three context keys stop working in the first minor release published on or after 2027-01-13 that is at least the second after this one.
  - **Does not keep working, change it now:** entries that *remove* a default binding (`"command": "-omp.focusComposer"`) match nothing any more, so the default key is back until you rename them to `-ompDesk.focusComposer`; every other `omp.*` context key in a `when` clause (`omp.catalogPending`, `omp.hasWorkspaceFolders`, `omp.sessionsLayout`, `omp.processesLoaded`, `omp.sessionTransitionPending`, `omp.defaultSessionMode`, `omp.<view>.scope`, `omp.context.canMaintain`) is never true; `config.omp.*` in a `when` clause tests an unknown setting; `settingsSync.ignoredSettings` entries naming `omp.*` settings no longer apply.
  - The OMP Desk views return to their default arrangement once (collapsed state, order, a side bar they were moved to), because VS Code stores that by view id. Open editors and running sessions are unaffected: the editors' own types did not change.

### Changed

- **Chat looks calmer and is easier to scan**, in Dark, Light and High Contrast themes. Secondary text and borders are derived from your theme (in Light Modern, muted text is now really dimmer than normal text); your messages sit in a tinted bubble; a tool row is one 26 px line with no success tick, a regular muted name, a workspace-relative path and coloured `+N −N` on edits, the operation and `done/total` on TODO calls, and `N agents: A, B` on Task and Agents rows instead of the sub-agent's prompt; tables and inline code are tidier and Copy under a reply is an icon. The composer toolbar is quiet text and icons with one pill **Send** button and one focus ring. An aborted reply is one muted line and a provider error one line; the working row has a spinner and a shimmer, both stopped when your system asks for reduced motion; the ask dialog has flat options and text **Cancel** and **Stop** buttons. An empty chat now shows the folder, the model, the key shortcuts and up to three recent sessions of that folder, which open as a click in Sessions does. The **Tools output** button is removed from the composer toolbar; the density stays the `ompDesk.toolCallDetail` setting (Overview or Detailed) in Settings.
- Chat: typing while the Chat page has the keyboard focus but nothing editable does (after a click on a tool row, a file link, a copy button or the transcript) now goes into the composer, and so does Ctrl+V / Shift+Insert. Before, those keys went nowhere until you clicked the composer again. Space, Enter, Tab, Escape, arrows and shortcuts keep their usual meaning, and nothing is redirected while the composer is disabled or read-only, an ask is open, or the Rewind picker is active.
- Internal structure: opening, restoring and re-attaching a session, launching or re-adopting its OMP process, stopping it to learn a verdict, Kill, the gated stop and replacement of a writer (stop, delete, new session in place, view switch, Restart), what follows a process that ended on its own (its exit, a lost broker, the identity its conversation reports, host control and the native Terminal's watch and handover) and the Chat conversation surface (pages, commands, view-only history, prompt history and Rewind reads, and the live session's facts and operations: footer reads, model and thinking choices, Compact, Shake, export, Share, rename, the Context view and Restart's guards, each named by an incarnation) now go through a `SessionRuntime` port in a new `src/runtime/` layer that may not refer to `vscode` (ADR-0066); the OMP path setting, the provider-login terminal and the terminal lookup moved to `host/omp-vscode.ts`. No behavior change.
- Durations are shown in whole seconds everywhere (Chat working row, reply footers, tool and agent rows, Sessions process uptime, the model list's first-token time, OMP Desk: Show Diagnostics): `12s`, not `12.3s`; under one second they stay in milliseconds.
- Reload Window restores a window's surviving sessions much faster. A session whose OMP process survived is re-adopted without any PowerShell identity probe when its broker is from this build (before: four per session, seconds each on a busy machine): the broker reports its own and its child's identity in its authenticated status. Older brokers and native Terminal children are still read through the kernel; proofs running at the same time share one reading. The broker state folder's access check starts at activation instead of in front of the first re-adopted session. The rows of a window are restored in parallel (four at a time) instead of one after another; the report, the one-writer-per-session rule and every ownership check are unchanged, and a failing row no longer delays the others.
- Reload Window restores sessions sooner on a busy machine, with every admission check unchanged. The check that the extension's private folders are limited to your account (it runs once before the first session is re-adopted, and again whenever the OMP helper is staged) now needs one PowerShell start instead of four (measured on an idle machine: 1.5–1.8 s → 0.4–0.5 s for the broker folder, 2.8–3.3 s → 1.0 s for staging the identity helper); and when Desk must read both a session's broker and its OMP process from Windows (a session started by an older build), it reads them at the same time instead of one after the other. A failed, slow or malformed read still refuses, as before. One consequence: when that single read fails as a whole, Desk no longer tightens folder permissions in the same pass (before, a failure of only the folder-permission read still allowed it); the folders stay refused until a later check succeeds.
- The OMP Desk output logs every PowerShell start behind a restore as one line, `tool spawn: <tool> <purpose> pid <pid> <ms> ms <outcome>` (for example `powershell broker state security read (9 paths) pid 1234 412 ms ok`), so a slow Reload Window can be traced to the start that was slow. A line never contains a path or any text a process printed.
- Reload Window leaves Sessions' own background reads until the restore is over, so they stop competing with it. While your sessions are being re-adopted, the Sessions rows' extra ownership checks (which read other sessions' processes and probe for a terminal OMP) and the Processes list's reads wait; a restored session's row shows Restoring and another row shows Checking until then, and every explicit action (a click, Open, Stop, Kill All, Refresh) still reads at once. Staging the OMP helpers verifies the private folders once instead of twice when nothing needs writing (a repeat of an already staged helper: 0.9–1.0 s → 0.4 s on an idle machine), and the broker folder's access check now starts the moment the extension starts, before the saved sessions are read. Every check is unchanged.
- The PTY runtime self-check result is remembered on disk per broker tree and executable, so a reload or another window reuses it instead of repeating the 4–13 s check (`PTY runtime proof reused from <time>: ready in N ms`). A stored proof expires after 24 hours, and one that a failed broker start contradicts is deleted, so the next launch runs the check again and reports what is wrong. Staging, byte verification and the access check still run every time.
- The OMP Desk output has one `window timing: restore tab …` line per restored session with the duration of each step (admission, reconcile, attach with connect and identity, launch, persist), a `restore pass` line, and a `startup restore timeline` line (activation → catalog adopted → restore started → restore finished).
- Reload Window with several windows at once makes one slow window much less likely to hold up the others' saving of sessions. On Windows a window that was busy in the middle of reading the shared session record kept the file open and made every other window's save wait or fail ("The editor mode could not be recorded durably"); a reload of three windows once left one window restoring for a minute with almost nothing to do. The shared record is now read in a single step that a busy window cannot interrupt, a saving window reads the record once after saving instead of twice, only changes to the record itself (not the temporary file of a save in progress) wake the other windows, and a burst of such wake-ups is answered by one refresh at a time instead of a dozen in parallel. Saving stays durable and every merge and ownership rule is unchanged. A window that is itself stalled while it is saving still delays the others for that long.
- A machine that is too busy for the session-ownership probe (a PowerShell start that times out after 5 s) is probed less and less often while it keeps failing: 15 s, 30 s, 1 min, doubling up to 5 min, instead of the same doomed start every half minute in every window; the first probe that answers resets it. Rows show their ordinary state meanwhile, as before, and a click still probes at once.
- Sessions: rows are sorted alphabetically by folder, then by session title (case-insensitive, numbers in numeric order: "Task 9" before "Task 10"), instead of by unread mark and last activity. Running sessions still come first and closed ones after them, each group in the same order. In the folders layout the rows inside each folder follow the same order.
- The shipped bundles (`out/extension.js`, `media/guest.js` and the others) are minified; the extension host parses the first at every window start and a session editor the second when it opens, and both were about twice the size (2.1 MB and 2.0 MB, now 1.1 MB each). The watch build (`npm run watch`) stays readable.
- The OMP Desk output logs how long the PTY broker's health check took on the first launch in a window (`PTY runtime proved itself: self-check N ms, ready in M ms`): the check's own run, and the whole proof including the staging of the broker tree. An unproven admission and the repeated check log their times too. The numbers are the basis for deciding whether one proof should be shared by every window.
- Internal structure: every writer that replaces a file now goes through `src/host/atomic-file.ts` (one exclusive `<file>.<pid>.<uuid>.tmp` staging entry, removed on every exit, and one retry loop for Windows sharing violations with two named budgets, unchanged in length), and the hard-link publishers of the runtime copies and the PTY records stage through the same module; the separate `file-operation-retry.ts` is gone. Temporary files of the session claims, bridge records, control rendezvous and native evidence are now named `*.tmp`, not `*.staged`.
- Internal structure: `src/` is divided into layers (`shared`, `chat`, `protocol`, `host`/`broker`/`omp`, `views`, `webview`, `wiring`) with one import direction, checked by `scripts/check-imports.mjs` inside `npm run typecheck`; the host and broker no longer import page code, the page no longer imports host code, the message contracts live in `src/protocol/`, and five import cycles were removed. No behavior change.
- Internal structure: `src/host/session-index.ts` is split into four modules: `session-model.ts` (the row and host types and the predicates that only inspect them), `session-files.ts` (the session-file header and activity readers and the working-directory and identity helpers), `session-availability.ts` (the ownership-verdict contracts and the availability policy) and `session-index.ts` (the `SessionIndex` class and the catalog internals). Every importer names the module that defines what it uses; `session-index.ts` re-exports nothing. No behavior change.
- Internal structure: the extension host's roughly 100 mutable module bindings (the maps, sets, handles and counters of one window) are now the fields of one `WindowState` object, grouped by concern, that `activate` creates and installs first; `src/extension.ts` keeps a single `let` (the installed state) and functions read it through `windowState()`. The lifecycle test installs a fresh state per case instead of assigning module bindings. No behavior change.
- Internal structure: five regions of `src/extension.ts` moved, function bodies unchanged, into wiring modules with explicit dependencies and their own tests: `src/wiring/window-routing.ts`, `session-actions.ts`, `guest-dispatcher.ts`, `editor-panels.ts` and `bridge-host.ts`. `extension.ts` shrinks from about 14,800 to about 11,400 lines, and the lifecycle test no longer replaces internal functions to fake the panel factory, the bridge endpoint or the broker provenance. No behavior change.
- Chat: `Esc` `Esc` opens Rewind when the focus is anywhere on the Chat page, not only in the composer: on the transcript, a tool row, a link or copy button, or the page itself. The same conditions apply as in the composer (no turn running, empty draft, no popup open), a single `Esc` keeps closing a popup or stopping a turn, and `Esc` in another text field (a search box, a rename field) is not counted.

### Fixed

- Test environments (contributors): `scripts/test-vscode.ps1` now says so when VS Code is waiting to install an update, instead of starting a window that exits after 30 s with no window and no log (VS Code holds off every new start while its update installer runs); `-VsCodeDir` starts another VS Code install.
- Agent debugger: breakpoints the agent set stay the agent's after Reload Window. Desk kept who owns each breakpoint only in memory, so after the window's extension host restarted (VS Code keeps the breakpoints and their ids) the agent's own breakpoints were listed as `owner: user` and `vscode_debug_breakpoints clear` left them behind. The owner records are now saved in the workspace state and read back. A breakpoint you delete and set again at the same place is a new breakpoint and stays yours: it is never handed to the agent. Ending a debug session (for example when Unity reloads its domain) never changes an owner. `vscode_debug_handoff` now lists the breakpoints that passed to you and tells the agent to remove the ones it does not want to leave behind before it hands off; the breakpoint list explains each owner, and a refused removal says who owns the breakpoint and asks the agent to leave it to you.
- **The first start after an update no longer waits ten seconds for the settings move.** The move of the old `omp.*` settings to `ompDesk.*` held activation for up to 10 s in each window, and three windows starting together each rewrote the same `settings.json` key by key. Activation now does not wait: a start with nothing to move (every start after the first) reads the settings once and writes nothing, and a start with work moves the keys concurrently in the background, with one window of the profile moving the user settings while the others wait for it. The first launch of a session still waits (at most 10 s from activation) so it never reads a half-moved `omp.executablePath`. Measured with all 13 keys seeded: activation → catalog 1583 ms before, 126 ms after.
- **When VS Code's updater ends your running sessions, OMP Desk now says so.** **Restart to Update** makes VS Code's installer stop every `Code.exe` of the install after waiting 30 s, and the processes that keep sessions alive between windows run as `Code.exe`, so their OMP processes end with them and the sessions are resumed from their files instead of re-adopted (a turn in progress and its sub-agents are lost). This cannot be avoided from an extension; OMP Desk now reads the updater's log, and when it names one of its processes it logs the pids and shows one notice. README states the limit.
- Chat: the result of Shake or Compact (for example "Shook 12 tool results") no longer appears and then disappears when Chat re-reads the session file straight after it. A result row belongs to the last message it followed; when the re-read does not hold that message yet, the row now stays under the nearest earlier message instead of being dropped with it.
- Chat: long lines wrap instead of making the whole transcript scroll sideways. A long inline-code path, file or symbol link, web link, URL or unbroken word in a reply, list item, heading or quote broke the line in no place, so the transcript grew a horizontal scrollbar above the composer and cut the line off; they now wrap at the edge of the text, and the link colours, underline marks, Copy and expand controls are unchanged. A long path or URL in inline code or link text wraps after a `/` or `\` (and, inside a segment longer than 20 characters, after `.`, `_` or `-`) instead of in the middle of a word; copying and selecting it give the same text as before. A wide table now scrolls inside a block of its own (as a fenced code block and a diagram already did) instead of widening the transcript, and the transcript itself never scrolls sideways.
- Chat: while only a background job (for example a `git push` started in the background) keeps a turn open, the working row no longer keeps showing the last tool's wording and the whole turn's timer, which looked like a hang after an hour. It says "Waiting for background job: <name>" (or "Waiting for N background jobs", or "Waiting for background work" when no job can be named) and times how long the wait has lasted; when the agent works again the row returns to its normal wording and timer. OMP reports only that background work is pending, so the job names come from the transcript.
- Chat: `/clear` typed right after an aborted turn is no longer refused as "wait for the current response to finish" while nothing is streaming. A refusal now says why: a response is streaming, OMP is still finishing the interrupted turn, a message is waiting in OMP's queue, a dialog is open, or a sent message is not confirmed yet. When the reason is only that OMP is finishing the interrupted turn, has a queued message, or has not confirmed a sent message, Chat shows "/clear will run when OMP finishes the interrupted turn." (and says what it waits for), and runs the clear as soon as OMP is ready. Sending a message, starting another command, the session stopping, or 60 seconds without readiness cancels it (the last shows the precise refusal); a second `/clear` does not double it.
- Chat: a fast reply (a model streaming hundreds of tokens per second) no longer makes the page spend most of its time reparsing. OMP sends one `message_update` per token chunk, each carrying the whole partial message, and the page validated, reduced and rendered every one; the host now passes on at most one per message every 33 ms (the latest wins, order is kept, a pause flushes on the next turn), and the Markdown of a reply that streams in parses only the block the new text touches, keeping every earlier block's element (a 20 KB reply rendered at 400 growth steps: 562 ms of parsing became 16 ms).
- Activation no longer waits for the window's own process start time. The reading is a PowerShell command (hundreds of milliseconds idle, seconds on a busy machine) and `activate` awaited it before registering the Sessions view, the commands and the editors; now only a session claim this window writes waits for it (the start-time rule of ADR-0035 is kept), and everything else appears at once. The installed Nerd Font list, another PowerShell command (it loads System.Drawing, a second or more of CPU), is read when the first terminal pane asks for its font instead of at every activation, for panes most windows never open.
- Sessions: the 15 s heartbeat no longer opens and parses every session file's header. Each header is re-read only when the file's modification time or size changed (one `fstat` otherwise; a title OMP rewrites in place changes the time), and the reads that complete together repaint the view once rather than once per file.
- Close, Stop and Reload of a session whose OMP process had already ended (killed from another window or Task Manager, or crashed together with its background process) no longer fail with "could not be confirmed stopped" and offer a Force Stop that has nothing to stop. When the stop cannot be confirmed, Desk checks the recorded OMP process itself (its id no longer in use, or now another process's) and, when it is gone, closes the session normally. A window still on a build from before Kill existed does not notice such a kill by itself; reload it.
- Sessions: a session whose first prompt could not be read once (the file was busy) keeps trying on later refreshes instead of showing the fallback title until the file changes, and an error while repainting the view no longer stops every later refresh of the window.
- The profile catalog's commit now stages its new revision exclusively and privately, like every other atomic write.
- Chat: a path in inline code that is only the end of a path in the project, such as `host/session-index.ts:579` or `shared/code-symbols.ts`, is now a link to the file VS Code's file search finds, like a bare file name already was: one file links to it at the line, several files link to the pick list. Such a path was only checked against the working folder, so it stayed plain whatever the file search knew. Paths written from a fixed place (`./`, `../`, a drive, `~` or a leading slash) are not looked up this way, and `files.exclude` and `search.exclude` still hide files, so in a Unity project whose settings hide `*.meta`, `*.asset`, `*.prefab`, `*.unity` and `*.mat` those names stay plain.
- Chat: file names and path ends in inline code linked far less often while files were being written in the project (an agent running tests, Unity importing assets): every changed file anywhere dropped the lookups under way, Chat asked again after 5 s and 20 s, and a large repository's search takes seconds, so a name such as `WorldStateSnapshotTests.cs` stayed plain for a minute. A changed or saved file no longer discards file lookups at all (it cannot change which files exist), and a lookup running while files are created, deleted or renamed now answers with the files it found that still exist.

## [0.3.2] - 2026-10-12

### Added

- **End-to-end tests (contributors).** `npm run test:e2e` drives a real VS Code with the extension on the hidden desktop of `scripts/test-vscode.ps1` through Playwright over CDP, with a local mock model and no provider key: other-window rows, Kill then resume, `/context` rendering and latency budgets, with a foreground watchdog and a guard on your real OMP and VS Code settings. See CONTRIBUTING.md and ADR-0064.
- **`omp.executablePath` names the OMP to run.** Set an absolute path (the `omp` program, or a Bun-installed `omp.exe`) in your user settings and Desk uses that OMP only: it is checked like any `omp` on PATH, and when it cannot be used Desk says why and does not look at PATH. The setting is machine-scoped, so a workspace cannot set it, and it applies to sessions started, resumed or read afterwards. Its row in the Settings view has a **Test** button that resolves what you typed (empty: the OMP on PATH) and shows the file, its release and how it was found, or the exact failure, without saving anything. See ADR-0011 (amended).
- **A Settings view in the OMP Desk side bar** lists every OMP Desk setting and changes it in place: a toggle for each on/off setting, a dropdown (with the option descriptions) for each choice, and a validated field for numbers and text; settings that are lists or objects open `settings.json` at the key. Each row shows where the value in effect comes from (default, user or workspace), has a Reset button that restores the default, and an **Open in Settings editor** button; a search box filters the list and the view follows changes made anywhere else (the Settings editor, `settings.json`, another window, the Chat footer's Tools picker). Changes are saved to your user settings; a setting that your workspace already overrides is saved there, and where the setting's scope allows it you can choose Workspace on its row. The list comes from the extension's own settings schema, so a setting added later appears by itself ([design](docs/designs/2026-10-12-settings-view.md), [ADR-0062](docs/decisions/0062-render-the-settings-view-from-the-contributed-schema-in-a-webview-view.md)).
- **Context view** in the OMP Desk side bar: shows the selected Chat session's context — model and window usage with the Chat footer's numbers and thresholds, messages and billed tokens of the retained context, auto-compaction state, session cost, compaction count and last compaction, the last `/clear` boundary, and the AGENTS/rule files OMP put in the prompt (click to open). A **Read Breakdown** action runs OMP's own `/context` in the conversation (its report also appears in the Chat) and lists OMP's categories with the time it was read; Compact and Shake from the view title or the Used row reuse the Chat's flow. Reads happen only while the view is visible and send no prompt; the breakdown is never read automatically ([ADR-0063](docs/decisions/0063-read-the-context-breakdown-from-omps-own-context-report-and-files-from-the-system-prompt.md)).
- **Kill in Sessions.** The context menu of a session row (and of a process row in the Terminals group) offers **Kill**: it ends the session's whole process tree (the broker, OMP and everything it started) at once, without asking OMP and without looking at whether the session is busy, who holds it or what claims it. The one check it keeps is that the process is still the one Desk recorded (id and creation time), so it never ends a stranger. Desk then updates its own records as it does after an unexpected exit, so the row shows the session stopped and it can be resumed; the window that has the session open shows it ended. A failure is shown in a notification and logged. See ADR-0060 (amended).

### Fixed

- Starting a session no longer fails on a busy machine because the PTY broker's health check was slow. The check runs the staged broker's console child and pipe child once per window before the first launch; with the CPU saturated it took up to 14 s against 4 s idle and a phase that missed its 15 s deadline refused the launch (`the runtime self-check failed with exit code 7: the pipe child did not finish within the self-check deadline`). A check that only ran out of time, with nothing observed to be wrong, is now inconclusive: the session starts and a repeated check with a 90 s deadline settles it in the background (the OMP Desk output logs `PTY runtime admitted unproven` and the outcome). A check that observed a fault (an addon that does not load, a child that cannot start, a nonzero exit, a wrong echo) still refuses the launch at once, and so does one that still delivers nothing after the 90 s window; launches in the next minute get that refusal. See ADR-0032 (amended).
- Skills, Tools, MCP and Extensions: the `List may be incomplete: some sources failed to load` banner now says which source failed and why (for example `[MCP Config] Failed to parse JSON in D:\project\.mcp.json`); it names the provider and, where OMP names one, the local file, never a plugin id, URL or error text, shows at most two and the OMP Desk output lists every one. An MCP server that OMP's discovery drops because another server has the same command or URL is shown `shadowed by <that server>` instead of the vague `shadowed by a higher-priority item of the same name`, and a lower definition of a name that a higher-priority file also defines is listed in the row's tooltip as `shadowed by <the file that owns the name>`.
- Chat: a long session (tens of MB of session file) reopened in a window, after a reload or from another window, no longer stays disconnected while Sessions shows it Running. Its catch-up answer (`get_entries`, sent by OMP as a train of 1 MiB chunks) pushed the earlier answers out of the broker's 4 MiB line ring before the paced replay reached them, so the broker disconnected the Chat as "fallen behind the retained lines" on every attempt, every 30 s. Answers to an attached client now wait under their own 128 MiB budget until it has read them. Sessions started before this update keep the old broker until they are restarted.
- Stop and close of a Chat whose connection the broker had already closed no longer fail with "The session could not be confirmed stopped": the stop now opens a fresh, identity-checked connection to the same broker instead of using the closed one.
- Context view: a Chat that is running a long turn no longer shows only the live groups. The deep read (the "This context window" statistics, the Auto-compaction row, the Session file and Context files groups) used to wait for the end of the turn, so a read made when the view opened was dropped by any compaction pass or epoch change inside the turn and nothing asked again until the turn ended; it now runs at attach and after such a change while the turn goes on (never during a compaction or a pass; once one exists, automatic refreshes still wait for idle). A read the session could not answer yet (not live, refused, timed out) is logged and retried at the session's next phase change or snapshot instead of staying empty. See ADR-0063 (amended).
- Launching on a busy machine no longer silently starts an older OMP. When the `omp --version` probe of the OMP your PATH selects does not finish in time (it timed out at 15 s under CPU load, and Desk then used a stale compiled `omp.exe` later on PATH), or Desk could not start or read it right now (out of handles or memory, the file busy), the launch, the Terminal, the CLI reads and the stopped-session rename now stop with a message naming that OMP and the cause and never fall back to another one; try again once the machine is less busy. The Skills, Tools, MCP and Extensions views do the same on their first read and keep showing what they already had when a later read hits it. A launcher that is plainly not OMP (missing file, foreign launcher, a probe that exits with an error) is still skipped in favour of the next one on PATH. Settings, the rename and the inventory read the package source of the OMP Desk resolved (the package that holds its entry script) and no longer borrow another install's from a global Bun or npm folder. When PATH offers two different OMP installs, the OMP Desk output logs both paths and releases once per window. See ADR-0011 (amended).
- Skills, Tools, MCP and Extensions: a refresh no longer fails with "a compiled-only OMP install cannot supply it" on a busy machine. Finding Bun and OMP's package source repeated the full OMP launcher resolution (an `omp --version` probe that can run past its limit under load and then fall through to a second, compiled `omp.exe` that has no package source) on every read; the answer is now resolved once, shared by concurrent reads and kept when a later resolution fails because the machine was busy, and when nothing can be found the message names the launcher Desk resolved or the missing Bun instead of blaming a compiled install.
- MCP view: a server that one file defines and another file only switches off (a project's `.mcp.json` with servers and `.omp/mcp.json` with `{"unity": {"enabled": false}}`) is one row, not two. The row shows the definition's transport and command or URL and says `disabled by mcp.json`, its tooltip lists every contributing file and what each does, it is no longer called `shadowed`, no switch is offered where a by-name project entry keeps it off, and the banner `List may be incomplete: some sources failed to load` no longer appears for such an entry.
- Skills, Tools, MCP and Extensions lists no longer take 10 s or more to appear. Opening the views one after another started one Bun worker run per view (each importing OMP's modules, 1.5 to 1.9 s idle and several times that on a busy machine) and re-resolved Bun, the OMP package and the worker's hash every time; now one read is shared by every view, a read less than five seconds old is reused, an older one is shown at once marked `refreshing…` while a fresh one runs, and the OMP Desk output logs each read's duration.
- Sessions: a row another window runs keeps its ⧉ mark and the status that window publishes on a busy machine, and a click on it switches to that window at once. The holder is now found in the window registry (a current lease and a live process) instead of a PowerShell start-time reading that timed out after 5 s and made the row look like an ordinary Running row.
- Sessions: a failed session lease probe is no longer retried at once by every row observation (up to three 5 s PowerShell attempts in a row, repeating for as long as the machine was busy); it answers unknown for 15 s first.
- Sessions: a row another window runs is no longer left highlighted as the selected session. Clicking it switches to that window and VS Code selects the row; the selection stayed there after you came back, so the view showed another window's session as this window's, while the Chat tab in front was a different one. The selection now returns to this window's own session when the switch ends, when the window regains focus and on any later refresh, and a row you picked here is left alone.
- The extension host no longer freezes for seconds on a busy machine (a Sessions title-bar button such as **Sessions Layout** took seconds to react, and VS Code reported "Extension host is unresponsive" with OMP Desk as the cause). The window's own start time and every launch/stop/delete check of another window's holder were synchronous PowerShell commands (measured 0.2 s idle, 5 to 17 s under CPU load), and every catalog commit, lock, read and refresh was synchronous file I/O with an `fsync` and up to 2 s of sleeping rename retries; all now run off the host thread, and activation waits for them instead of blocking every extension. A new always-on monitor logs `event loop blocked for N ms` to the OMP Desk output with the Desk operations (commands, catalog adoption, Sessions refresh) that overlapped the stall and the process's CPU time, so a stall of Desk's or of someone else's can be told apart.
- The shared session catalog no longer grows without bound: its conflict ledger (one record each time two windows changed one session row at once, each holding both whole rows) had reached 613 KB on a real profile, and every window parsed, rewrote and fsynced it on every change. It now keeps the newest three records per disagreement with a count of the dropped ones, and an oversized ledger shrinks the next time any window saves a change. See ADR-0034 (amended).
- Chat: terminal styling in native output is drawn instead of shown as raw text. OMP's `/context` report (typed or sent by the Context view's **Read Breakdown**) listed fragments such as `[38;2;107;114;128m░░░░[39m` because the escape byte was dropped and the rest of each sequence printed; the colored bars now render in the theme's terminal colors. Bash tool previews, bash executions and extension widgets use the same renderer; every other escape sequence (cursor moves, titles, hyperlinks — link text stays) is removed whole, and the copied text is plain.

## [0.3.1] - 2026-10-12

### Added
- **Skills, Tools, MCP and Extensions views** replace the single Tools view. Each lists items with their origin (Global, Project, Managed or another ecosystem), opens the item's source file on click (a skill's `SKILL.md`), and has a Session | Global scope button: the active session's inventory by default, the global one when no session is active or when you choose it. Checkboxes enable or disable skills, tools, MCP servers, extension modules and plugins **globally** in OMP's own user configuration (never a project file; comments in `config.yml` are not preserved, as with OMP's own saves); the notice says whether a running session may apply the change live or needs a restart. MCP shows configuration and name-matched tools, never a connection state.
- **`/clear`, `/new`, `/delete` and `/fresh` work in Chat.** `/clear` clears the model's context in place: the same session, file, tab and model stay, OMP's provider session is rotated, and Chat folds the earlier history behind a **Context cleared** marker (Rewind stops at it). If a clear does not finish, Chat says so and keeps the earlier history visible. Some runtime state that OMP's terminal `/clear` resets may carry over, such as cached capabilities and advisor costs. `/fresh` rotates the provider session and keeps the history. `/new` opens a new session in the same folder and column; `/delete` runs Delete Session with its confirmation, then opens a new session ([ADR-0059](docs/decisions/0059-clear-chat-in-place-through-a-desk-registered-omp-command.md)).
- **Agent debugger tools.** Chat sessions get `vscode_debug_*` tools that drive VS Code's own debug sessions (set breakpoints, start a launch configuration, wait for a stop, read stack and variables, step, hand the paused program to you). Starting a configuration and running expressions ask for your confirmation by default (`omp.agentDebugger.start`, `omp.agentDebugger.expressions`); **Always Allow** in the confirmation switches that setting to `allow` so you are not asked again. `omp.agentDebugger.enabled` turns the tools off. Main session only; sessions started by an earlier Desk build must be restarted. They are the first user of a new host tool channel ([ADR-0055](docs/decisions/0055-expose-vscode-capabilities-as-rpc-host-tools-run-by-the-owning-window.md)): the broker keeps an unanswered tool call until its result is written or OMP cancels it, only the window that holds the session's input executes and answers calls, and every call OMP does not cancel gets exactly one result, even after a reload, a lost connection or a takeover.
- **Attach the agent debugger to Unity.** The agent debugger offers an Attach to Unity Editor preset (`vstuc`) when the Microsoft Unity extension is installed; verified live against Unity 6000.3 Editors, normal and batchmode (`-batchmode -debugCodeOptimization`): attach, breakpoint, stack, locals, evaluate, step, handoff. The Editor needs Debug code optimization (a headless Editor needs `-debugCodeOptimization`), and the reproduction must not block on the paused thread, so start tests asynchronously and then wait for the stop.
- **Agent debugger reads and failures are clearer.** `vscode_debug_inspect what=stack` now honours `levels` (default 20) and `startFrame` even when the adapter returns the whole stack (the Unity adapter does), and says how to page. A session that ends, or whose adapter connection fails, reports the last adapter error (for example `write EPIPE`) in `vscode_debug_wait` and `vscode_debug_configs`. A control result says the next stop has a higher generation than the one it names, not necessarily the next number.
- **A bare file name in inline code is a link.** `session-index.ts:849` in a Chat reply opens that file at the line when VS Code's file search finds exactly one file of that name in the session's folders (a file in the working folder wins); several matches link to a pick list. Search exclusions apply, and the lookup is bounded and never delays the reply.

### Changed

- Ctrl+Shift+L focuses the chat composer from anywhere, replacing Ctrl+Shift+Q; it takes over VS Code's Select All Occurrences of Find Match key, which you can rebind.
- The notice shown in a chat or terminal tab, and in the warning, after OMP Desk was updated while the window was open is one sentence, "OMP Desk was updated. Reload the window to continue.", and the tab has a **Reload Window** button.
- **The Processes view is part of Sessions.** A running session says `Process: running` in its tooltip. Terminals and processes that no listed session stands for are in a **Terminals** group after the sessions, and the new **Terminals** layout (third Sessions layout, next to the flat list and folders) lists every background process with its folder; a click opens its session or terminal. **Stop Orphaned and Idle** and **Kill All** are Sessions title buttons. Kill All stops what this window runs through its own stop lifecycle and, if you choose *Stop in All Windows*, asks each other open OMP Desk window to stop its own sessions and terminals the same way, then reports one result per process. Processes no window runs, and those of a window that never takes the request up or is gone, are stopped through their authenticated broker and reported as stopped without their window; no process id is signalled and nothing is force-stopped without a prompt. A window asked to stop its own processes never prompts or forces, and a stop another window reports is counted only once its background process is confirmed gone. A window that took a stop request up and went quiet is left alone until its process is proven gone, and nothing owned by another window is stopped while the window list cannot be read. A notification for a session that has since ended no longer does nothing in the Terminals layout: it switches to your last session list layout and shows the session. **New Session** and **Resume Session** are no longer title buttons; their rows in the list stay. The Processes view and `omp.processes` are removed ([design](docs/designs/2026-10-11-sessions-unify-processes.md), [ADR-0060](docs/decisions/0060-merge-background-processes-into-sessions-and-kill-all-through-authenticated-routes.md)).
- Processes are read only while Sessions is visible (every 5 s in the Terminals layout, every 30 s otherwise), and a verified process identity is trusted for 60 s rather than a number of ticks.
- **The Sessions layout is chosen with one title button** that opens a picker of Flat List, By Folder and Terminals (the current one marked); its icon shows the current layout. It replaces the buttons for the two layouts the view was not showing. In the flat list and the folders layout the **Terminals** group is the last row, after the sessions (or folders) and the New Session… and Resume Session… rows, set off by a blank row.
- **Skills, Tools, MCP and Extensions views are quieter.** The permanent explanatory paragraph above each list is gone: one short line appears only when the list is incomplete, the project overrides the global list, the session is not running or the inventory could not be read. Standing notes (no MCP connection status, providers disabled in OMP, unlisted project plugins, unreadable session tool list) are in a folded "About this list" row at the end; rows show state compactly, with details in the tooltip.

### Fixed

- **OMP: Open Terminal in Folder** and **OMP: Reconnect Terminal** run from the Command Palette ask which folder to use, as New Session does, instead of warning "Choose a registered OMP folder".
- **A checkbox switch in the Skills, Tools, MCP or Extensions views is traceable and can be undone.** Tab from such a view's list reaches each row's checkbox, and Space or Enter on it switches the row at once (a click on a row's label or icon only opens its source and never switches). Disabling now shows its notice with an **Undo** button that switches the row back on. OMP Desk writes every switch to its output: the request (view, item, enabled→disabled, the list shown, the profile) and the outcome (what was written to which file, already as requested, or the refusal), and every failed read. Before, a change to `config.yml` from those views left no trace to tell it from an edit by anything else.
- Clicking into the Chat composer of a window that did not have the focus no longer leaves the composer without it. VS Code refocuses a webview editor when its window gains the focus, which cleared the focus the click had just given to the composer (or to whichever element in the page you clicked); the page now puts it back, only when the loss is that refocus and not you moving away.
- The Chat composer keeps the keyboard focus while the session is re-attached under you. A session whose connection drops or goes silent, or whose state is rebuilt, is "resyncing" for a moment, and the composer is disabled for that moment; a disabled field cannot hold the focus and the browser does not give it back, so the composer could lose focus at a moment you did not choose and typing went nowhere. The composer now takes the focus back when it is writable again, unless you moved elsewhere in the meantime. A composer that loses focus without a click, Tab or Escape is now written to the OMP Desk output as `tab …: focus: …`, with what the page saw just before and the function that called `focus()` or `blur()`, so a future report can be attributed.
- In the Chat composer, Up and Down recall prompt history only when the caret is already on the first or last visual row. A soft-wrapped paragraph used to count as one line, so Up anywhere inside it replaced the text with an older prompt; now the arrows move the caret through the wrapped rows first.
- A C# member named with its class in Chat (`SessionIndex.Reload`, `Outer.Inner.Member`, `Box<T>.Put`) is a link again when its class has exactly one such member. The C# language server describes a member's class as `in SessionIndex (project omp-vscode (net8.0))` (translated in a non-English VS Code), which the class match did not understand.
- `/clear` (and Rewind) in a chat whose OMP process was started by an earlier OMP Desk build no longer says "not supported by this OMP version"; it says the process predates the command and the session needs a restart.
- `Esc` in a VS Code list with search (a model picker, the Command Palette) opened over a working Chat only closes that list; it no longer also stops the turn.
- A Shake or other maintenance result row in Chat no longer vanishes when OMP reports it while the next reply is already streaming. OMP's automatic shake (and the other automatic passes) report their outcome, for example "Shake failed: Auto-shake reclaimed ~N tokens but context is still above the threshold", at that moment; the re-read of the session file that follows every such report dropped the row because it was attached to the reply still being written.

## [0.3.0] - 2026-10-11

### Added

- Folder paths in Chat are links too. A click opens a file in a tab; **Ctrl+Click** selects the file or folder in the Explorer without opening it, and **Ctrl+Shift+Click** opens its folder in File Explorer with it selected. A plain click on a folder selects it in the Explorer. The Explorer can show only paths inside a folder open in the window. The same three actions are in the link's right-click menu, and a web link's right-click menu offers **Open in Editor** and **Open in Browser**.
- In Chat sessions the model is asked to write the files and folders it mentions as paths in inline code (`src/app.ts:42`, `docs/`), so they become links, and to link every code symbol it names, at each mention and in tables and lists, to the definition line it has seen (`` [`World.Current`](src/World.cs:42) ``) or to the file alone, so a click opens the definition.
- **Code symbols in Chat replies are links when VS Code can tell where they are defined.** An inline code span such as `Session`, `SessionData.Cast()`, `SessionStoreBase<T>` or `[Tracked]` in an assistant reply becomes a link, with the same underlined look, click and `Ctrl+Click` as a file path, when VS Code's language extensions (C# Dev Kit, TypeScript and others) report exactly one definition of it inside the session's folders; a click opens the file at the definition. A partial class or an overloaded method links to one of its declarations (the type's own file, else the first); a symbol with several different definitions (same-named types in different namespaces) is a link with a dotted underline and the tooltip "N definitions — click to choose" that opens VS Code's workspace symbol search for its name, never a guessed definition; unknown symbols and code blocks stay plain. Each lookup is logged in the OMP Desk output (counts and verdict). Symbols in bold, italic and strike-through text count too. While a language server is still loading its projects, or when its queue is full, symbols stay plain code and are linked as soon as it answers, without reloading the window. It is asynchronous, bounded and cached, and never delays a streaming reply. Language servers rank and may cap workspace symbol results, and a server that has not loaded the workspace yet answers nothing, so a symbol can be missed. Turn it off with `omp.linkCodeSymbols`.
- **A bare file name in a Chat reply is a link when VS Code can find the file.** An inline code span such as `session-index.ts:849`, `session-index.ts(849)` or `index.ts` in an assistant reply becomes a link, like a path, when VS Code's file search finds exactly one file of that name in the session's folders; a click opens it at the line. The file in the session's own folder wins, `files.exclude` and `search.exclude` are honoured, and on Windows the case of the name does not matter. A name that several files carry links to a list of those files (dotted underline, tooltip "N files"): a click lets you pick one. Nothing is guessed and nothing delays the reply; `omp.linkCodeSymbols` turns it off together with the symbol links.
- **An optional per-message reminder keeps the model linking files and code symbols.** With `omp.linkReminder` on, a short reminder follows each prompt you send, on its way to the model only (a separate message that is never saved to the session or shown in Chat; your prompt is not changed and the prompt cache keeps working): write the files and folders you mention as paths in inline code and every class, method, property, field and type as a link with its definition line. In a test fixture the share of symbols left as plain code dropped from about 50% to about 30%. It adds about 120 tokens per prompt. It is off by default; turn it on with `omp.linkReminder`; it applies to sessions started or resumed afterwards.
- **Compact…** in the context popover asks for OMP's compaction mode, with `snapcompact` (no model call) preselected; `soft` and `remote` then ask for optional instructions. A new **Shake…** beside it drops heavy content from the context, with `elide` preselected, or `images` or `thinking`. Both are also in the editor title menu and the Command Palette.
- **Ctrl+Shift+Q** puts the cursor in the chat composer from anywhere, the integrated terminal included: the active session, else the one showing next to your files. With no session open it opens the OMP Desk side bar. In a Terminal-mode session it no longer reaches OMP as Ctrl+Q; press Ctrl+Q itself for a follow-up message.
- **Ctrl+N** in a Chat opens VS Code's symbol search with the text you selected in the Chat (or in the composer) already typed in, the way it does in a text editor; with nothing selected it opens the empty symbol search. It is the command **OMP: Search Symbol from Chat Selection**.
- Sessions open in their own editor group on the left, and that group is locked, so files you open from Chat links, the Explorer or Quick Open appear in a group on the right and the chat stays visible. Turn it off with `omp.chatColumn`.
- **Ctrl+Shift+M** (**OMP: Toggle Files Window Next to Chat**) moves every tab of the group next to the chat into a window of its own, kept on top of other windows, wherever the focus is. That file window stays: files you open from Chat links go into it until you close it, then everything goes back to the right of the chat. Pressing Ctrl+Shift+M again, from any window, brings all its tabs back into the group next to the chat (created to the right of the chat if missing) and closes the window; the next press detaches again. The window is larger than VS Code's default when every tab is a text file; with a diff, a viewer or an unsaved file among the tabs, VS Code moves the group as it is, into a default-size window. Tabs that cannot be reopened in the other window (unsaved files, custom views) stay where they are when coming back. It replaces VS Code's Problems key and the Chat's Cycle Model key; Cycle Model stays in the Command Palette. A keymap extension that binds the key in the text editor (IntelliJ IDEA Keybindings uses it for Move Caret to Matching Brace) wins there; add a user keybinding for `omp.moveFileToNewWindow` to take it back.
- **Sessions is one flat list by default.** Every session of the shown folders is a row labelled `folder · title`: sessions that are not stopped first (unread on top, then the most recent activity), stopped sessions last, and **New Session…** and **Resume Session…** rows at the end that ask for the folder. The button in the view's title bar (`omp.sessionsGrouping`) switches to the previous layout, grouped under folders, and back.
- **Unread replies.** A **●** marks a session whose agent finished a reply or asked you something while you were not looking at its editor; it clears when you look at the session, and it survives a window reload. Both layouts show it.
- While a session has an open editor, its row in Sessions stays selected: the session you viewed most recently. Clearing the selection or selecting a folder or the New Session or Resume Session row puts it back.
- **Ctrl+Alt+Q** (**OMP: Go to Session…**) opens a searchable list of every session, from anywhere including the integrated terminal: title, folder and status, in the Sessions order (unread first, stopped last). Picking one opens it as a click in Sessions does; **New Session…** at the end of the list asks for the folder and starts one.
- **Resume Session** is a button in the Sessions title bar, next to New Session, and a **Resume Session…** row under **New Session…** at the end of the flat list, so it is reachable there, where there are no folder rows. It asks for the folder when several are shown, then lists that folder's saved sessions.
- **Sessions shows the repository's agent root for a subfolder.** A folder opened inside a Git repository whose root holds the agent files (`AGENTS.md`, `CLAUDE.md`, `.agents`, `.omp`, `.claude`, `.pi`) while the folder itself has none, as a Unity project under `repo/` does, is shown as that ancestor, so new sessions start where OMP finds them; sessions already recorded in the subfolder stay listed under it. Turn it off with `omp.useAgentRootFolder`.
- **Sessions is the same in every window.** The folders open in any window of the profile now appear in all of them, so a project open only in another window shows its sessions too; a window that closes takes its folders away after a few seconds. A session another window runs shows that window's live status (Working, Needs your answer, Idle, Unread reply) instead of "Running · in another window"; its icon is the status icon, and a `⧉` mark after the status says it is open in another window. Selection, a row's available actions and the collapsed state of an unpinned folder stay per window. `omp.showWorkspaceFolders` and `omp.useAgentRootFolder` now apply to all windows.
- **Clicking a session another window runs switches to that window at once.** The window comes to the front with the session's tab selected; the "Switch to Window" question is gone (the row's menu keeps **Switch to Window** as the same direct switch). A message appears only when switching is impossible, and says why (the window has no saved workspace or folder, two windows show the same folder, it did not answer, or it no longer has the session open). Sessions that only show history in another window are not switched to.
- **A session starts in the window that has its folder open.** New Session, Resume Session and opening a stopped session of a folder that is open only in another window now run in that window, which comes to the front with the session's tab (the most recently used one when several have it). A **Unity project** (a folder with `ProjectSettings/ProjectVersion.txt` and `Assets/`, found in the session's folder or two levels below it; several are asked once) runs in a window that has the project folder open, or in a new window opened on it, because the Unity extensions need that; the session's working directory stays the repository folder. If the other window does not answer, a message says so and nothing is started. The `omp.launchInFolderWindow` setting (default on) turns it off.
- **A window that was not reloaded after an update is skipped when sessions start in another window.** Such a window cannot open views any more; a session for its folder now starts in the window you used, with a note to reload the other one, instead of ending in an "OMP was updated while this window was open" page there.

### Changed

- **Switching to another window is fast.** Clicking a session another window runs, or starting a session in another window, took up to 22 seconds, because every check whether another window is alive ran a PowerShell command on the extension host's event loop, once per row on every change. The check is now done once per window, in the background, and a switch takes about a fifth of a second. The OMP Desk output log gained `window timing:` lines for the steps of a hand-over.
- **Unpin Folder** no longer refuses while a session in that folder runs. A folder with a running session in the window stays visible, unpinned.

### Fixed

- An `@path` mention written in inline code in Chat (`` `@CHANGELOG.md` ``) is now a link, as it already was in plain text.
- Inline code in a Markdown link label in Chat (`` [`World.Current`](…) ``) is shown as code, not with its backticks.
- **Session cost** in the context popover covers the whole session, as the terminal UI's status line does. After a compaction it used to count only the spend since that compaction.
- The context ring and its popover under the Chat composer show the new usage after **Compact** / **Shake** (from the popover or typed), after `/handoff` and after an automatic compaction. They used to keep the figure from before the pass until the next turn.
- **Chat's model and thinking pickers work during a turn.** Choosing a thinking level or a model while OMP was working was refused with "OMP is busy; choose a thinking level after the turn ends". OMP accepts both changes mid-turn (the next model request uses them), so Chat now sends them at once. When Chat cannot send a change yet (OMP is compacting, a rewind is running, the connection is being restored), it keeps your choice, shows it in the picker with a clock icon and sends it as soon as OMP is ready, before any message you send in the meantime; the newest choice wins. If OMP rejects it, the picker goes back to what OMP uses and a notice says so. **Cycle Model** and **Cycle Thinking Level** (`Ctrl+Shift+U`) behave the same. A choice that is still waiting is lost if the window is reloaded.

## [0.2.1] - 2026-10-09

### Added

- Provider login is easy to find before the first session: Sessions shows **Log in to a model provider to start** when the default OMP profile has no available models. Chat's model chip becomes **Log In to Provider** when its own profile has no models, and the model picker always offers **Log In to Provider…** to add another provider.

### Changed

- A compaction shows in Chat as it does in the terminal UI: a rule across the transcript that cuts off the summarized history, labelled with the amount (for example **Compacted · 400k → 47.8k tokens**); click it to read the summary. The unclear "context-full · complete" line is gone; only a cancelled or failed pass leaves a short line.
- **Compact…** in the context popover also works while a turn runs, as `/compact` does in the terminal UI: OMP interrupts the turn, compacts, then continues it. It is unavailable only while a compaction is already running.

### Fixed

- Chat explains an OMP process that exits on its own with its exit code and bounded stderr text instead of only saying the session stopped. A "No default model selected" refusal offers **Log In to Provider** for that session's profile; other startup failures show their own reason. After configuring a provider, Resume uses the same tab.
- In the composer's command, argument and file suggestions, Up and Down now scroll the list to the selected item. Before, the selection could move past the visible part of a long list, so you could not see what Enter would insert.
- Restored Chat tabs can receive large transcripts, screenshots and tool-result rows after Reload Window without overflowing the authenticated bridge's bounded outbound queue. Snapshot delivery uses socket backpressure and bounded authenticated fragments, closes non-reading peers within a finite write deadline, and explains repeated connection failures instead of reconnecting silently forever.
- **OMP: Log In to Provider…** works without an open session: it opens `omp login` for the default profile, or asks which profile when your sessions use more than one. Before, it refused with "Open a managed OMP session first", which left a new user with no way to log in before the first session could start.
- Chat no longer shows OMP's "xd://: mounted …" list of MCP tool names at the start of a session. That notice is meant for the model; warnings about devices still appear.

## [0.2.0] - 2026-10-09

### Added

- **Chat brings the terminal UI's everyday controls.** Copy buttons on code blocks and your own messages; **Retry** (`F5`, `Alt+R`) on a failed or aborted reply; `↑`/`↓` prompt history in the composer and **Search Prompt History** (`Ctrl+R`) across conversations; `Ctrl+T` and `Ctrl+O` show all thinking and expand all tool calls, remembered for every Chat; **Send now** turns a queued follow-up into steering, and `Alt+↑` takes the newest queued message back into the draft; **Compact…** in the context popover with optional instructions; `Alt+click` on the model or thinking chip cycles it (`Ctrl+Shift+M`, `Ctrl+Shift+U`); **Export Conversation as HTML…**, **Share Conversation Link…** and **Show Chat Keyboard Shortcuts** in the editor title menu. Status lines and warnings from OMP extensions appear around the composer, and their errors as VS Code error messages; their informational notices are not shown.
- Terminal-only OMP slash commands typed into Chat (`/hotkeys`, `/copy`, `/settings` and others in the installed OMP) are no longer sent to the model as text. Chat opens the matching VS Code view, or says where the command works.
- **Rewind a Chat conversation in place.** `Esc` `Esc` in an empty composer, **Rewind to here** on one of your prompts, `/rewind` or **OMP: Rewind Conversation…** (Command Palette and the editor title menu) go back to that prompt; it returns to the composer to edit and send again. **Rewind & summarize** also keeps a model-written summary of the abandoned messages. Files are not restored: the files changed after that point are listed. A chat started by an earlier OMP Desk must be restarted before it can rewind.
- **Undo** after a rewind or a branch switch returns to where the conversation was, as long as nothing newer was added; it still works after the chat is reopened.
- **Switch between your branches.** A marker after the message where the conversation split lists the branches you left by rewinding and switches to one in place. Branches OMP creates on its own (retries, checkpoints) are not listed.
- `/branch` typed alone in Chat opens the same Rewind, as it does in OMP's terminal UI; it never forks the session into a new file. `/branch` or `/rewind` with arguments is refused with a sentence saying how to rewind.

### Changed

- **Models and Agents settings** are easier to read and navigate: the model browser shows available models first and by default, roles and agents are compact keyboard-navigable lists, and fallback chains and presets are listed instead of hidden behind a key field. Selection, filters and unsaved drafts survive reloads and saves, results appear next to the control that caused them, and the pages follow the VS Code theme in Dark and Light.
- **Stop and `Esc` in Chat put messages that were still queued back into the draft**, as the terminal UI's `Esc` does, instead of running a queued steer as a new turn. This needs OMP 18.8.5 or newer; with an older OMP, Stop still stops the turn, but queued messages stay queued.
- **Models and Agents settings pick models the way OMP's `/models` does.** Every model field is now a searchable picker listing the models your roles use first, then each provider, with context size, thinking levels and the roles using each model. Choosing a role's model saves it at once and then offers its thinking level. Fallback chains, the cycle order and agent model overrides are ordered lists with Add, Remove and Move up/down (`Alt+Up`/`Alt+Down`); a new chain picks its role, provider or model from a list. Prewalk and advisor are Inherit, Off or On, with an optional model.
- **OMP: Open Models Settings** and **OMP: Open Agents Settings** open your global settings without asking for a folder; a scope control in the editor switches to a project folder. `/models` in a Chat still opens that Chat's folder.

### Fixed

- OMP sessions now start on localized Windows: private runtime storage is verified by security identifiers instead of English account names or incorrectly decoded console output, without allowing other users access.
- The queued-messages row above the composer no longer keeps listing a steer that OMP already delivered after a Stop, with Edit and Remove still offered.
- Clicking a role's model field no longer shows an empty suggestion list when the role is saved with a thinking level such as `:high`.
- Enabling or disabling an agent no longer copies project-level disabled agents into the global config.
- Clearing a setting that is not set no longer rewrites the config file and strips its comments.
- Opening a project or global config that does not exist yet explains that saving creates it, instead of showing a generic error.
- Chat no longer keeps showing the old branch when OMP moves the conversation to another one itself: it re-reads the moved branch, and loading older messages follows the active branch instead of the last lines of the session file.
- Chat names the file changed by OMP's line-anchored `edit` in its tool card summary and in Rewind's list of changed files.
- The Chat **Agents** row now shows a subagent that finished and was then resumed by a message (`write agent://<id>`, "Delivered"), running with its current tool, and removes it when it stops. OMP's own subagent list does not report that run. The subagent no longer counts as finished for notifications either.

## [0.1.0] - 2026-10-07

First public preview of OMP Desk: a Windows-only VS Code extension that runs your installed [Oh My Pi](https://github.com/can1357/oh-my-pi) (`omp`) sessions in editor tabs.

### Added

- **Sessions view** listing the folders open in the window, pinned folders and every running or stopped OMP conversation for them, with live status (Working, Waiting for subagents, Needs your answer, Idle, Unread reply) and row actions: Open, Rename, Reload, Close, Forget, Delete and Resume Session. Sessions held by another VS Code window or written by a separate `omp` process are marked, and opening them asks first.
- **One editor, two modes.** Each session opens as a rich **Chat** or as the unmodified native OMP **Terminal** TUI, switchable from the editor title. **OMP: Choose Default Session View…** sets the mode for new sessions.
- **Sessions survive restarts.** Each session runs in a detached background process that keeps working when its tab closes, the window reloads or VS Code exits; reopening reattaches to the same process and screen. Only one window writes a session at a time.
- **Chat**: streaming replies, saved history, steer and queued follow-ups (editable before they run), questions and approvals as a card above the composer, slash-command argument suggestions, model and thinking pickers, a footer with context usage, provider quotas and the Git branch, an Overview or Detailed view of tool calls, pinned TODO and Agents rows with detail tabs, a working status row and progress bar, clickable file links, and web links that open in an editor tab (`Ctrl+Click` for the external browser). Drafts stay until OMP confirms them; if OMP stops responding, **Reconnect** or **Restart** keeps the conversation and unsent text.
- **Terminal**: the genuine OMP TUI with Nerd Font glyphs, clickable file and web links, live theme colors, **Copy screen** and **Redraw Terminal**.
- **Windows desktop notifications** when a session finishes or asks for input (`omp.desktopNotifications`).
- **Add Selection to Session** and **Add File to Session** (`Alt+Shift+K`) insert an `@path` reference into a session you pick, without sending it.
- **Folder shells**: **Open Terminal in Folder** and **Reconnect Terminal**.
- **Processes view** for the background processes behind sessions and terminals, with Stop and a one-step cleanup of orphaned and idle processes.
- **Stats** opens OMP's usage dashboard in an editor tab.
- **Tools view** listing the tools and skills of the active session.
- **Models and Agents settings** tabs for OMP's model roles and agent overrides (`/models`, `/agents`).
- **OMP: Log In to Provider…**, **OMP: Show Diagnostics**, **Copy Diagnostics** on rows, and file change observation commands.
- Windows packages for `win32-x64` and `win32-arm64`.

### Notes

- OMP is not bundled. The extension launches the `omp` found on `PATH` and never installs, downloads or updates it.
- OMP Desk is an unofficial, independent integration, not an official OMP distribution.
